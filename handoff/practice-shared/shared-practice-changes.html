共用改動 — 八張卡一起更新的

Content Mirroring 與 Vocabulary Mirroring 已交接。這兩版裡有一批決定不是那兩張卡自己的， 是八張卡共用的元件與規則——名稱在哪一步、Settings 長什麼樣、用什麼字、Assign 怎麼做。這份把它們抽出來， 逐項寫成規格，並對照每一張卡現在的程式碼說明「能不能直接套、為什麼」。給工程的用法：改共用元件一次，五種／八種一起變； 各卡自己的部分（Vocabulary Quiz 的 Question Types、QA 的 Guide phrase language…）不在這裡。

1 這份是什麼

八張卡對到六個型別、六份設定檔。建立流程全部走同一個 practice-unified-view.js， 步驟標籤在 src/utils/practice-stepper-config.js，Assign 那一步八種共用，Settings 那一步五種共用同一批元件 （AudioModeToggleCard、AudioSettingsPanel、MaxAttemptsField）；Comprehension Quiz 與 Vocabulary Quiz 沒有設定（兩張的 Settings 步只有 Practice name ＋ 題目清單）。

// practice-stepper-config.js @ 599dd4cb MIRRORING Content → Settings & Preview → Assign Practice （提案：四步，Edit Sentences 獨立） QA Content → Settings & Preview → Assign Practice VOCABULARY Vocabulary → Settings → Assign Practice （提案：四步，Teaching Points 在前） VOCABULARY + MC Vocabulary → Question Types → Settings → Assign Practice MULTIPLE_CHOICE Question Bank → Edit & Preview → Assign Practice SENTENCE_SCRAMBLE Content → Edit Sentences → Settings → Assign Practice FOLLOW_PATTERN Teaching Points → Question Review → Settings → Assign Practice

每一項定案標 S1…S11。規格本身以 Content Mirroring／Vocabulary Mirroring 的交接包為準 （Content Mirroring HANDOFF、 Vocabulary Mirroring HANDOFF）， 這裡寫的是「套到其他卡時哪裡一樣、哪裡不一樣」。判準在 practice-design-rules.html（R11 是 Settings 的固定形狀）。S3 套到三張卡的畫面已經畫好：Settings 套到各 practice（畫廊）。

3 S1 · Practice name 在第一步

規格。名稱欄位（ReUI c-input-2）放在第一步、來源選單正下方，說明句 Filled in from the project(s) you pick. Change it if this practice needs its own name.。 選了來源就填入（專案名／題庫名）；多個來源用「 + 」串（我的一天 + 环境保护与可持续发展），取消一個就縮回去；老師改過之後不再跟著來源變。

為什麼能套。六種型別現在都在第一步就把名字設好了，欄位卻長在第二步——老師到第二步才看到一個「自己沒打過的名字」：

4 S2 · 第一步的元件

三個 ReUI 元件，Content Mirroring 第一步換過、Vocabulary Mirroring 第一步沿用：

  • 來源選單 → c-dropdown-menu-18：標籤在上、outline 觸發鈕、選單有群組標題，每列 語言 mark（BCP-47 原樣）＋ 名稱 ＋ 級數 ＋ 數量。專案是這樣，題庫也照這個畫（QA、Comprehension Quiz 的 Select a Question Bank）：每列 題庫名 ＋ 題數。多選（Vocabulary、Scramble、Follow Pattern）點一下切換、選單不關、觸發鈕把選到的一個一個列出來。
  • 內容預覽 → c-frame-6 ghost frame：Title ＋ Description ＋ 白底 panel，底色用該欄自己的 wash（Content #EFFBF4、Vocabulary #FFF8E7、Sentence／Comprehension 照 practice-type-labels.js）。課文一段一行帶編號、不 join('')。
  • Teaching point 勾選 chip ＋ Add words（Vocabulary Mirroring）：每個專案一個 frame、標頭三態全選框、chip 勾＝會生成、From Project／Custom word。Scramble 與 Follow Pattern 已經有 steps/shared/teaching-point-picker.js ＋ use-teaching-point-pool.js，這是它們的版面版，邏輯不必再寫；它們獨有的 Number of questions 放在 frame 底下同一行。
一個原則：第一步只有「選來源、看內容、決定要練哪些」，不放編輯器（Content Mirroring 問題 7：句子表要按 Next 再 Back 才存在）。要審、要改的東西是下一步。

5 S3 · Settings ＝ 工具列 ＋ 視窗預覽（R11）

規格。一張卡：上面是貼在畫布頂上的工具列（兩行，第一行＝畫面上看得到的、第二行＝喇叭播什麼 ‖ Max tries；每格 10px 大寫小標在上、28px 控制項在下；沒有眉標、沒有副標）， 下面是灰色地板上一個有陰影的視窗（34px 視窗列：小螢幕圖示 ＋ Student view），裡面是學生端的主欄照抄；改哪個格子那張卡跟著變。底部一行計數。 完整規則見 R11，參考實作是 Content Mirroring 第三步。

畫好了：Settings 套到各 practice——Open-ended Questions、Sentence Scramble、Sentence Response／Building 三張的工具列 ＋ 視窗預覽，控制項可以點，畫布跟著變。

為什麼能套。三份設定檔（QA、Scramble、Follow Pattern）用的都是同一批共用元件加各自 Object.entries(ENUM).map(...) 的下拉；工具列的分段控制項、Speed chip、Voice 下拉、Max tries 做成共用元件之後， 各卡只是「放哪幾格」的差別。畫布每張卡各自抄一份——這是唯一不共用的部分，也是每張卡最花時間的部分。

改設定不該整頁被擋：拼音／翻譯／模式只是 metadata，前端已排除在 AUDIO_AFFECTING_FIELDS 之外，但草稿路徑的後端仍會 enqueue SQS（use-practice-editor.js 的註解）。這件事一次解，五種都受益——見 §9。

7 S8 · Assign 搬回頁面

規格（Content Mirroring 第四步，八種共用）：三段 Who does it／When／How it counts；一份時間套用到所有選到的班、要分開再 Set dates per class；班級列三種狀態（整班已派變灰掛 Assigned、部分已派仍可選、名冊是 diff：Assigned／New／Will remove／In ⟨班級⟩）；Mandatory／Optional 對齊 AssignmentTypeChip；已指派的清單在上、再派一次的表單在下，卡片上 Cancel 改 Remove；送出前預覽只講例外（skippedUsers、沒選的人）；頁腳一顆鈕依狀態換字 Assign to N classes／Done／Skip for now。 班名用該欄的 label 色（Content #00754A、Vocabulary #8F6209…）。

為什麼能套。step-three.js ＋ assign-practice.js 是八種共用的，mutation 不變（assignPractice 一次多班 ＋ 逐班 upsertAssignment）。做一次，八張卡同時變。

8 S9 · 頁腳與捲動

  • 換步驟捲回最上面：practice-unified-view.js 整份只有一個處理對話框的 scrollIntoView，沒有換步驟時的捲動重置。換步驟、送出指派、結束流程三個時機 window.scrollTo(0, 0)。八張。
  • Next 灰著要說為什麼（R9）：沒選來源、一個字都沒勾、題庫沒題——原因寫在內容區，不是按下去才跳 snackbar。
  • 頁腳標籤：Next 一路到倒數第二步的 Save（resolvePrimaryActionLabel 現況），最後一步依 S8。Scramble／Follow Pattern 第一步的 Generate 與 Vocabulary 的 Next（Vocabulary Mirroring 決定留 Next）要不要對齊，待定——這是唯一跨卡還沒統一的字。

9 S10–S11 · 要問工程才能套的

#定案規格要問的
S10回第一步不鎖、只生新的 生成後第一步仍可編：多勾的掛 New、按 Next 直接回下一步不做生成動畫、新內容在卡上生；取消勾的離開；其他的卡、圖、順序留著。Vocabulary Mirroring 跟工程談定 practice 在第二步儲存，所以第一步是自由的。 Scramble、Response／Building 第一步 Generate 之後同樣鎖住（use-teaching-point-pool.js）。要問：生成能不能只補新勾的 teaching point、儲存能不能延到審題那一步——跟 Vocabulary Mirroring 契約 §1 同一題。
S11審句步：眼睛＝隱藏、對話類提醒只在這一步 一句一列、眼睛按下去那句不給學生（可還原，不是刪除）；對話類專案 Split／Merge 收掉、句子表上方一則 warning Alert Conversation — lines can't be split or merged.（15px），第一步不提醒。 Scramble 的 scramble-sentence-list.js：先查 canSplitMerge／contentType === 'CONVERSATION' 有沒有用在這裡；隱藏要 updatedArticleArray 項目帶 hidden——跟 Content Mirroring 交接包的 H1 同一題。

另外兩題跨卡的後端題：E3 拼音／翻譯／模式改動不該重產音檔（§5 的警告）；E1 新的發音 Lambda 什麼時候支援 slack（決定「發音嚴格度」要不要進工具列）。

10 動工順序

  1. 共用元件先：分段控制項（S4）、Practice mode 格（S5）、Max tries（S6）、Speed chip ＋ Voice 下拉（S7）、工具列容器與視窗預覽的殼（S3）。做完 Content Mirroring 那一包的第三步，其餘四張只剩「放哪幾格 ＋ 抄自己的畫布」。
  2. Assign（S8）與頁腳／捲動（S9）：各一處，八張同時變。
  3. S1 名稱搬家 ＋ S2 第一步元件：一張卡一張卡做，每張半天內。Comprehension Quiz 是最小的一張（名稱搬家、Assign、捲動），可以當第一張試。
  4. 各卡自己的畫布（S3 表格最右欄）：QA、Scramble、Follow Pattern、Vocabulary Quiz 各抄一份學生端主欄。
  5. S10／S11 等後端答覆再排。

11 不在這份裡的 待設計梳理

  • Vocabulary Mirroring 第二步「一個字一列 ＋ 逐卡 chip ＋ 總開關 ＋ 上傳圖 ＋ 再生例句」——Vocabulary 自己的。Vocabulary Quiz 的第二步是 Question Types，不是卡。
  • QA 的 Guide phrase language、Vocabulary Quiz 的 Question Types、Scramble 的 Number of questions——各卡獨有的設定，工具列裡留格子，內容各自定。
  • 學生端畫面。工具列的畫布是照學生端抄的，不是反過來改學生端；唯一的例外是 Vocabulary Mirroring 契約 §5（Vocabulary 學生端要開始讀三個顯示設定）。
  • Comprehension Quiz 的題目清單本身（Edit & Preview）。它沒有設定，R11 不適用。

這四項各卡自己的部分還沒有設計，要逐張卡另開版本梳理（照 VERSIONING-WORKFLOW：一版一個資料夾）。建議順序見 practice-design-rules.html §4——下一張 Vocabulary Quiz。
