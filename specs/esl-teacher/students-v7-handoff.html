1 Page Overview

The Students page is a master-detail layout for ESL Teachers to browse, filter, and inspect individual student performance. The left panel (38% width) shows a searchable, filterable student list. The right panel (62%) shows detailed KPI, practice history, translation frequency, and vocabulary data for the selected student.

3 Data Model

Student Object

{
  name:      "Emily Chen",
  initials:  "EC",
  level:     1,                // WIDA level 1-6
  lang:      "Mandarin",       // display language name
  subjects:  ["Science", "Math"],
  group:     "3rd Grade · WIDA 1"  // matches KPI tracker name
}

Student Detail (Generated)

{
  practiceHistory: [
    {
      date:     "2026-04-15",
      type:     "Spelling",    // "Spelling" | "Multiple Choice" | "Mirroring"
      subject:  "Science",
      score:    85,            // 0-100
      words:    8,
      transSec: 18             // seconds between translation taps
    }
  ],
  vocabulary: [
    {
      word:    "hypothesis",
      subject: "Science",
      state:   "learning",   // "learning" | "mastered"
      mastery: 3,            // 0-5, 5 = mastered
      spell:   1,            // completed in Spelling mode (0|1)
      mc:      1,            // completed in Multiple Choice
      mirror:  0             // completed in Mirroring
    }
  ]
}

KPI Tracker Object

{
  id:     1,
  name:   "3rd Grade · WIDA 1",
  metric: "times",      // "times" | "mins" | "words"
  target: 5,
  cycle:  "7",          // days
  start:  "2026-03-26"
}

Students are matched to trackers via student.group === tracker.name.

5 Interaction Patterns

Student Selection

  • Click a student card in the left panel to select
  • Active card gets green border + green background
  • Right panel immediately populates (no loading state in demo)
  • On page load, the first student is auto-selected
  • List re-renders on each selection to update active state

Filter Behavior

  • All 3 filters (group, level, grade) work together as AND conditions
  • Search is a substring match on student.name (case-insensitive)
  • Student count in title updates in real-time: (N)
  • If no students match, shows "No students match filters." centered
  • Filtering does NOT deselect the current student (detail stays visible)

Edit Student Flow

  1. User clicks edit icon in detail header
  2. Modal opens with current values pre-filled
  3. On Save: student object is updated in-place, modal closes, list re-renders, detail refreshes
  4. Initials are re-computed from updated name
  5. Clicking overlay background also closes modal

Manage Students Flow

  1. User clicks "Manage" button in list panel
  2. Full-screen modal with spreadsheet-style table of all students
  3. All fields are editable inline (inputs and selects)
  4. "Save All" saves all changes at once, re-renders list and detail
  5. Cancel discards changes

7 API Suggestions

These are suggested endpoints based on the data structures and interactions in the demo. Adjust to your actual API design patterns.

Student Roster

MethodEndpointDescription
GET/api/teachers/{teacherId}/studentsList all students with filters: ?group={name}&wida={level}&grade={n}&search={query}
PUT/api/students/{studentId}Update student info (name, lang, grade, wida, kpiGroup)
PUT/api/teachers/{teacherId}/students/bulkBulk update from Manage modal. Body: { students: [{ id, name, lang, grade, wida, group }] }

Student Detail

MethodEndpointDescription
GET /api/students/{studentId}/detail Full detail: KPI progress, cycle history, practice sessions, translation frequency, vocabulary. Consider batching into one call for performance.
GET /api/students/{studentId}/practice-history Paginated practice sessions: { sessions: [{ date, type, subject, score, transSec }] }
GET /api/students/{studentId}/vocabulary Word bank: { words: [{ word, subject, state, mastery, modes }], stats: { total, learning, mastered, newThisWeek } }
GET /api/students/{studentId}/kpi-history?trackerId={id} Cycle-by-cycle KPI results: { cycles: [{ start, end, goal, achieved, status }] }

KPI Progress (per student)

MethodEndpointDescription
GET /api/students/{studentId}/kpi-progress Current cycle progress for all trackers the student belongs to: { trackers: [{ name, metric, target, value, daysLeft, met }] }
Consider a single /detail endpoint that returns KPI + vocabulary + history in one response to minimize round trips when selecting a student.
