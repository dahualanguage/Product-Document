1 Page Overview

The Dashboard is the default landing page for ESL Teachers. It gives a real-time overview of student KPI progress and language independence metrics. The layout is a two-column grid:

Layout Structure

RegionComponentGrid Position
Page Header Title ("Dashboard"), subtitle, "Manage Trackers" button, "+ New Tracker" button Full width, above grid
Left Column KPI Tracker -- list of tracker cards with expandable student progress grid-row: 1 / 3 (spans full height)
Right Top Language Barrier · Translation Frequency -- 3-column card grid with per-tracker stats Row 1, Column 2
Right Bottom Most Tapped Words in Class -- ranked table of vocabulary across subjects Row 2, Column 2
The dashboard grid uses display: grid; grid-template-columns: 1fr 1fr; gap: 20px. The KPI Tracker panel spans two rows on the left.

Expanded State -- Student Rows

Each student shows name (12px, 600 weight) and their individual interval value with the same color coding.

Barrier Computation

The interval is calculated as: (practice_minutes * 60) / tap_count = seconds between taps. Higher = more independent. The "previous period" value is simulated as current * 0.85 (except the first tracker which uses current * 1.22 to show a declining scenario).

3 Data Model

Student Object

{
  name:  "Emily Chen",
  lang:  "zh",            // "zh" | "es"
  wida:  1,               // WIDA proficiency level 1-6
  grade: 3,               // school grade 3-8
  times: { "7": 2, "14": 5, "30": 10 },   // practice count by period
  mins:  { "7": 10, "14": 22, "30": 45 },  // practice duration (minutes)
  words: { "7": 3, "14": 6, "30": 12 },   // mastered word count
  taps:  { "7": 24, "14": 45, "30": 88 },  // translation tap count
  hover: { "7": 90, "14": 170, "30": 330 } // hover-to-translate count
}

Metric values are stored per time window (7, 14, 30 days). For arbitrary cycle lengths, the demo linearly interpolates between known data points.

Tracker Object

{
  id:       1,
  name:     "3rd Grade · WIDA 1",
  metric:   "times",      // "times" | "mins" | "words"
  target:   6,            // numeric goal per cycle
  cycle:    "7",          // cycle length in days (string)
  start:    "2026-04-10", // cycle start date (YYYY-MM-DD)
  end:      "2026-06-30", // optional end date
  students: ["Emily Chen", "Carlos Garcia", "Lucia Torres"]
}

Days Left Calculation

// Recurring cycle: compute days until next cycle boundary
function getKpiDaysLeft(tracker) {
  today = new Date();  // midnight
  start = parseDate(tracker.start);
  cycleDays = parseInt(tracker.cycle);
  elapsed = daysBetween(start, today);
  cyclesPassed = Math.floor(elapsed / cycleDays);
  nextEnd = start + (cyclesPassed + 1) * cycleDays;
  return daysBetween(today, nextEnd);
}

If start is in the future, daysLeft = days until start + cycleDays.

Language Barrier Computation

// Interval = seconds between translation taps
// Higher interval = more independence = better
function computeBarrierValue(studentNames, days) {
  intervals = studentNames.map(name => {
    student = findStudent(name);
    taps = getStudentVal(student, "taps", days);
    mins = getStudentVal(student, "mins", days);
    return (mins * 60) / taps;  // seconds per tap
  });
  avg = mean(intervals);
  prev = avg * 0.85;  // simulated previous period
  return { val: avg, prev: prev };
}

7 API Suggestions

These are suggested endpoints based on the data structures and interactions in the demo. Adjust to your actual API design patterns.

Tracker CRUD

MethodEndpointDescription
GET/api/teachers/{teacherId}/trackersList all trackers for the teacher, ordered by display position
POST/api/teachers/{teacherId}/trackersCreate a new tracker. Body: name, metric, target, cycle, start, end, studentIds[]
PUT/api/trackers/{trackerId}Update tracker fields (name, metric, target, cycle, dates, students)
DELETE/api/trackers/{trackerId}Remove a tracker
PUT/api/teachers/{teacherId}/trackers/reorderBody: { orderedIds: [1, 3, 2, 4] }. Persists display order.

Tracker Progress

MethodEndpointDescription
GET /api/trackers/{trackerId}/progress Returns per-student progress for the current cycle. Response: { cycleDaysLeft, students: [{ name, value, target, met }] }
GET /api/trackers/{trackerId}/progress/summary Lightweight: { metCount, totalCount, percentMet, daysLeft, isUrgent }

Language Barrier

MethodEndpointDescription
GET /api/trackers/{trackerId}/barrier?window={days} Returns translation frequency stats for the tracker's students. Response: { avgIntervalSec, prevIntervalSec, trendPct, trendDirection, students: [{ name, intervalSec }] }
The "previous period" comparison should be the actual prior window (e.g. previous 7 days), not the simulated * 0.85 from the demo.

Most Tapped Words

MethodEndpointDescription
GET /api/teachers/{teacherId}/tapped-words?window={days}&limit={n}&trackerId={id} Ranked list of most-translated words. Response: { words: [{ rank, word, subjects: [{ name, count }], tapCount }] }

Student Roster (for Tracker Target Picker)

MethodEndpointDescription
GET /api/teachers/{teacherId}/students?grade={g}&wida={w} Filterable student list. Response: { students: [{ id, name, lang, wida, grade }] }

Dashboard Summary (batch)

MethodEndpointDescription
GET /api/teachers/{teacherId}/dashboard?barrierWindow={days} Returns all dashboard data in a single call: trackers with progress, barrier stats, and top tapped words. Useful for initial page load.
Consider a batch endpoint for initial load to avoid multiple round trips. Individual endpoints are useful for filter changes and real-time updates.
