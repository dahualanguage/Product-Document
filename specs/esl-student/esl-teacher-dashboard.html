ESL Teacher Dashboard

Practice activity monitoring, mastery tracking, and vocabulary insights — everything an ESL teacher needs at a glance.

Flow 6 — Live Classroom Version: v5 Status: Design Last updated: March 2026
Open Live Demo (v5)

1 Feature Goal

How does an ESL teacher quickly assess whether students are practicing, how they're performing, and which words need attention?
Teachers manage multiple ESL groups (A–D) with varying proficiency levels. Without a centralized dashboard, they must navigate between individual student records to gather insights — losing time that could be spent on targeted instruction.
Goal: Provide a single-screen dashboard that answers three questions: (1) Are students practicing? (2) Are they improving? (3) What vocabulary needs more work? — filterable by group and time period.

The dashboard is organized into three rows:

  1. Row 1 — Insight Inbox (left) + Practice Activity (right)
  2. Row 2 — Practice Outcomes (full width): mastery progress + most missed words
  3. Row 3 — Most Tapped Words (full width): cross-subject vocabulary frequency from live sessions

3 Practice Activity

The Practice Activity card lets the teacher set weekly practice goals and monitor which students are meeting them. It combines goal-based achievement tracking with a per-type breakdown, all filterable by group and time period.

3.1 Goal Setting

The card header includes a gear icon (⚙) that opens a settings popover where the teacher sets two independent weekly goals:

GoalUnitDescriptionExample
Practice times targettimes / weekMinimum number of practice sessions expected per student per week10
Practice duration targetmins / weekMinimum total practice minutes expected per student per week60
Independent goals: The two targets are tracked separately — each has its own achievement rate and below-target list. A student can meet the times goal but miss the duration goal, or vice versa.

Settings Popover

  • Triggered by clicking the ⚙ gear icon in the card header (next to the period selector)
  • Two input fields: "times / week" and "mins / week" with number stepper
  • Default values: 10 times, 60 mins (configurable)
  • Settings persist per teacher and apply to all groups

3.2 Achievement Rate

Two side-by-side stat blocks replace the old summary stats, each showing:

3.3 Below-Target Students

Clicking the "N students below target" label expands an inline list directly below the stat block, showing each below-target student:

ColumnDescription
Student nameStudent's display name
GroupESL group badge (A / B / C / D)
ActualTheir actual value this week
GapHow far below target (e.g., "−4 times" or "−22 mins")
Interaction: The list is collapsed by default. Click to expand, click again to collapse. Each goal (times / mins) has its own independent expandable list. Students are sorted by gap (largest gap first).

3.4 Group Filter

Multi-select checkbox row allowing the teacher to filter by ESL group:

Filter Controls

CheckboxBehavior
AllSelects/deselects all groups (A, B, C, D). Uses pre-computed aggregate data for accuracy.
A / B / C / DIndividual group toggles. Multiple groups can be selected simultaneously.

Multi-group logic: When multiple individual groups are selected (but not "All"), the summary stats display averaged values across the selected groups. The "All" checkbox auto-checks when all 4 groups are checked, and unchecks if any single group is deselected.

Styling: Checkboxes use :has(input:checked) to apply a filled state — checked labels get a #ecfdf5 background with #059669 border and text color.

6 Data Model

6.1 Practice Activity Data

Data is structured per-group (A, B, C, D, All) and per-period (7, 14, 30 days):

// Teacher-set goals (persisted) goalSettings = { timesPerWeek: number, // e.g. 10 minsPerWeek: number // e.g. 60 } // Per-group, per-period activity data activityData[group][period] = { // Times goal timesAvg: number, // avg practice sessions across students timesAchievePct: number, // % of students meeting times goal timesBelowCount: number, // count of students below target timesBelowList: [ // students below target, sorted by gap desc { name: string, group: string, actual: number, gap: number } ], // Duration goal durationAvg: number, durationAchievePct: number, durationBelowCount: number, durationBelowList: [ { name: string, group: string, actual: number, gap: number } ], // Type breakdown (unchanged) types: [ { name: string, pct: number, color: string, icon: string } ] }

Groups: all, a, b, c, d. The all group contains pre-computed aggregates (not simply averaged from A–D).

6.2 Practice Outcomes Data

Outcomes data is per-period only (not per-group in current design):

outcomesData[period] = { mastered: number, // count of mastered words learning: number, // count of learning words newWords: number, // count of newly added words total: number, // sum of all pct: number // mastered percentage (0–100) }

6.3 Most Tapped Words Data

Static ranked list (top 10) with per-word subject breakdown. Currently not filterable by group — shows all-student aggregate. Has its own period selector.

7 Filter Interactions

Period Selector

A <select> dropdown with options: 7 Days, 14 Days, 30 Days. Each card (Practice Activity, Practice Outcomes, Most Tapped Words) has its own independent period selector.

Group Checkboxes (Practice Activity only)

Multi-select behavior:

  • Checking "All" → checks A, B, C, D and uses activityData['all']
  • Unchecking "All" → unchecks all groups
  • Checking all 4 individual groups → auto-checks "All"
  • Unchecking any individual group → unchecks "All" and averages remaining
  • If no groups are checked, the card shows activityData['all'] as fallback

Multi-Group Achievement

When multiple groups are selected, achievement rate is recalculated across all students in the selected groups combined (not averaged across group-level percentages). The below-target list merges students from all selected groups, sorted by gap.

Goal Settings Popover

The ⚙ gear icon opens a small popover anchored to the card header. Changing a goal value immediately recalculates achievement rates and below-target lists for the current view. Goals are saved per teacher and persist across sessions.

8 Open Questions

Should Practice Outcomes also be filterable by group?
Currently mastery data is shown as an all-student aggregate. Group-level mastery could help teachers identify which groups need more vocabulary support, but adds data complexity.
Should Most Tapped Words be filterable by group?
Different proficiency groups may tap different words. However, since tapping happens during live sessions where all groups are present, per-group filtering may not reflect the shared classroom context.
What defines "mastered" vs "learning"?
The current demo uses placeholder thresholds. The engineering team needs to define: how many correct answers in a row? Across which practice types? Over what time window?
