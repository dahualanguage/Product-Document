Live Classroom

Real-time transcription with word-level language support for ESL students during content-area instruction.

3.5 Live Classroom Status: Planning Target: TBD Last updated: 2026-02-23

1 Feature Goal

How can ESL students follow along in a content class taught in English when the instructional language is above their proficiency level?
Content teachers (science, math, social studies) teach in English. ESL students in mixed-level classrooms need real-time language support to access the content being taught — without interrupting the lesson or the teacher's flow.
Goal: During a live content class, capture the teacher's speech in real time, convert it to text, and deliver it to students as an interactive transcript where they can tap any word for instant language support.

The Live Classroom combines three capabilities into one seamless experience:

  1. Live Transcription — Teacher's speech is converted to text in real time and pushed to all connected students
  2. ClickableTranscript — Every word in the transcript is tappable; students get instant translation, definition, and examples
  3. Difficulty Tracking — Each word tap is recorded as a difficulty event, building a per-student language profile that feeds into the Data Dashboard

3.2 UX Logic & Edge States


  
3.2.1 Teacher Pre-class Settings

  
Before starting a live session the teacher must complete a microphone voice test. The following scenarios describe each state the test can reach.


  

    
ScenarioScreenTextBehaviour

    
      

        1. Microphone Unconnected (no device)
        No microphone hardware detected
        “Microphone unconnected — Please allow Microphone access in your browser, or check that your device is connected.”
        Voice test cannot proceed. Block session start.
      

      

        2. Permission Denied (Browser settings)
        Browser mic permission dialog was dismissed or rejected
        “Microphone permission is required. Please enable it in your browser settings.”
        The system cannot detect any audio input. The teacher must enable microphone permission in their browser settings before proceeding.
      

      

        3. Connected — Ready to Test
        Microphone Connected
        “Speak to test” — “Test 1, 2, 3”
        Display test phrase prompt. Await teacher voice input.
      

      

        4. Connected — Voice Test Active
        Teacher is speaking; transcribed words enlarge in the transcription box
        Each correctly transcribed word becomes enlarged in the transcription box.
        Confirms: (a) audio is being recorded, (b) speech-to-text is functioning, (c) the transcription pipeline is working end-to-end.
      

      

        5. Voice Test Passed — Ready to Start
        Test phrase successfully transcribed
        Test phrase remains visible as confirmation.
        The “Start Class” button appears. Teacher can begin the live session.
      

      

        6. Voice Test Failed — Low Volume
        Microphone input volume too low to transcribe accurately
        “Volume too low — please move closer to the microphone or increase input volume.”
        Prompt the teacher to adjust microphone position or volume level before retrying.
      

      

        7. Voice Test Failed — Mismatch
        Transcribed output is significantly different from the expected test phrase
        “Voice test did not match. Please try again in a quieter environment.”
        The microphone is recording and text is appearing, but the words do not match the expected phrase. Prompt the teacher to retry or check mic input source.
      

      

        8. STT Service Unavailable
        Microphone is working but Speech-to-Text service is down or unreachable
        “Transcription service is currently unavailable. Please try again later.”
        Falls back to Scenario 1 behaviour — voice test cannot proceed, block session start. Retry button available.

4.2 UX Logic & Edge States


  

    
StateConditionUI Treatment

    
      

        Waiting for session
        Student opens Live Classroom but teacher hasn't started yet
        Centered message: “Waiting for your teacher to start the live session…” with subtle pulse animation.
      

      

        Late join
        Student joins after session already started
        Load transcript history from session start. Show catchup indicator: “Catching up…” then auto-scroll to live position.
      

      

        Reconnecting
        Student's internet drops briefly
        Banner: “Reconnecting…” On reconnect, fetch missed transcript chunks from channel history and append seamlessly. Student sees no gap.
      

      

        Word lookup failed
        lookupWord query fails (network / server)
        Popup shows: “Couldn't load word info. Tap to retry.” The tap is still recorded as a difficulty event regardless.
      

      

        Session ended
        Teacher ends the live session
        Banner: “Live session has ended.” Transcript remains readable (frozen). Link: “View session summary.”

5.2 Difficulty Event Schema


  
DifficultyEvent {
  word: String            // The word the student tapped
  studentId: String       // Who tapped it
  sessionId: String       // Which live session
  timestamp: ISO8601      // When it happened
  contextSentence: String // Surrounding sentence for context
  contentArea: String     // Subject being taught (science, math, etc.)
  source: "LIVE_TRANSCRIPT"  // Distinguishes from practice events
}


  

    Data pipeline: These events are the primary input for the Language Difficulty Profile and Language Access Level metrics in the Data Dashboard (1.3 School Management). When a student repeatedly taps the same word or category of words, the system identifies it as a persistent difficulty area.
  


  
  
5.3 Session Record Schema


  
LiveSession {
  sessionId: String       // Unique session identifier
  teacherId: String       // Content Teacher who broadcast
  classroomId: String     // Associated classroom
  contentArea: String     // Subject (science, math, etc.)
  gradeLevel: String      // Grade level of the class
  startTime: ISO8601      // Session start
  endTime: ISO8601        // Session end
  transcript: [           // Full transcript with timestamps
    { text: String, startMs: Number, endMs: Number }
  ]
  connectedStudents: [String]  // Student IDs who joined
  difficultyEvents: [DifficultyEvent]  // All word taps
}


  
  
6 Open Questions


  

    
Should students be able to review their own difficulty history after a session?

    
Currently, post-session data goes only to the teacher dashboard. Showing students their own tapped words could encourage self-study, but it might also cause anxiety for struggling students.

  


  

    
How should the system handle multiple simultaneous live sessions?

    
If a school has several content classes at once, ESL Teachers may need to monitor more than one session. Should the monitoring view support multi-session tabs?

  


  

    
Should the transcript support sentence-level bookmarking?

    
Beyond tapping individual words, students might want to mark entire sentences they didn't understand for later review. This would add a second interaction layer to the transcript.
