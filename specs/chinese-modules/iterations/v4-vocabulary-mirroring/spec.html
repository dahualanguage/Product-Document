v4 — 優化 Practice-Vocabulary Mirroring

Vocabulary Mirroring 的建立流程是三步：Vocabulary → Settings → Assign Practice。§2–§5 是現況與查到的問題，§6 是待決事項。 §7 是提案——第一輪只換 v3 動過的共用元件，Vocabulary 自己的部分刻意沒動。

2026-09-10 分岔自 v3 程式碼基準 origin/develop @ 77ea5d6f 狀態：提案第五輪（Vocabulary 重畫）

1 這一版的範圍

入口是 https://dahua-dash-dev.web.app/dashboard/practice/create/?type=VOCABULARY&subType=MIRRORING， 也就是在 Choose Practice Type 點下 Vocabulary Mirroring 之後進的那條建立流程。 範圍是這三步；不含 Choose Practice Type（v1）、不含 Edit 模式、不含 Vocabulary Quiz （同一份設定但多一步 Question Types，另開一版）。

Practice Type 那一步已經不在了。 設計判準 §4 與 8/31 的 inventory 都還寫著「攤平後 Practice Type 那一步是多餘的，可以順手拿掉」—— 現行 STEPS_BY_TYPE[VOCABULARY] 已經是三步，practice-stepper-config.js 的註解直接說 the sub type … arrives in the URL, so no flow asks for it again。 留下的痕跡只剩第二步的檔名 vocabulary-step-three-section.js（docblock 還寫著 Step 3）。 那兩份文件要更新。

v3 已經涵蓋的

第三步 Assign 是 step-three.js，八種共用——v3 那一整組（搬出對話框、三段、可重複指派、送出前預覽） 直接適用，這一版不重畫。Stepper、頁腳、捲動重置也是共用外殼。 第二步的 AudioSettingsPanel 與 MaxAttemptsField 是五種共用的元件，v3 已經動過； Vocabulary 跟 Mirroring 不同的地方在 §3 與 §4。

第一步 · Vocabulary

一個多選的 Autocomplete（Pick projects to source vocabulary from），候選只留 hasVocabularyData() 過的專案（splitArticleArray 裡有中文字），每列帶語言／級數 chip， 右邊印 N words 或紅字 No teaching points。選了之後出現 Teaching Points Preview——每個專案一張卡、詞用 chip 列出來——底下一條綠色的 Content will be loaded from the selected project. ＋ Load Content。

跟 Mirroring 不一樣：practice 是在第一步裡按 Load Content 建的，不是按 Next 建的。 Next 在 practice 存在前是灰的（activeStep === 0 && isVocab && mode === 'CREATE' && !effectiveId）， 硬按會跳 Please load vocabulary content before continuing.

Load Content 之後 status 先是 GENERATING——第一步不開 ProcessingDialog （open = (isProcessing || isAudioGenerating) && activeStep > 0），改用 VocabularyLoadingState 在原地放一張 loading 卡。完成後 Autocomplete 鎖住、Teaching Points Preview 消失，換成 Vocabulary Content：每個專案一個手風琴（folder 圖示、專案名、N vocabs、右邊一顆綠色 Add Vocab ▾ → From Project / Custom Word），裡面一張一張 280–320px 的生詞卡：右上角 編輯（例句）／隱藏 兩顆鈕、 圖片（可在縮圖裡挑一張）、字、拼音、翻譯、詞性／型別／級數 chip、例句 1／例句 2； 文法類（GRAMMAR / PHRASE / OTHER）或含非中文字元的詞多一個 Read Sentences Only 開關。

選 Project 的當下 practiceName 就被設成第一個選到的專案名稱了 （setValue('practiceName', value[0].projectName)），欄位在第二步——跟 v3 問題 1 一樣。

5 查到的問題

每一條都在程式碼裡看得到。編號只是編號，沒有優先順序。跟 v3 重複的只註明，不重講。

1 · 三個顯示設定，學生端一個都沒讀

§4.3。老師把 Pinyin 設成 NO_PINYIN、Translation 設成 HIDE、Image 設成 HIDE， 學生打開來仍然是拼音開、翻譯開、圖片在。第二步的 Display Settings 手風琴目前只改老師自己的預覽。 這是「是不是有意的」那一類——要問工程（E1）。答案決定這張卡的第二步要不要重畫： 如果三個設定本來就打算讓學生端吃，那是 bug、畫面照設計走；如果 Vocabulary 本來就是「學生自己決定」，那三個下拉根本不該出現， Image 那一項更是連學生端的畫面都沒有（8/31 inventory 的第 6 題，仍然沒有答案）。

2 · 預覽跟學生端對同一個值畫出相反的東西

§3 的警告。STUDENT_CHOICE 在預覽裡是「不印」，在學生端是「先開著、學生自己關」。 預設值就踩在這個差上：老師第一次進第二步，看到的預覽沒有翻譯，學生看到的有。 另外預覽是「字、拼音、翻譯三欄並排在一個綠框裡」，學生看到的是「拼音在字上面、翻譯在字下面、左邊一張圖」——排版也不是同一個東西（R5 / R6）。

3 · 「一個字＝三張卡」在老師端看不出來

第一步的生詞卡把例句畫成兩個灰底小框、字級 12px，看起來像附註；第二步的預覽把它們叫 Example 1 / Example 2、字級 14px，也還是配角。 但學生要念的是三句、評分三次、attempts 逐卡算。Max attempts before auto pass 的說明寫 on a card—— 用了「card」這個字，可是畫面上沒有任何地方告訴老師一個字是三張 card。

§4.1 有算式：3 tries × 3 cards ＝ 一個字最多 9 次。老師設 3 的時候大概不是這樣想的。

4 · 三個下拉印資料庫欄位值

display-settings-accordion.js 三個 Select 都是 Object.entries(ENUM).map(...)：NO_PINYIN、STUDENT_CHOICE、SHOW、HIDE。 ＝ v3 問題 2，多一個 Image。（R7）

5 · 第一步的按鈕與狀態

Load Content 這個名字講的是「載入」，做的是「建 practice ＋ 叫 AI 生拼音／例句／圖／音檔」——按下去要等幾十秒、之後 Project 就鎖死了。 頁腳的 Next 在它按下之前是灰的，但沒有說為什麼灰（R9）；硬按才跳 snackbar。 Teaching Points Preview 說 Review the teaching points that will be used to generate vocabulary——用了 generate， 按鈕卻叫 Load。同一件事兩個動詞（R10）。

另外：Sentence Scramble 與 Follow Pattern 在同樣位置的按鈕叫 Generate（resolvePrimaryActionLabel）， 而且是頁腳那顆——Vocabulary 是唯一把它塞在內容區裡、頁腳另放一顆灰 Next 的型別。

7 · 練習的名字在第一步被決定，在第二步才看得到

＝ v3 問題 1。多選的情況下取的是 value[0]——第一個選到的專案。

8 · Audio Settings 的說明承諾了畫面上沒有的東西

＝ v3 問題 3（pronunciation precision），共用元件，v3 已處理。

9 · 改 Speed／Voice 會重產全部音檔，並且全螢幕遮罩

一個字三段音檔，N 個字就是 3N 段；改一次 Voice 全部重跑，第二步整頁被 Generating audio… 擋住。 ＝ v3 問題 8 的 Vocabulary 版，量更大。

10 · 兩個小的

  • targetLanguage 的預設值兩步不一樣。 第一步顯示用 TAGS.ZH_CN 兜底，第二步取聲音清單用 practice?.targetLanguage ?? TAGS.ZH_TW—— 專案設定還沒回來的那一瞬間，Voice 下拉會先給繁體那組（7 個混在一起，v3 問題 11）。
  • 學生端的圖片網址寫死 zh-CN。 card-stack.js 呼叫 getVocabularyImageUrls(content, TAGS.ZH_CN)，不看 targetLanguage； 老師端傳的是專案的語言。繁體專案兩邊拿的圖可能不是同一張。學生端的事，這一版不改，記下來。

6 待決事項

分兩類：要使用者決定的（設計方向），和只有工程答得出來的。

要決定的

#題目為什麼要先決定
D1這一版要改哪裡？ 照流程，登記完等使用者說。問題 1–6 是這張卡自己的，7–9 是 v3 已經處理過的共用部分。
D2第二步要不要照 v3 的做法「預覽跟設定合成同一張卡」？ 如果要，這裡的「樣本」不是一句，是一個字的三張卡（§4.1）——卡本身就把「一個字＝三張卡」講清楚了（解問題 3）， 而且要照學生端排（圖在左、拼音在上），不是現在的綠框橫排。但前提是問題 1 有答案：學生端不讀這三個設定的話，樣本上就沒有東西可以設。
D3兩份生詞卡要不要合成一套？ 問題 6。已定（2026-09-11）：生成後的卡只有一份，在第二步 Vocabulary，畫成學生的三張卡；第三步 Settings 底下那份 Vocabulary Preview 還在（沒動），是下一輪要處理的。
D4Load Content 要留在內容區，還是併進頁腳？ 問題 5。已定（2026-09-11）：併進頁腳，標籤留 Next——勾好字按 Next 就生成，生完留在第一步看卡，再按 Next 到 Settings。Scramble / Follow Pattern 同一位置叫 Generate，要不要對齊留給下一輪。
