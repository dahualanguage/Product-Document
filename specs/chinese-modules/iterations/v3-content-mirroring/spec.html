v3 — 優化 Practice-Content Mirroring

Content Mirroring 的建立流程是三步：Content → Settings & Preview → Assign Practice。§2–§4 是現況與十二個查到的問題，§6 是提案——流程從三步變四步，Settings 收成三段、主角是一張既是預覽也是設定介面的樣本句， Assign 從對話框搬回頁面。

2026-09-09 分岔自 v2 程式碼基準 origin/develop @ c01d0ac0 狀態：提案完成（未定稿）· Settings 第四版 2026-09-14

1 這一版的範圍

使用者給的入口是 https://dahua-dash-dev.web.app/dashboard/practice/create/?type=MIRRORING， 也就是在 Choose Practice Type 點下 Content Mirroring 之後進的那條建立流程。範圍就是這三步， 不含 Choose Practice Type 那一頁（那是 v1）、不含 Edit 模式、不含其他七張卡。

v1 的設計已經上線了。 src/utils/practice-type-labels.js 現在就是攤平後的八張卡、 四個欄位（Content / Vocabulary / Sentence / Comprehension）與四個顏色（#00B95C / #EFA00B / #EC4899 / #8B5CF6）——跟 v1 spec §4 定案的一模一樣。 所以這一頁的標題在產品裡真的叫 New Content Mirroring，不是舊的 Mirroring Practice。
設定表已經跟 8/31 那份盤點不一樣了。 English First 已被 Translation First 取代，而且從布林變成三個值 （On / Off / Student choice），還是這張畫面上唯一有人話標籤的下拉。 practice-settings-inventory.md 那一欄要更新。

不在範圍內、但會被牽動的

§4 有兩題（問題 5 Audio Mode 的定位、問題 6 Preview 名不副實）一旦動， 改的是老師對「學生會看到什麼」的理解，設計上勢必要把學生端畫出來對照。學生端本身不改，但要畫。

4 查到的問題

以下每一條都在程式碼裡看得到，不是推理出來的。編號只是編號，沒有優先順序。

1 · 練習的名字在第一步被決定，在第二步才看得到

選 Project 的那一刻 practiceName 就被設成專案名稱了，但欄位長在下一步。 老師在第一步不知道自己已經有一個名字，到第二步看到一個「自己沒打過的名字」躺在最上面。

2 · 同一張畫面上，兩個下拉給老師看資料庫欄位值

Object.entries(PINYIN_PREFERENCES).map(...) —— 老師看到的是 NO_PINYIN、 STUDENT_CHOICE。而正上方的 Translation First 有一份 _LABELS，顯示的是 On / Off / Student choice。同一張畫面，兩套做法，其中一套是漏掉的那一套。

（＝ mirroring-settings-questions.md 的 Q3，過了六百多個 commit 仍在。Follow Pattern 也一樣。）

3 · Audio Settings 的說明承諾了畫面上沒有的東西

說明文字寫著 “Controls audio playback speed, pronunciation precision, and voice.”， 但畫面上只有 Speed 和 Voice。發音嚴格度被一行 TODO 關掉了：

// audio-settings-panel.js {/* TODO: Re-enable pronunciation slack selector once the new pronunciation Lambda supports the slack parameter … */} // config/practices.js — 選項本身還在 SLACK_OPTIONS = [ 🟢 Gentle (Easy) · 🟡 Teaching standard (Normal) · 🔴 Exam level (Hard) ]

（＝ Q2，仍在。設計這邊被這句文案誤導過一次，憑它做了一個不存在的設定。）

4 · 「學生自己決定」在同一張畫面上有三種機制

更正（2026-09-14）。 學生端 Mirroring 是兩欄：左欄 content-window.js 的整份清單裡， 翻譯的 Their choice 是逐句眼睛；主欄 practice-content-list.js → message-list.js 的 PRACTICE SENTENCE 卡 右上角有跟 Vocabulary 共用的 settings-panel.js，Pinyin／Translation／Translation first／Speed 四個 Their choice 都是那裡的 toggle（resolveToggleVisibility）。這一題講的「三種機制」在主欄其實是統一的——不一致的是左欄。
設定學生要怎樣才能自己決定
Pinyin · Translation自己的選項裡有 STUDENT_CHOICE，但 Audio Mode 打開會覆寫並鎖死
Speed選項裡有 Student choice，獨立於 Audio Mode，不會被鎖
Translation First選項裡有 Student choice，同樣不受影響

四個設定、三種行為。老師沒有辦法從畫面上看出為什麼有兩個會變灰、另外兩個不會。

5 · Audio Mode 不是顯示偏好，卻排在顯示偏好中間

它改的不是「這個練習長什麼樣」，是「這個練習是什麼」——學生端整片課文會換成一張純聽力卡 （assignments/content/index.js 的 renderAudioModePanel：耳機圖、 Audio Mode is ON、Please pay attention and repeat the sentences.，拼音預設關）， 開始卡也換成 Listen and repeat — text is hidden。

但它在畫面上就是五塊裡的第一塊，看起來跟 Translation First、Display Settings 同一個層級。 名字也沒講出「純聽力」。它會強制鎖住那兩個偏好，正是因為它根本不同層——但畫面沒有表達這件事。

6 · 這一步叫 Settings & Preview，但 Preview 不是學生看到的東西

底下那份句子清單是老師視角的稿件：一句一列、一顆播放鍵，跟著 Pinyin / Translation 兩個下拉決定要不要顯示拼音與翻譯。學生端的 Mirroring 畫面不長這樣。

Audio Mode 打開時最明顯：學生根本看不到這些句子（換成純聽力卡、拼音預設關）， 但這份清單照列五句、照顯示拼音。Preview 在說謊的情況是可以直接製造出來的。

7 · 句子編輯在第一步，但第一次走到第一步時它不存在

要編句子（切句、合併、刪除）得先按 Next 建出 practice，再按 Back 回來。 第一次進第一步的人不會知道這裡之後會多一張表。

// step-one-mirroring.js // No auto-creation: practice is created when user clicks Next committedRows ← draft.updatedArticleArray ?? practice.updatedArticleArray ?? [] // CREATE 時是空的

8 · 在第二步動任何一個下拉，都可能被全螢幕遮罩擋住

Speed 或 Voice 改動 → 一定重跑 SQS 產生音檔 → Generating audio… 全螢幕 modal （不能按 Esc 關），三段進度條每 10 秒往前一格。

拼音／翻譯／Audio Mode 也會。 前端刻意把它們排除在 AUDIO_AFFECTING_FIELDS 之外，但草稿路徑的後端仍然會 enqueue SQS，程式碼註解自己講了：

// use-practice-editor.js // Backends like upsertPracticeDraft may flip audioStatus to GENERATING for // fields (pinyinPreference, translationPreference, audioMode) the frontend // list excludes …

所以老師只是想把拼音關掉，就有機會整頁被擋住幾十秒。而遮罩的條件是 (isProcessing || isAudioGenerating) && activeStep > 0——第一步刻意不擋，第二步全擋。

9 · 三步的主要按鈕是三個不同的詞

Next → Save → Done。中間那顆叫 Save 是因為 activeStep === assignStepIdx - 1 會真的送出，但在一條三步的流程裡，第二步出現 Save 讀起來像「這裡就結束了」。

10 · Auto pass 這一個東西，全產品有三個名字

Mirroring 與 Vocabulary 用共用欄位 Max attempts before auto pass； Sentence Scramble 叫 Attempts per sentence；Follow Pattern 叫 Attempts per question。 這一版只碰 Mirroring，所以這條是「改名字要小心」的提醒，不是這一版要解的問題—— 真要統一就會動到另外三種練習。

11 · 聲音清單把簡體和繁體混在一起，而且看不出來

只有 zh-TW 的專案會混。 getVoiceList() 對 zh-CN 只回 SIMPLIFIED 那組四個，對 zh-TW 回的卻是 [...TRADITIONAL(3), ...SIMPLIFIED(4)]——七個串成一份清單。 而標籤只寫 HsiaoChen (Female)、Xiaorou (Female)， 沒有任何地區標記，繁體專案的老師會在同一份下拉裡看到四個大陸口音的聲音，從名字分不出來。

（同一批聲音在 pronunciation-sandbox/constants.js 裡倒是寫了 (TW, female) / (CN, female)，所以標記是有的，只是沒帶進練習設定。）

12 · 換步驟不會回到頁面最上面

practice-unified-view.js 整份只有一個 scrollIntoView， 而且是處理對話框關閉後捲到某張卡的——沒有換步驟時的捲動重置。 第一步的句子表或第四步的班級清單一長，按 Next / Back 就會落在半空中。

（提案已修：換步驟、送出指派、結束流程三個時機都捲回最上面。基準檔維持原狀。）

5 待決事項

分兩類：要使用者決定的（設計方向），和只有工程答得出來的。 「產品實際長什麼樣」不列在這裡——那種問題去 repo 裡找就有答案。

要決定的

#題目為什麼要先決定
D1這一版要改的是結構還是用字？ 問題 1／5／6／7 是結構（東西放錯步、放錯層級），問題 2／3／9 是用字。兩種的動土範圍差很多——後者幾乎不動流程。
D2可不可以動共用元件？ Audio Mode 卡、Audio Settings 面板、Max attempts 欄位是五種練習共用的。動了就是五種一起改；不動的話有些問題只能繞路解。
D3Preview 要不要真的畫成學生畫面？ 問題 6 若要解，就得把 Mirroring 的學生端（含純聽力兩種狀態）畫進這一頁。這會讓這一版從「整理設定」變成「重畫一步」。
D4Planning 那條線的分組要不要拿來用？ teacher-planning.html 的右側面板已經把同一批設定重新分過組（依「它改變什麼」：看得到的貼預覽、聽得到的收一組、什麼時候算過關單獨一行），也已經把 Pinyin/Translation 改成 Shown / Hidden / Their choice。要沿用還是各走各的。

要問工程的

#題目狀態
E1新的發音 Lambda 什麼時候支援 slack 參數？ 問題 3。決定「發音嚴格度」要不要現在就設計進去。不管答案是什麼，那句文案都該先改掉——它現在承諾一個不存在的控制項。
E2兩個下拉直接露出 enum 值，是有意的嗎？ 問題 2。若不是，這是一個一行就能修的字串問題，不必等這一版定稿。
E3拼音／翻譯／Audio Mode 觸發 SQS 重跑，是後端刻意的嗎？ 問題 8。純 metadata 卻要重產音檔，若非必要，遮罩就不該出現。這題會直接決定第二步能不能「即時預覽」。
D2 與 D3 已經回答（2026-09-09）。 可以動共用元件——「改好之後五種練習一起改」； 樣本句也可以真的畫成學生畫面。提案見 §6。D1 與 D4 還沒問，但提案先照 「結構與用字一起動、沿用 Planning 那套分組」的方向走。

6 提案

一句話：把「設定」這一步變成一張學生會看到的句子，控制項長在它上面。 不是「設定面板＋旁邊一個預覽」——那兩個永遠有機會不一致（現在就是，見 §4 問題 6）。 是同一張卡同時是預覽也是設定介面，所以它不可能跟自己矛盾。
§6.1–§6.4 是第一版提案（2026-09-09）。 Settings 那一步在 2026-09-14 改成第四版「工具列 ＋ 畫布」， 見 §6.9；三段分法、樣本句、純聽力交出去的做法都被它取代，留在這裡當過程。

6.1 分成三段，依「它改變什麼」

段裡面有什麼為什麼是一段
On screen樣本句 ＋ Pinyin ＋ Translation 這三個講的是同一件事：學生螢幕上有什麼。所以它們在同一張卡裡，控制項就貼在它改的東西下面。
On playPlay the translation first ＋ Speed ＋ Voice 按下播放之後會聽到什麼。試聽鍵也在這一段——聲音的事都在這裡。
PassingMove on after N tries 什麼時候算過關。只有一項，但它跟看／聽都不同類，硬併進去只會讓另外兩段變得不精確。

Audio Mode 不在這三段裡。 它換的是練習本身（§4 問題 5），所以提到最上面、 改成兩選一的模式：Text on screen / Audio only。不是開關——開關暗示 「有一個預設狀態、另一個是加購」，但這是兩種同等的練法。

分組原則沿用 Planning 那條線。「依它改變什麼分組，不依欄位來源」是 teacher-planning.html 的右側面板已經在走的做法。 兩條線講同一套語言，不是這裡新發明的。

6.2 逐個控制項的處置

現在改成為什麼
Audio Mode 開關，夾在五張卡中間Text on screen / Audio only 兩選一，置於最上 它是練習模式，不是顯示偏好。
Pinyin PINYIN / NO_PINYIN / STUDENT_CHOICE 分段控制項 Shown / Hidden / Their choice 三個短選項全部露出比藏起來好：一次點擊、看得到有哪些、看得到現在是哪個。用字跟 Planning 一致。
Translation SHOW / HIDE / STUDENT_CHOICE同上同上。
Translation First（標題是欄位名） 敘述句 Play the translation first ＋ Yes / No / Their choice 是一個問句，就該用 Yes / No 回答。
Speed 下拉（含 Student choice） 跟 Voice 同一種 chip：▶ Slow / ▶ Normal / ▶ Fast ＋ 不帶 ▶ 的 Their choice 速度跟聲音是同一類決定——都得先聽過才選得出來，所以用同一個元件： 點一下＝選它＋聽它。Their choice 不是一個聽得到的速度， 刻意不給 ▶——少一個播放鍵本身就說明了「這裡沒有東西可以聽」。 原本那顆獨立的 Hear a sample 因此多餘，收掉。 四個「學生自己決定」仍然全部講同一句話 Their choice（解 §4 問題 4）。
Voice 下拉，每列一顆小 ▶ chip，點一下＝選它＋聽它；標籤用 config 裡的原字串 （Xiaorou (Female)），不縮寫 聲音不聽就選不出來。現在要「開選單→找→點小三角→選單還開著」。 地區標籤只在不只一組時出現——它是為 §4 問題 11 那個情況存在的： getVoiceList('zh-TW') 會把簡體四個接在繁體三個後面。 zh-CN 只有一組，標上語言只是把已經選好的專案語言再講一次。
Max attempts before auto pass 數字欄位 Move on after 3 tries ＋ 加減鈕 原標籤講的是機制（auto pass），不是老師關心的事。
Practice name 在第二步移到第一步，選 Project 的正下方 它在第一步就被填好了（§4 問題 1）。搬過去之後那個「自己沒打過的名字」就有出處了。
底下一長串句子清單樣本句的 ‹ Sentence 1 of 5 › 翻頁 ＋ 收起來的 All 5 sentences 清單真正的用途是「逐句確認音檔有沒有問題」，那是驗證不是預覽，收起來就好。
不是「下拉一律不好」。 下拉的價值是「清單很長，先收起來」。這一頁四個下拉裡有三個 只有 3–4 個選項、每個兩個字，收起來沒省到空間，卻要兩次點擊、看不到選項、也沒辦法比較。 規則是選項固定又短就攤開，資料驅動又長就收起來。Voice 是唯一長的那個—— 而它連下拉都不當，因為它的選項要「聽過」才有意義。

第一步的兩個欄位：c-input-2 與 c-dropdown-menu-18

c-input-2（Input with label）＝ Field + FieldLabel + Input。 標籤在輸入框上面，不是 MUI 那種浮在框線上的凹槽標籤，輸入框也從 56px 收到 40px。 Practice name 照這個做。

Content preview 換成 ReUI 的 c-frame-6（ghost）

Frame → FrameHeader（Title ＋ Description）→ FramePanel → FrameFooter。c-frame-6 用的是 ghost 變體：外框沒有邊框， 只剩底色與 panel。重點在同心圓角，而 ghost 因為少了那 1px 邊框，算式也跟著少減 1：

--frame-radius = --radius-xl = calc(0.625rem + 4px) = 14px --frame-px = --spacing(0.75) = 3px ghost: --frame-panel-radius = calc(--frame-radius - --frame-px) = 11px default: --frame-panel-radius = calc(--frame-radius - --frame-px - 1px) = 10px

panel 的圓角是外框圓角減掉內距（default 變體再多減 1px 邊框）， 所以內外兩道弧線平行，而不是內外一樣圓。外框灰底 3px 內距，內 panel 白底、細邊、 shadow-xs、16px 內距；header 與 footer 在框內、panel 外。

選 ghost 的理由：這一頁的 1px 邊框已經夠多了。 上面兩個欄位各一道、panel 自己一道，default 變體再加一道外框就變成三層框線。 ghost 把最外那層拿掉，灰底當托盤、白 panel 當內容，層次靠底色差而不是線。

順手收掉了三層重複的標題。 現行同一件事被標了四次—— Content Preview 綠色分隔線、綠色的專案名、Article Content 小標、 然後才是那個綠框。改成 Frame 之後是 Title Article content ＋ Description 直接放專案名稱＋ 白底 panel，一層一個工作。 （Description 原本寫 From ⟨專案名⟩，那個 From 沒有做事—— 標題已經說了這是課文，副標放來源就夠了。第二步的 Split from ⟨專案名⟩ · 5 sentences 保留 Split from， 那句話在講「這些句子是從哪裡切出來的」，拿掉就不成句了。）

沒有 footer——照 c-frame-6 的範例，只有 Header ＋ Panel。 （曾經在這裡放過一行「Sentences and audio are generated when you continue.」回答 §4 問題 7， 已拿掉；問題 7 因此仍然沒有解，見 §6.7 P3。）

一處換色：原版外框是 bg-muted/50，那在白色頁面上讀得出來； 這一頁底色是 #f4f7fb，直接用 grey.200 外緣會整個糊掉， 所以換成產品自己的淺綠色票：PRACTICE_TYPE_COLUMNS.CONTENT.wash = #EFFBF4（practice-type-labels.js）。 Content Mirroring 就是 Content 欄那張卡，用它自己那一欄的 wash 最站得住； 而且現行的課文預覽本來就是綠底綠框，綠在這個位置是產品既有的說法， c-frame-6 換掉的是框線結構不是顏色。

用實色而不是半透明：ghost 沒有邊框，形狀全靠這層底色撐， 實色才不會隨背後的東西變色。同一個色票也收掉了我先前在三個地方各自調的 alpha （.06 模式卡選中 / .07 切句中的那一列 / .10 外框）—— 一個淺綠，一個值。

取捨：#EFFBF4 比先前的 .10 疊色淡。 配上 ghost 的無邊框，外框的邊緣偏柔。想要更明確有兩條路—— 改回 c-frame-16（default 變體，加回 1px 外框）， 或把外框邊線設成同一欄的 tint: #BBF1D0。

Stepper 換成 ReUI 的 c-stepper-2

來源 @reui/c-stepper-2（https://reui.io/r/c-stepper-2.json ＋ @reui/stepper）。 它跟現行 MUI Stepper 的差別是三件事：指示圈 24px 圓形、四個狀態都顯示數字（不換成打勾）、 連接線是 2px 圓角實心條而不是髮絲線、而且走過的那一段會變綠—— 進度因此看得出來，不只是「現在在第幾步」。

  • 原版只有數字、沒有標籤。Content / Settings / Assign Practice 是必要資訊，保留。

還有一個換色：未走到那格原版是 bg-accent，那是預設「白底」才看得見； 這一頁底色是 #f4f7fb（hasTintedBg），淺灰會整個糊掉，所以加深一階到 grey.300。

只改了提案頁。 create-mirroring.html 是現行產品的複刻， 它的 Stepper 維持 MUI 原樣——基準檔一旦跟著提案走，就沒有對照組了。

關鍵前提：一份作業可以重複指派

這一點決定了整步的形狀。 指派不是流程的終點、也不是一次性的動作—— 同一份練習可以先派給一個班，之後再派給別班、或用不同的日期再派一次。 （這裡原本被我當成「兩顆按鈕」的問題，是我把它讀成一次性動作了。）

提案的預覽框守一條規則：只講例外，不覆述常規。

  • 標題用跟觸發鈕一模一樣的字（Assign to 2 classes）—— 同一個動作從頭到尾同一個說法；底下就是 Back / Assign 兩顆鈕， 本來就看得出是確認關卡，不必再寫一句「Review before assigning」。
  • 副標只留兩個要確認的數：Mandatory · 10 students。 Mandatory 的定義寫在後面那一頁的 How it counts 裡，老師三秒前才選過。
  • 整班 → 一句 all 5 students，不列名字； 有人拿不到 → 5 of 6 students ＋ 只把那個人與原因寫出來 （郑雅文 is already in Chinese 3B）。第一版把八個人全列成藥丸， 而那八個就是整班——名字沒有帶來新資訊，老師上一畫面才剛勾過。
  • Mandatory / Optional 是整批共用的設定，寫在最上面一次， 不用每個班掛一顆一樣的 pill。
  • 班名用 CONTENT.label（#00754A）——那一組色票裡唯一為文字準備的綠； primary #00CB61 當 14px 內文對比只有 2.3:1。
比產品多一段：被跳過的人。 產品的建立模式確認框不會講衝突（只有編輯模式列 added / removed）。 但衝突是真的會發生——老師該在按下去之前就知道有人沒拿到、以及為什麼。 取捨：不列全部名字。 想在送出前逐一核對名單就得按 Back 回去看名冊； 判斷是這個框的工作是「確認形狀」不是「逐一核對」。

6.6 冒的險，以及它為什麼站得住

險：把預覽跟設定合成同一張卡。 代價是那張卡的視覺重量遠大於其他區塊； 好處是這一頁唯一用「內容尺寸」排版的字就是學生會看到的那句話，其餘全是 14px 的介面字—— 層級不靠顏色也不靠框線，靠字級差。配色完全不動，沿用 theme/palette.js。

站得住的地方：試聽的素材本來就是「聲音 × 速度」的組合。

// use-audio-preview.js · handlePreviewSpeed const currentVoice = voiceList.find((v) => v.id === selectedVoice); const url = currentVoice?.exampleAudio?.[SPEED_KEY_MAP[speed]];

所以點一個速度 chip 就能播「當下這個聲音＋那個速度」，用現有素材就做得到， 不需要後端——這也是 Speed 能跟 Voice 用同一個元件的前提。 但播的是範例音檔，不是這一句：這一句的音檔要 SQS 重跑完才有。 所以說明文字寫的是 Tap one to hear it，沒有承諾是這一句。
