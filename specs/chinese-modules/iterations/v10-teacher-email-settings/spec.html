通知信設定：老師、學生、Mail Box

讓老師決定自己觸發的信怎麼寄，讓學生決定自己要收哪些信，站內用 Mail Box 兜住所有通知。

v102026-10-21狀態：提案第二十輪，等 PM／後端回待定原型：老師 Settings · 學生 Settings · Mail Box

1 為什麼做

DAHUA AI 現在會寄九種通知信，全部由系統固定觸發，沒有任何人能設定：老師不能決定派作業要不要通知、要不要自動催交；學生不能決定每天那封彙整要不要收。結果是三個問題：

  • 老師沒有自動催交的工具。要提醒學生只能一個一個按 Remind，而且按兩次會寄兩封（後端刻意不去重）。
  • 學生收到的信彼此重疊。一個作業從派到逾期，學生最多收到五封：派作業通知、每日彙整兩次、老師的提醒兩次。沒有一處能調。
  • 站內沒有通知。老師留了回饋、作業快到期，學生只能靠 email 知道；email 沒看就什麼都沒有。

2 目標與範圍

目標

  1. 老師在一個設定頁決定「我收什麼」和「我的學生收什麼」，預設值等於今天的行為——老師不動設定，一切照舊。
  2. 老師可以設自動提醒（到期前幾天、逾期後幾天各寄一封），不用再一個一個按。
  3. 學生在自己的設定頁決定要收哪些 email；站內 Mail Box 一律會有通知，email 是加選的。
  4. 所有信的名字在三個地方一致：設定頁、Mail Box、信本身。

這一版做

  • 老師端 Settings 頁（Account 選單那一項，原本叫 Profile）：Profile ＋ 兩段信的設定。
  • 學生端 Settings 頁（學生端 UI）：Profile ＋ 一個 email 總開關。
  • 學生端 Mail Box：側欄新項目，三型通知。

這一版不做

  • Teacher Dashboard 的 Send reminder 按鈕本身不動；派作業對話框不加勾選。
  • 班級層級覆寫、學校層級預設（第三期）。
  • 改信的文案與版型（Brevo 模板不動，只有 Assignment reminders 那封多一段老師留言，見第 11 節）。
  • 「Ask me each time」這種每次都問的選項，不做（2026-10-19 定：開關就好）。

4 使用情境

老師Joey 不想每天早上收到五封「今天到期」。她把老師收的 Daily summary 改成「只在有人沒交時寄」、合併成一封、時間改 07:30。
老師Joey 的學生常常拖到最後一天。她打開 Assignment reminders，設到期前 2 天一封、逾期後 1 天一封，留言「You have not submitted this assignment yet…」。之後每個作業自動寄，不用再去 Dashboard 一個一個按。
老師Joey 想要 7 天前也提醒一次。Reminders 清單按 Add reminder 加一列、填 7 days before the due date。
老師Joey 不想學生每次被派作業就收信。關掉 New assignment。學生每天還是會收到 Daily summary，那封不歸她管，她的 Settings 頁也不列。
學生Amy 每天早上的彙整信太多，不想收。在自己的 Settings 關掉 Daily summary。老師的提醒她還是會收到，而且站內 Mail Box 一定有。
學生Amy 想知道老師有沒有回饋。側欄 Mail Box 徽章顯示 2，點進去看到「Feedback on Unit 3 Speaking Practice」，點開有老師的話和一顆 Open in History。

5 老師的 Settings

入口：右上頭像 → Account 選單 → Settings（原本叫 Profile，頁面標題原本叫 Edit User）。只在編自己時顯示信的設定；管理員替別人編帳號時維持原本的 Edit User。

老師的 Settings：三段 Profile／Emails you receive／Emails your students receive，提醒規則打開開原型 ↗

頁面結構

  • 三段，每段一張白底列表、各自一顆 Save：Profile（現有欄位）、Emails you receive、Emails your students receive。
  • 每列只有：信的名字、Preview（開一個對話框看那封信長什麼樣）、右邊一顆開關。沒有說明文字。
  • 開關開著時，底下出現灰底小表放規則；關掉整塊收起。

入口：學生端右上頭像 → Settings。用學生端的 UI（跟 /student/practice 同一套殼）。

8 寄信規則

  1. 誰的設定管哪封：寄給學生的信（New assignment、Teacher feedback、兩種 reminders）以「那個作業的老師」的設定為準。寄給老師的信（老師的 Daily summary、Question bank ready）以老師自己的設定為準。學生的 Daily summary 只看學生的設定。
  2. 學生的總開關是最後一關：寄給學生的每一封都先看它。老師開、學生關 → 不寄 email、Mail Box 有。老師關 → 什麼都沒有。
  3. 自動提醒的上限：學生交了就停；兩列落在同一天只寄一封；同一個學生同一個作業 24 小時內最多一封（手動按的也算進去）。清單沒有列數上限——老師加的每一列都是她要的。待定 24 小時這條會改掉現在「按兩次寄兩封」的行為，要後端點頭。
  4. Optional 作業：現在派作業時選 Optional 就「不寄提醒信」。這條涵蓋哪幾封要後端回；原則上 Optional 作業不進自動提醒。
  5. 時區：Daily summary 的時間和「n 天前」都用學校時區。待定 School 有沒有時區欄位。
  6. 信的名字：設定頁、Mail Box、Preview 對話框的標題三處一致，見第 3 節。

11 資料與接點

給工程的摘要，細節進交接包。

  • 存哪裡：User 上一個 notificationPreferences JSON，老師、學生各自的鍵；用現有的 updateUser mutation 擴充 input。
  • 老師的 Daily summary（模板 17）的排程：寄之前讀老師的設定（開關、時間、只在有人沒交時、合併）。
  • New assignment（模板 14）、Teacher feedback（模板 15）：assignAssignment、teacherFeedback 寄信前讀老師的開關，再讀學生的 email 總開關。
  • Assignment reminders（模板 48）、Word Game goal reminders（模板 49）的自動提醒：新的排程，每天跑老師的 Reminders 清單；ReminderLog 記每封（學生、作業、時間），用來做 24 小時上限；手動 Remind 的兩個 mutation 也寫 log。
  • Assignment reminder 的信（模板 48）：照 Word Game goal reminder 的信（模板 49）加「A Note From Your Teacher」一段和 MESSAGE 參數；sendStudentAssignmentReminder 多傳 message。
  • 學生的 Daily summary（模板 59）：排程寄之前讀學生的 email 總開關。
  • Mail Box：新的 Notification 資料（type、from、title、preview、body、link、read）；Teacher feedback、兩種 reminders 寄信的同時寫一筆；未讀數給側欄。
  • Preview：設定頁的 Preview 用現有模板的渲染結果，固定預設版，不跟設定連動。

預設文案（老師可改）：Assignment reminders「You have not submitted this assignment yet. Please finish and submit it when you can.」；Word Game goal reminders「You have not reached this Word Game goal yet. Jump back in when you can — keep it up!」（照產品現有的 remindMessage）。

12 已定與待定

已定

  • 定 Profile 改名 Settings；三段各自 Save；不分頁。
  • 定 不做「Ask me each time」，New assignment、Teacher feedback 就是開關。
  • 定 自動提醒是「一列一封」的清單，不是「每 n 天」的規則；沒有次數上限欄位，也沒有列數上限（2026-10-21）。
  • 定 Assignment reminders 也能留言，預設句給好。
  • 定 學生的 Daily summary 給學生自己設定，老師不能關。
  • 定 老師和學生的每日彙整都叫 Daily summary；Word Game 的期限叫 end date。
  • 定 學生端用學生端 UI；側欄加 Mail Box；站內一律有、email 自己選。

13 怎麼知道做對了

  • 老師手動按 Remind 的次數下降，自動提醒的開啟率上升（目標：上線一個月有三成老師開 Assignment reminders）。
  • 學生 email 的退信、標垃圾、關掉的比例不上升；Daily summary 的關閉率是觀察值，不是目標。
  • Mail Box 的 Feedback 一則被點開到 History 的比例（回饋有沒有被看到）。
  • 客服收到「為什麼收到／沒收到信」的問題減少。
