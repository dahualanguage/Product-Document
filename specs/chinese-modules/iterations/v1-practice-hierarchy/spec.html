3 查到的問題

3.1　同名不同物，而且有兩組

第一層和第二層各有一個 Mirroring 和一個 Multiple Choice，名字一樣但完全是兩回事。老師在第一層看到的六張卡，其中兩張會在第二層再出現一次、意思卻不同。

名稱出現在素材來源步驟
Multiple Choice第一層題庫 Question BankQuestion Bank → Edit & Preview → Assign
Multiple ChoiceVocabulary 第二層生詞Vocabulary → Practice Type → Question Types → Settings → Assign
Mirroring第一層課文句子Content → Settings & Preview → Assign
MirroringVocabulary 第二層生詞Vocabulary → Practice Type → Settings → Assign

3.2　依賴關係在選擇畫面上看不出來

六張卡視覺權重完全相同，但性質差很多：

  • Mirroring / Vocabulary / Sentence Scramble / Sentence Patterns — 直接從 Project 內容生成。
  • Multiple Choice / QA — 需要題庫。從 Project 進來時會先跳出「Select a Question Bank」第二步；該 Project 沒有題庫的話只能先去建一個。

這個分岔在選卡的當下完全沒有提示，老師要點下去才知道。

3.3　Sentence Patterns 的權限不一致

Practice List 的類型篩選用 isDahuaAdmin 把 FOLLOW_PATTERN 藏起來，但這個對話框裡那張卡沒有同樣的判斷。結果是一般老師建得出 Sentence Patterns 練習，卻無法在列表中篩選它。

3.4　六張裡三張掛 NEW

Sentence Patterns、Sentence Scramble、Multiple Choice 都有 NEW 徽章。一半的卡都是新的，這個標記已經失去指示作用。 處置見 §6。

3.5　Mixed Mode 資料層還在、UI 已拿掉

practice-type-selection.js 裡 mixed（Combined practice modes）整段被註解、available: false；但 enum VOCABULARY_PRACTICE_TYPES.MIXED 和兩張 UI↔DB 對照表都還留著。要嘛補回來、要嘛連資料層一起清掉。已決定：連資料層一起清掉（§6）。

4 定案設計

定案。 第二層全部攤平成八張同層卡片，分成四欄； 每一欄上方有共用標題與一條該欄顏色的軌道線；每張卡帶一張學生畫面的示意圖， 示意圖裡「學生會動到的部分」用該欄的顏色畫。 設計檔：choose-practice-type-color.html

四欄：Content · Vocabulary · Sentence · Comprehension，欄高 1 / 2 / 3 / 2。 原尺寸開啟 ↗

4.1　四欄：Content / Vocabulary / Sentence / Comprehension

八張卡分成四欄，欄名講的是這一欄在練哪一種東西——前三欄是語言單位（整篇課文 → 詞 → 句），第四欄是理解：

Content Vocabulary Sentence Comprehension ──────────── ─────────────────── ───────────────── ────────────────── Content Vocabulary Mirroring Sentence Scramble Comprehension Quiz Mirroring Vocabulary Quiz Sentence Response Open-ended Questions Sentence Building

這個分法跟前一版（依素材分成 句子／生詞／教學點／題庫）有兩處實質差異：

  • Sentence Scramble 換欄了。 它的素材是課文句子，依素材分會跟 Content Mirroring 同欄； 但對學生來說它做的事是處理一個句子，跟兩張教學點練習是同一類動作。欄名改講「練什麼」之後，它歸到 Sentence。
  • 「題庫」從欄名消失。 那一欄改叫 Comprehension——講的是這兩張在考理解，而不是題目存在哪裡。 代價見 §4.4 的第一個提醒。

四欄不再等高：1 / 2 / 3 / 2。前一版是整齊的 4 × 2，這一版 Content 欄只有一張，底下空兩格。 這是照實反映「課文層級目前只有一個練法」，沒有為了排版硬湊。

4.2　八個名稱

新名稱欄位現在叫什麼說明文字
Content MirroringContentMirroring PracticeListen and repeat each sentence
Vocabulary MirroringVocabularyVocabulary → MirroringListen and repeat each word
Vocabulary QuizVocabularyVocabulary → Multiple ChoiceImage, pinyin & meaning
Sentence ScrambleSentenceSentence Scramble
（不變）		Listen, then reorder the words
Sentence ResponseSentenceSentence Patterns → Guided ResponseAnswer questions using a pattern
Sentence BuildingSentenceSentence Patterns → Sentence BuildingBuild sentences from teaching points
Comprehension QuizComprehensionMultiple ChoiceAuto-graded questions from a bank
Open-ended QuestionsComprehensionQA PracticeOpen questions, AI assessment

幾個名稱的理由：

  • 兩個 Mirroring 保留同名是刻意的。 它們確實是同一個練法，差別就在素材—— Content / Vocabulary 前綴講清楚就夠，不需要發明兩個不相干的字。 §3.1 的同名問題因此消失，而不是被繞開。
  • 第一層的 Mirroring Practice 補上 Content 前綴，跟 Vocabulary Mirroring 對得起來。
  • Sentence Patterns 這個層級消失，兩個子項目改用 Sentence 前綴， 跟 Sentence Scramble 併成一欄——三張都是「對一個句子做事」。
  • Multiple Choice → Comprehension Quiz：原本的名字只講題型（選擇題）， 沒講在考什麼。改成 Comprehension 之後跟 Vocabulary Quiz 的關係也清楚了—— 兩個都是 Quiz，差在一個考詞、一個考理解。
  • QA Practice → Open-ended Questions：跟 Comprehension Quiz 對照， 一個是選的、一個是自己答的。八個名稱裡只有這一個是複數——它本來就是一組開放題，不像其他七個是一種練法。

4.3　示意圖取代 icon 圓

每張卡的 icon 圓換成一張學生實際會看到的畫面縮圖，老師不必從名字推敲這個練習長什麼樣。 示意圖沿用 teacher-planning.html 已經畫過的那一套（THUMB，136×56 畫布）： 灰色是內容，綠色是學生實際會動到的部分—— 播放鍵、麥克風、被選中的選項、要填的空格。

卡片示意圖畫什麼live 現在的 icon 與顏色
Content Mirroring兩行帶播放鍵的句子ic:round-mic · primary
Vocabulary Mirroring一張生詞卡，底下一支麥克風ic:round-flip · warning
Vocabulary Quiz一個詞、三個選項，中間那個是綠的ic:round-checklist · warning
Sentence Scramble四個散落的詞塊，底下一格虛線ic:round-view-column · #EC4899
Sentence Response一個問句、一個帶空格的句型，然後開口說ic:round-question-answer · #00897B
Sentence Building一個教學點，底下整句自己造ic:round-construction · #00897B
Comprehension Quiz一道題、三個選項，中間那個是綠的ic:round-quiz · #7C3AED
Open-ended Questions一段提示，底下用說的回答ic:round-chat-bubble · info
三個取捨。
① 示意圖取代 icon 圓，不是並存。 兩個都放太重，而且縮圖本身已經是最強的辨識物。 icon 圓因此整個退場，右欄那一列留著是備查——顏色沒有跟著消失，而是換一套規則進到示意圖裡（§4.4）。
② 同一個練法的兩張圖刻意相似。 Vocabulary Quiz 和 Comprehension Quiz 都是「題目＋三個選項、中間那個是綠的」， 差別只在選項寬度——因為它們對學生來說本來就幾乎一樣，差的是考什麼而不是動作。這點看得出來反而是準確的。
③ 對話框變高了。 八張排成三列（而不是兩列），加上示意圖比 icon 圓高， 對話框整體比 live 高一截。窄螢幕（<1040px）退回兩欄、欄位標題變成整行的分隔標籤。

4.4　顏色：四條軌道

§4.3 的代價是顏色整個退場——示意圖換掉 icon 圓之後，四欄之間只剩一行灰色小字在區分。 顏色在這一節回來，用的是現在線上那組色系。

規則只有一條。 示意圖裡的綠色本來就有意思——THUMB 語彙規定它是「學生會動到的部分」。 這一版把它升一級：有顏色＝學生會動到的部分，色相＝這是哪一欄。 顏色因此不是貼上去的裝飾，而是接管了一個本來就存在的語意欄位。灰色仍然是素材，變的只是「學生的那一筆」用什麼顏色寫。

色票怎麼選的

不重新配色——每一欄直接繼承「欄內某一張卡在 live 已經有的顏色」。 攤平＋改名之後剛好四欄各有一張卡帶著一個夠有代表性的顏色過來，所以老師從舊介面過來還認得出誰是誰。

欄色ink · tint · wash · label繼承自 live 的哪一張
Content綠 #00B95C · #BBF1D0 · #EFFBF4 · #00754A Mirroring Practice 的 primary
Vocabulary黃 #EFA00B · #FFE49E · #FFF8E7 · #8F6209 Vocabulary 的 warning 琥珀
Sentence粉 #EC4899 · #FBD5E8 · #FEF2F8 · #BE185D Sentence Scramble 的 #EC4899
Comprehension紫 #8B5CF6 · #E9DDFD · #F7F3FE · #6D28D9 Multiple Choice 的 #7C3AED

被放掉的兩個是 Sentence Patterns 的 #00897B 藍綠與 QA 的 info 藍—— 正好就是卡片換了欄的那兩張（Pattern 兩張併進 Sentence、QA 併進 Comprehension），所以它們本來就得改。 八張裡沒有一張是憑空換色的。

四個值一組的原因：ink 是學生會動到的那一筆（線條、實心的播放鍵與麥克風）， tint 是被選中／被填入的粉彩填色（＝ live 的 icon 圓底色）， wash 是示意圖的底板。label 只給欄位標題的文字用—— 粉彩當 12px 文字讀不動（#EFA00B 在白底上只有 1.9:1），壓深版是同一個色相、對比 ≥4.5:1。

顏色只出現在三個地方：欄位標題與它底下的軌道線、示意圖裡學生會動到的部分、hover 時的卡片框線。 卡片本體維持全白、灰框線、墨色標題。

三個設計判斷。
① 軌道線。 欄位標題底下一條該欄顏色的線，橫貫整欄。四欄因此讀成四條軌道—— Content 欄底下那塊空白（§4.1）跟著從「少了什麼」變成「這條軌道只有一項」。這是這一版唯一多出來的裝置。
② 顏色進示意圖，不進卡片。 卡片本體維持全白、灰框線、墨色標題； 整張卡上有顏色的只有那塊 136×56 的示意圖。這樣八張並排時顏色是在「畫面裡」， 而不是八個色塊在搶——比 live 的 icon 圓輕，但講的事更多。
③ hover 的框線改用該欄的顏色。 live 一律是主色綠；一張粉色的卡被碰到卻轉綠，會讓顏色看起來跟卡片無關。 這是這一版唯一偏離 live 的互動細節。
顏色上的一個已知妥協。 error 紅的 NEW 徽章（#FF5630）壓在 Sentence 欄的粉色示意圖上會有點擠。 橘與洋紅分得開，不到看錯的程度，接受。
順手補的兩件事。 卡片加了 tabindex 與該欄顏色的 focus ring（live 目前用滑鼠以外的方式選不到卡）； prefers-reduced-motion 時關掉 NEW 的脈動動畫。兩件都不影響外觀，實作時一併帶上。

4.5　連帶影響

題庫依賴現在只剩鎖定狀態在講。 Comprehension Quiz / Open-ended Questions 的名字裡沒有「題庫」兩個字， 所以 §3.2「依賴關係在選擇畫面上看不出來」不是靠命名解決的， 完全落在 §5 的鎖定狀態上——沒有題庫時那兩張直接鎖住並寫明缺什麼。 這代表 §5 不是加分項，是這套命名成立的前提。
名稱字串有三個地方要一起改。 AddNewPracticeDialog.js（這個對話框）、 practice-type-chip.js 的 PRACTICE_TYPE_CONFIG（列表上的類型標籤）、 view/index.js 的 PRACTICE_TYPE_FILTER_TABS（篩選下拉）。 漏掉任何一處，列表和建立畫面就會叫不同名字。這一版的設計範圍只有對話框，但實作時三處要同步。
建立流程的第 2 步變成多餘。 攤平之後， StepTwoVocabularyType 和 StepTwoSentencePatternType 這兩個「Practice Type」步驟已經在選卡當下就決定了。四條流程各少一步，步驟表 STEPS_BY_TYPE 要跟著重寫。

5.2　提案

改名之後 Comprehension Quiz / Open-ended Questions 的名字裡不再提到題庫（§4.2）， 所以這一頁是題庫依賴唯一被說出來的地方——它不是加分項，是那套命名成立的前提。

沒有 Question Bank 的情境。頁面上方的膠囊可以切換三種情境（展示用，不是產品的一部分）。 原尺寸開啟 ↗

  • 兩種缺料都事先擋下——題庫和專案內容，不只現在的 content 一種。
  • 鎖定的卡片說明缺什麼：說明文字換成 Needs Question Bank，示意圖抽掉飽和度（該欄的顏色跟著淡掉），右上角加一個鎖。
  • 解鎖動線放在卡片上：Create Question Bank →，不必回頭找入口。
  • 頂部一句話交代整體狀況，沿用 live 既有的 MUI Alert 樣式與位置（hasContent 那個警告就在同一個位置）。
三個設計判斷。
① 不用 live 的 opacity: .5 + pointerEvents: none。 那會把「怎麼解鎖」也一起壓灰、而且點不了。這裡改成卡片本體轉灰、但解鎖動線維持可讀可點—— 鎖定的目的是指路，不是單純擋住。
② 卡上的動線只在「部分鎖定」時出現。 八張全鎖時它會重複八次、又和頂部按鈕講同一件事， 所以全鎖情境只留頂部那一個入口，卡片單純說明缺什麼。
③ 顏色抽掉，只留出口。 定案沒有 icon 圓可以轉灰（§4.3），改成把示意圖 grayscale(1) + opacity .45—— 該欄的顏色（＝學生會動到的部分）跟著消失，「這條軌道現在走不了」自己就說完了。 欄位標題那條軌道線維持原色（欄位沒有被鎖，是卡片被鎖）， 而卡上唯一還有顏色的是解鎖動線——一張灰卡上唯一活著的東西就是出口。
