3 查到的問題

3.1　同名不同物，而且有兩組

第一層和第二層各有一個 Mirroring 和一個 Multiple Choice，名字一樣但完全是兩回事。老師在第一層看到的六張卡，其中兩張會在第二層再出現一次、意思卻不同。

名稱出現在素材來源步驟
Multiple Choice第一層題庫 Question BankQuestion Bank → Edit & Preview → Assign
Multiple ChoiceVocabulary 第二層生詞Vocabulary → Practice Type → Question Types → Settings → Assign
Mirroring第一層課文句子Content → Settings & Preview → Assign
MirroringVocabulary 第二層生詞Vocabulary → Practice Type → Settings → Assign

3.2　依賴關係在選擇畫面上看不出來

六張卡視覺權重完全相同，但性質差很多：

  • Mirroring / Vocabulary / Sentence Scramble / Sentence Patterns — 直接從 Project 內容生成。
  • Multiple Choice / QA — 需要題庫。從 Project 進來時會先跳出「Select a Question Bank」第二步；該 Project 沒有題庫的話只能先去建一個。

這個分岔在選卡的當下完全沒有提示，老師要點下去才知道。

3.3　Sentence Patterns 的權限不一致

Practice List 的類型篩選用 isDahuaAdmin 把 FOLLOW_PATTERN 藏起來，但這個對話框裡那張卡沒有同樣的判斷。結果是一般老師建得出 Sentence Patterns 練習，卻無法在列表中篩選它。

3.4　六張裡三張掛 NEW

Sentence Patterns、Sentence Scramble、Multiple Choice 都有 NEW 徽章。一半的卡都是新的，這個標記已經失去指示作用。

3.5　Mixed Mode 資料層還在、UI 已拿掉

practice-type-selection.js 裡 mixed（Combined practice modes）整段被註解、available: false；但 enum VOCABULARY_PRACTICE_TYPES.MIXED 和兩張 UI↔DB 對照表都還留著。要嘛補回來、要嘛連資料層一起清掉。

4 設計決定

已決定（2026-08-19）。 第二層全部攤平成八張同層卡片；八個名稱全部重新定義成一套系統。 設計檔：choose-practice-type-a.html

提案 A — 攤平八張

八張同層卡片，4 欄 × 2 列，同素材直向成對。顏色與 icon 全部沿用 live。 原尺寸開啟 ↗

提案 B — 攤平八張 ＋ 同源標題

卡片跟 A 完全一樣，只在每一欄上方加一個共用標題，講明這一欄的兩張考的是同一批素材： Sentence、Vocabulary、Teaching Points、Question Bank。

沒有群組框線、沒有底色，只是欄位上方多一行小字，所以 A 的扁平感大致保留； 但四種素材的關係從「要自己看出來」變成「直接寫在上面」。

四個共用標題，各罩住同一欄的兩張卡。卡片名稱維持完整，不因為有了標題就縮短。 原尺寸開啟 ↗

三個設計判斷。
① 標題講「在考什麼」，不是「取材自哪裡」。 用 Sentence 而不是 From the passage—— 老師要判斷的是這一批練習在練哪一種東西，不是資料從哪來。
② 名稱不縮短。 有了 Sentence 標題之後，卡片其實可以縮成 Mirroring、Scramble， 但那會讓兩個 Mirroring 並排、必須靠上方標題才分得出來。維持完整名稱，卡片單獨被引用時（列表、篩選、通知）也還說得清楚自己是誰。
③ 標題和卡片放在同一個 grid。 不是切成四個獨立欄位——同一個 grid 排三列，跨欄的 icon、標題、說明文字才會落在同一條線上。

提案 C — 攤平八張 ＋ 學生畫面示意圖

把 icon 圓換成一張學生實際會看到的畫面縮圖。老師不必從名字推敲，直接看出這個練習長什麼樣、學生要做什麼動作。

示意圖沿用 teacher-planning.html 已經畫過的那一套（THUMB，136×56 畫布）： 灰色是內容，綠色是學生實際會動到的部分—— 播放鍵、麥克風、被選中的選項、要填的空格。六張直接對應現有的圖，Pattern Response 與 Pattern Building 照同一套語彙補畫。

八張示意圖：兩行帶播放鍵的句子 · 詞塊與空格 · 生詞卡加麥克風 · 選項三選一 · 句型填空後開口說 · 教學點造句 · 題目三選一 · 提示後開口說。 原尺寸開啟 ↗

C 的取捨。
① 示意圖取代 icon 圓，不是並存。 兩個都放會太重，而且縮圖本身已經是最強的辨識物。代價是失去 live 的六個顏色—— 卡片不再靠顏色區分，靠圖形。
② 同一個練法的兩張圖刻意相似。 Vocabulary Quiz 和 Question Bank Quiz 都是「題目＋三個選項、中間那個是綠的」， 差別只在選項寬度——因為它們對學生來說本來就幾乎一樣，差的是素材而不是動作。這點看得出來反而是準確的。
③ C 可以和 B 疊加。 示意圖與欄位標題不衝突，要的話可以同時有。這裡分開畫是為了讓每個提案只多一個變因。

4.1　攤平之後剛好是 4 種素材 × 2 個練法

把兩層壓平之後數出來是八個，而這八個不是散的——它們自然分成四種素材，每種素材各有兩個練法。名稱系統就建立在這個結構上：素材 + 練法。

練法 ① 練法 ② 句子 Sentence Mirroring Sentence Scramble 生詞 Vocabulary Mirroring Vocabulary Quiz 教學點 Pattern Response Pattern Building 題庫 Question Bank Quiz Question Bank QA

版面上就照這個結構排：4 欄 × 2 列，同一種素材直向成對。卡片之間沒有任何分組框線（維持方案 A 的扁平），靠欄位對齊表達同源關係。

4.2　八個名稱

新名稱素材現在叫什麼說明文字
Sentence Mirroring句子Mirroring PracticeListen and repeat each sentence
Sentence Scramble句子Sentence Scramble
（不變）		Listen, then reorder the words
Vocabulary Mirroring生詞Vocabulary → MirroringListen and repeat each word
Vocabulary Quiz生詞Vocabulary → Multiple ChoiceImage, pinyin & meaning
Pattern Response教學點Sentence Patterns → Guided ResponseAnswer questions using a pattern
Pattern Building教學點Sentence Patterns → Sentence BuildingBuild sentences from teaching points
Question Bank Quiz題庫Multiple ChoiceAuto-graded questions from a bank
Question Bank QA題庫QA PracticeOpen questions, AI assessment

幾個名稱的理由：

  • 兩個 Mirroring、兩個 Quiz 保留同名是刻意的。 它們確實是同一個練法，差別就在素材——前綴講清楚就夠，不需要發明兩個不相干的字（§3.1 的同名問題因此消失，而不是被繞開）。
  • Multiple Choice 改成 Question Bank Quiz，把 §3.2 的題庫依賴直接寫進名字裡。QA Practice 同樣加上 Question Bank 前綴——它一樣需要題庫，只是原本看不出來。
  • Sentence Patterns 這個層級消失，兩個子項目改用 Pattern 前綴，維持系統一致。
  • Sentence Scramble 是八個裡唯一不用改的——它本來就叫這個名字，而且素材正好是句子，天生就符合這套系統，跟 Sentence Mirroring 同源同色。原本第一層的 Mirroring Practice 反而要補上 Sentence 前綴才對得起來。

4.3　顏色與 icon：先貼齊 live

5.2　提案

沒有 Question Bank 的情境。頁面上方的膠囊可以切換三種情境（展示用，不是產品的一部分）。 原尺寸開啟 ↗

  • 兩種缺料都事先擋下——題庫和專案內容，不只現在的 content 一種。
  • 鎖定的卡片說明缺什麼：說明文字換成 Needs Question Bank，icon 圓轉灰，右上角加一個鎖。
  • 解鎖動線放在卡片上：Create Question Bank →，不必回頭找入口。
  • 頂部一句話交代整體狀況，沿用 live 既有的 MUI Alert 樣式與位置（hasContent 那個警告就在同一個位置）。
兩個設計判斷。
① 不用 live 的 opacity: .5 + pointerEvents: none。 那會把「怎麼解鎖」也一起壓灰、而且點不了。這裡改成卡片本體轉灰、但解鎖動線維持可讀可點—— 鎖定的目的是指路，不是單純擋住。
② 卡上的動線只在「部分鎖定」時出現。 八張全鎖時它會重複八次、又和頂部按鈕講同一件事， 所以全鎖情境只留頂部那一個入口，卡片單純說明缺什麼。

6 待決事項

§4 的兩個主要決定已經落在設計檔上。以下是還沒決定的。
  • 用 A、B 還是 C（或 B＋C）。 A 最輕；B 多一行欄位標題，把同源關係寫明；C 用縮圖直接show出學生畫面，但會放棄 live 的六個顏色、卡片也最高。
  • NEW 徽章的規則。 現在 8 張裡 4 張掛 NEW（見 §4.3）。保留幾個、掛多久。
  • Sentence Patterns 的可見性。 原本第一層那張卡在列表篩選裡是 isDahuaAdmin 才看得到、對話框卻沒擋（§3.3）。攤平成 Pattern Response / Pattern Building 之後，這兩張要不要擋。
  • Mixed Mode。 enum 裡還留著、UI 已註解掉（§3.5）。補回來變成第九張，還是連資料層一起清掉。
  • 顏色要不要改成一種素材一個顏色。 這一版先貼齊 live（見 §4.3），所以直向成對只有欄位對齊在表達，顏色沒有跟上。
  • 排序。 現在是課文 → 生詞 → 教學點 → 題庫。要不要改成依使用頻率或依難度。
