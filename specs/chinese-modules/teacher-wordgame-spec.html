Teacher — Word Game

教師端如何把 Word Game 當作目標式作業指派給班級、管理與監控各班進度、檢視遊戲關卡內容。

Chinese Modules Role: CLASS_TEACHER Status: 設計已定案（2026-08-05） Scope: 教師端 Updated: Aug 5, 2026 Prototype: Redesign v7
設計已定案（2026-08-05）。 §7 的 Q1–Q11 已全部拍板，結論整併在 §6 已決定事項；剩下的只有非設計性的待確認（telemetry 資料是否存在、內容時程、通知管道）。下一步是 engineer handoff。本文內容對齊 Redesign v7（凍結快照 versions/redesign-v7-wordgame.html）；設計真相來源為進行中的原型 teacher-wordgame-v10.html（2026-09-22：Game Content 改為真實課綱；前一版保留在 teacher-wordgame-v9.html 供對照）。

1 背景：Word Game 一分鐘

學生端的 Word Game 是自成一格的中文詞彙遊戲。教師功能要對齊的資料模型如下（現況，來自 dahua-dash WG2）：

概念現況
World（世界）共 7 個，Level 0–6 對應 HSK 0–6，名稱：渡口 / 石桥 / 龙亭 / 翠阁 / 宝塔 / 仙阁 / 天宫（各有 emoji + 主題色）
起始 World由 placement test 決定（wordGame2Level），學生從不同世界起步
Stage（關卡）每個 world 內是一條扁平有序清單（數量不固定，不是全域 54 關）。型別：TEACHING QUIZ BOSS
通關規則QUIZ 需答對 3 題（QUIZ_PASS_COUNT）；每關有 passed / unlocked / attempts / bestScore(0–5)
進度每個 world = passed / total；「下一關」= 最低的 unlocked 且未 passed
Stars（兩種，勿混淆）① 每關 bestScore 0–5（world 內加總＝遊戲內星星）
② 頭條大 badge「Stars」＝ class points（totalPoints），是另一套系統
設計決定：教師端已移除 leaderboard 與「Earn stars」目標 —— 星星是帳號層級、跨所有練習賺取，不專屬 Word Game（見 §6）。上表兩種 star 的區分仍是理解遊戲的背景。

2 問題：教師看不到、也指派不了 Word Game

  • 無法指派 —— 沒有把 Word Game 當作業派給班級的入口，無法設定可衡量的目標與截止日。
  • 看不到進度 —— 不知道班上誰玩到哪個世界、卡在哪、通關狀況。
  • 看不到內容 —— 無法逐關檢視遊戲實際教什麼、考什麼，也不知道全班在某一關的通關率。

本 spec 提出一個 Practice ▸ Word Game 頁面來解決以上三點。

3 設計理念

一句話定位：把老師端的 Word Game 從「看遊戲內容」重新定位為以到期日為軸心的班級進度指揮台 —— 打開頁面第一眼看到的不是關卡地圖，而是「哪個班、什麼目標、快到期了、多少人達標」。

3.1 · 三個核心原則

① 緊迫感優先（Due-date-centric）

左欄作業列表以作業期間 Start – Due 領頭（v7 起顯示整段期間，非單一到期日），並用一致的顏色語言貫穿整列：逾期／今天 紅 快到期 琥珀 之後 灰。Reached（X / total）數字的顏色跟著日期跑 —— 顏色本身就是緊迫程度，掃一眼就知道先追誰；全員達標則跳出綠色「All complete」作為正向終點。

② 對齊即資訊（Structure as information）

三張表（作業列表、展開的落後名單、學生名冊）共用同一套 5 欄 grid，Level·Stage 合併成與 Goal 同寬、膠囊統一尺寸。視覺上的「對齊」不是美觀，而是讓老師用同一個心智模型橫跨不同表讀資料。

③ 克制、跟隨系統（Restraint）

沿用 dashboard 設計系統（Plus Jakarta Sans + emerald 綠、同組卡片圓角／陰影）。全頁英文、拿掉奇幻世界名詞（渡口…）改用 Level N + 教學內容名；拿掉 leaderboard／星星（帳號層級、不專屬 Word Game），避免功能混淆。

一句總結

用顏色傳達緊迫、用對齊傳達關係、用克制跟隨既有系統 —— 讓老師在一屏內完成「誰快遲交、誰還沒達標、要不要指派新的」判斷。

3.2 · 關鍵取捨

決策理由
「Behind 落後數」→「Reached 達標數」正向框架；老師更關心「還差誰達標」而非「有多少人落後」。
學生名冊改成班級複選下拉（與 Assign 對話框同結構）元件複用、心智一致；預設不選、按需展開，面板保持精簡不爆長。
下拉在面板內行內展開（非浮層）卡片 overflow:hidden 會裁切浮層，行內展開更穩健、不被裁切。
作業＝跨班到期列表；學生名冊獨立把兩個問題分開：「班級層級的到期管理」vs「個別學生的位置」。v7 起拆成兩個獨立面板（Word Game Assignments / Student Levels），各有標題與自己的控制項。
日期改用日曆區間選擇器（取代兩個日期輸入框）v7「一班同一時間只有一個作業」這條規則要能被看見：日曆把該班已被占用的日子直接畫成不可選，老師是「挑一段空檔」，而不是填完日期才被系統退件。
編輯／刪除收進 Manage 面板v7主面板專心呈現「現在怎麼樣」；管理動作（改目標／改期間／移除）集中在一個明確入口，避免每列都掛一排小按鈕。
Level 2–6 標為 Coming soonv7真實內容只有 L0 / L1 齊備。與其展示程序生成的假關卡讓老師誤以為可用，不如誠實鎖住並標示狀態。
移除關卡頁 Insights 三榜v7三個指標全部依賴尚不存在的 telemetry，留在頁面上等同承諾一個做不到的功能；待後端有資料再議。

4 提案頁面：Practice ▸ Word Game

導覽位置：側邊欄 Practice ▸ Word Game。頁面為兩欄（左欄自 v7 起為兩個堆疊面板：Word Game Assignments + Student Levels），頂部一顆 Assign Word Game 按鈕。

┌─ Topbar ───────────────────────── [ + Assign Word Game ] ─┐ LEFT ① panel — Word Game Assignments [ N assignments ] [ ⚙ Manage ] • 跨班、依到期日排序 Dates（Start – Due）· 班徽 · Goal · Reached X / total （數字顏色跟著到期日；全員達標 = All complete） ▸ 展開一列 = 未達標學生名單 （min/day 目標 → 本週缺幾天） LEFT ② panel — Student Levels • 班級複選下拉（含 All students）+ 排序鈕 • 名冊：Student · Class · Level · Stage · Content（目前關卡名） RIGHT panel — Game Content [ 7 worlds ] • 7 個 world 列：Level N · 教學內容名 · HSK N · M stages（綠→紅） • Level 0 / 1 → 可點進關卡頁（搜尋 / 型別 filter / 分頁 12 關） • Level 2–6 → 🔒 Coming soon（不可點） └──────────────────────────────────────────────────────────┘

4.1 · 指派流程（Assign Word Game）

點 Assign Word Game 開啟對話框：

欄位內容
Assign to班級複選下拉（勾選 4A / 3B / 5C / 6A，含人數）。下方常駐一條規則說明：One assignment per class per time period。
When v7可收合的日曆區間選擇器（取代原本的 Start / Due 輸入框）：觸發鈕顯示 Start / End 兩格，展開為並排兩個月的月曆（可前後翻月）。點第一下設起日、第二下設迄日。
· 未選班級前整個日曆是 disabled —— 要先知道是哪幾班，才知道哪些日子被占用。
· 被選班級已有作業的日期畫成不可選；若圈選的區間中間跨過已占用的日子，直接拒絕並提示「That range overlaps a booked period」。
Goal Type三型：Complete N stages（做幾關）、Reach a level / stage（大關 Level + 可選具體小關 Stage）、Play a set time each day（每天玩幾分鐘；快速預設 10 / 15 / 20 / 30 + 自訂）。已移除 Earn stars
Days（僅 min/day 目標）v7分鐘目標多一組星期選擇：預設鈕 Every day / Weekdays / Weekend，下方 7 個星期 chip 可自由勾選（自訂組合，至少一天）。所選天數 = 該週應達成天數（reqDays），寫進作業並用於「本週缺幾天」的判定。

指派一律是目標式（已移除「Just play」純遊玩模式，見 §6）。送出後 toast 確認。已指派的 Word Game（含 Play min/day）會同步出現在 Dashboard ▸ Active Assignments。

一班一期間（v7 新規則）。 同一個班在同一段時間只會有一個 Word Game 作業；要再派下一個，就往後排一段沒被占用的期間。這條規則由日曆的「不可選日期」在輸入當下就執行，而不是送出後才報錯。規則本身待業務確認（見 §7 Q5）。

編輯與刪除：Manage 面板 v7

Word Game Assignments 面板標題右側有一顆 Manage 按鈕，開啟 Manage Assignments 對話框：每個進行中的作業一張卡片，顯示班級 · 期間 + 天數（如 Jul 24 – Jul 29 · 6d），以及三顆膠囊 目標型別 / 目標值 / N students。每張卡片兩個動作：

  • Edit —— 關閉此框、開回 Assign 對話框並預填該作業（標題變成 Edit assignment），送出後就地更新該筆而非新增。日曆的占用檢查會排除作業自己，所以原本的期間仍可選。
  • Delete —— 移除該作業，主面板列表與標題計數即時更新。

刻意不放「New」（新增一律走頁面上方的主按鈕，維持單一入口）與「End early」（提早結束是否要成為獨立行為未定，見 §7 Q8）。編輯與刪除都直接作用在目前的作業資料上，沒有另一份草稿狀態。

4.2 · 左欄：兩個面板 v7

v7 把原本擠在一個面板裡的兩件事拆開，各自成為一個有標題的面板。

① Word Game Assignments 標題列：N assignments · Manage

以到期日為軸心的跨班作業清單（非一次一班），表頭四欄 Dates · Class · Goal · Reached：

  1. 每條作業一列 —— Start – Due 期間（依急迫上色：逾期 / 今天紅、快到期琥珀、之後灰）· 班徽 · Goal（Reach Level N · 內容名 / Complete N stages / Play N min / day · 天數）· Reached X / total（達標人數；數字顏色跟著到期日跑，全員達標顯示綠色「All complete」）。
  2. 展開一列 → 未達標學生名單：Reach / Complete 目標顯示 Student · Level · Stage · To goal（還差幾關）；Play min/day 目標改為本週缺勤追蹤（見下）。全員達標顯示「Everyone reached this goal」。
  3. Manage 按鈕 → 編輯 / 刪除作業（見 §4.1）。
min/day 目標的展開視圖改版（v7）。 v6 顯示「今天玩幾分 vs 目標」；v7 改成以週為單位：標頭 This week · 週區間 · Goal N days，每列 Student · 缺 N days（把「該做幾天」與「缺幾天」對起來，而不是只看今天）。週區間由作業到期日所在的那一週推算，並依 Days 設定（每天 / 平日 / 週末）縮到對應的起訖。「哪一週」的定義待確認（見 §7 Q10）。

② Student Levels

獨立面板，頂部一個班級複選下拉（與 Assign 對話框同結構，另含一個 All students 全選項與人數）＋一顆排序切換鈕（進度 低→高 / 高→低）。預設不選任何班級，顯示提示文字。

選定後列出名冊，四欄：Student / Class / Level · Stage（合併成一欄）/ Content —— 其中 Content 是該生目前所在關卡的名稱（不只給數字，直接告訴老師他卡在教什麼）。

定位：看班級進度與到期，不是排行榜。 老師掃一眼顏色就知道哪條快遲交、誰還沒達標要追。已移除 leaderboard、星星、以及曾試做的 Class progress 分布（見 §6）。

4.3 · 右欄：Game Content

7 個 world 列，每列：Level N + 教學內容名（如 Pinyin & Tone Challenge / Vocabulary）+ HSK N · M stages（依等級綠→紅上色）。

Level 2–6 目前鎖住（v7）。 只有 Level 0 / 1 可點進關卡頁；Level 2 以上顯示 🔒 Coming soon 且不可點 —— 這兩級以外的關卡內容尚未齊備（原型為程序生成）。內容備妥後逐級解鎖。指派對話框的 Level 下拉目前仍列出 0–6，是否要跟著鎖見 §7 Q11。

點可用的世界 → 進到獨立的「關卡頁」（非彈窗）：

  • 搜尋框：依標題或詞 / 拼音即時篩。
  • 型別 filter：All / Teaching / Quiz / Boss（帶即時數量）。
  • 分頁：每頁 12 關，底部 1–12 of N + 頁碼。
  • 關卡卡片：關號 + 型別 + 標題 + 詞 / 題數；TEACHING 顯示詞卡（漢字 / 拼音）、QUIZ / BOSS 顯示題目列。
教師只檢視、不編輯遊戲內容（內容於他處建立）。此欄用途是「派作業前先看懂遊戲在教什麼、考什麼」。

Insights 三榜：v7 已移除 v6 有 / v7 無

v6 的關卡頁上方有一個可收合的 Insights 面板（Most time spent / Hardest quizzes / Most drop-offs 三個並列排行榜）。v7 整個拿掉：三個指標都需要後端 telemetry（平均停留時間、平均通關嘗試、離開 / 放棄事件），目前一律是假資料，放在頁面上等於承諾一個還做不到的功能。待 telemetry 具備後再重新提案。

4.4 · 連帶調整：Students 頁 v7

同一版一併調整了 Teacher ▸ Students（與 Word Game 共用同一組進度資料）：

  • 學生詳情的區塊更名為 「Word Game and Achievement」（Level / Stage / Stars 三格 + 成就）。
  • 移除 Manage 按鈕、HSK 等級篩選、單一學生的編輯 —— 這頁回到「查看」定位，指派與管理一律在 Word Game 頁做。保留搜尋與 All classes 篩選。

舊版（含 Manage + HSK 篩選）保存在 versions/redesign-v0-students.html。

5 現況：真 vs placeholder

原型為凸顯互動而用假資料，討論時請區分：

項目狀態
兩欄版面（左欄兩面板）、指派對話框 + 日曆區間、Manage 編輯 / 刪除、關卡頁（搜尋 / filter / 分頁）設計已定
「誰未達標」判定（reach level / complete N stages 對每生 world+進度即時計算）真實推算
World 0 關卡結構（母音對 + 聲調組）對齊真實 hsk0
World 1–6 的關卡、BOSS 關程序生成假關卡

各班名冊、作業（目標 / 到期）假資料
日曆的「已占用日期」（由現有作業的期間推得，含編輯時排除自己）真實推算
Level 2–6 鎖住 Coming soon（內容尚未齊備）內容待補
Insights 三榜指標（time / attempts / drop-off）v7 已移除
Play min/day 的「本週達成幾天 / 缺幾天」與達標判定假資料（待每日時長 API）

6 已決定事項

暫定基準，除非明確推翻。

  1. 指派一律目標式：移除「Just play」純遊玩模式。
  2. 目標三型：Complete N stages（做幾關）/ Reach a level · stage（大關 Level + 可選具體小關 Stage）/ Play a set time each day（每天玩幾分鐘；預設 10 / 15 / 20 / 30 + 自訂）。已移除 Earn stars 目標。
  3. 達標＝布林，不算百分比（2026-08-05 拍板）：Reach Level N 的達標定義就是該生 world ≥ N（選到具體 Stage K 時為 world > N，或 world = N 且 done ≥ K）。沒有「單一進度 %」這個概念，UI 不畫個人進度條，API 只回 reached: Boolean；班級層級才有 Reached X / total。
  4. Reach 是絕對、Complete 是相對（2026-08-05 拍板）：Reach a level / stage 為絕對目標（到達該等級即可，已在更高等級的學生視為已達標）；Complete N stages 為相對目標 —— 從指派當下起再清 N 關。
    ⚠️ 因此後端必須在指派成立時，對班上每位學生存一份 baseline（當時已清關數）；達標 = 目前已清關數 − baseline ≥ N。指派後才加入班級的學生，於加入當下補記 baseline。
  5. 移除 leaderboard 與星星：星星（totalPoints）是帳號層級、跨所有練習賺取，不專屬 Word Game，應放獨立 Leaderboard 頁。此頁左欄＝班級進度，非排行。
  6. 左欄＝兩個面板（v7）：①Word Game Assignments —— 跨班、依到期日排序，每條顯示 Start – Due 期間與 Reached X / total（數字跟到期日上色、全員達標 All complete），展開列出未達標學生；②Student Levels —— 班級複選下拉（含 All students）+ 可排序名冊，欄位到 Content（目前關卡名）。（取代早期的班級切換條 / by-class 卡片 / leaderboard / Class progress 分布。）
  7. min/day 目標以「週」結算（v7 + 2026-08-05 補完）：指派時選 Days（每天 / 平日 / 週末 / 自訂），展開列顯示 This week · 區間 · Goal N days 與每生缺幾天（v6 的「今天差幾分」作廢）。
    · 逐週結算，週一為一週之始（Mon–Sun）：作業橫跨幾週，每一週都要達成所選天數。
    · 單日達成 = 當天累計滿 N 分鐘（可分次累加），不需單次連續、不允許隔天補玩。
    · 一天的界線以班級所在時區的自然日為準。
  8. 一班同一時間只有一個作業（v7，2026-08-05 確認為硬規則）：日期改用日曆區間選擇器，被選班級已占用的日子不可選、跨越占用的區間直接拒絕；未選班級前日曆不可用。期間可以相鄰（前一個結束日的隔天即可開始）；日曆只開放今天之後，故已結束的作業不影響選日。後端必須同步驗證，不能只靠 UI 擋。
  9. 作業可編輯 / 刪除，入口為 Manage 面板（v7）：卡片式清單 + Edit（預填 Assign 對話框、就地更新）/ Delete。不做「New」（走主按鈕）與「End early」（2026-08-05 拍板：要提早結束就用 Edit 把 End date 改到今天，不另立狀態）。刪除為軟刪 —— 標記 deleted、畫面不再顯示、日曆不再占用，但資料保留供日後回顧與誤刪查覆。改目標值後直接以新目標重算達標，Phase 1 不保留修改紀錄。
  10. Level 2–6 暫時鎖住（v7）：右欄顯示 🔒 Coming soon 不可點，只有 L0 / L1 可進關卡頁，直到內容齊備。指派對話框的 Level 下拉一併鎖住，只能選 L0 / L1（2026-08-05 拍板）—— 不允許指派到尚未開放的等級。內容備妥後逐級解鎖。
  11. 關卡內容 = 獨立關卡頁：點世界進到全頁（搜尋 / 型別 filter / 每頁 12 關），非彈窗、非釘選 viewer。關卡扁平（不做 unit 分組）。
  12. 等級語言：綠→紅（Level 0 綠 … Level 6 紅），用於 HSK · stages 文字色與班級進度視覺。世界用 Level N + 教學內容名顯示（不再用渡口 / 石桥等遊戲名）。
  13. 關卡頁不放 Insights（v7 移除 v6 的三個排行榜）：Most time spent / Hardest quizzes / Most drop-offs 全都依賴尚不存在的 telemetry，等後端有資料再重新提案。
  14. 可提醒未達標學生（2026-08-05 拍板）：作業展開的未達標名單可直接發提醒，比照 Dashboard「提醒未繳交」的既有通知機制與文案結構（沿用同一套通知管道，不另做一套）。
  15. 不做單一學生的世界別細節（2026-08-05 拍板）：教師要看個別學生，走 Students 頁的「Word Game and Achievement」。Word Game 頁維持班級層級，避免兩頁功能重疊。
  16. 時間型目標進 Dashboard：Word Game 作業（含 Play min/day）出現在 Dashboard ▸ Active Assignments（Word Game 標籤 + done/total 達標框架）。

7 決策紀錄（Q1–Q11 已全數拍板）

2026-08-05 決策會結論。 原本的 11 題全部有答案，細節已整併進 §6。本節保留每題的問題與結論，供日後回溯「為什麼是這樣」。真正還沒閉合的只有下方三項非設計性確認。

Q1 已決定 目標語意

採 v5 定義：Reach a level / stage（選 Level 大關 + 可選具體 Stage 小關）與 Complete N stages（清關數）。早先「Reach stage 20」跨世界編號的歧義不再存在。

Q2 已決定 目標「完成」如何判定？

Reach Level N 的達標定義 = 該生 world ≥ N（若指定到 Stage K，則 world > N 或 world = N 且 done ≥ K）。
「Earn N stars」目標與「單一進度 %」都已不存在 —— 個人層級只有達標 / 未達標兩態，班級層級才有 Reached X / total。

Q3 已決定 目標要「絕對」還是「相對於起點」？

兩種目標各走一邊：

  • Reach a level / stage = 絕對。已在更高等級的學生視為已達標（這是刻意的：此目標用來確保「全班至少到某個水準」）。
  • Complete N stages = 相對於指派當下。用來確保「每個人都要再往前推進」，不因起點高低而失效。

後端影響：指派成立時要對班上每位學生存一份 baseline（當時已清關數），達標 = 目前已清關數 − baseline ≥ N；指派後才入班的學生於入班當下補記 baseline。

Q4 已解決 右欄 cohort 統計

原設計右欄關卡會顯示全校通關 cohort + 星等分布。v5 已移除：右欄回歸純「檢視遊戲內容」，班級進度改由左欄的 per-assignment 落後名單負責。若日後仍想在關卡層級看班況，再另議。

Q5 已決定 一個班可否有多個並存的作業？

不可以 —— 一班同一時間只有一個 Word Game 作業，這是硬規則。日曆把該班已占用的日期畫成不可選、跨越占用的區間直接拒絕，後端也必須驗證。期間可以相鄰（前一個結束日的隔天即可開始）；日曆只開放今天之後，故已結束的作業不影響選日。

Q6 已解決 星星該用哪一種？

此頁的 leaderboard 與「Earn stars」目標已整個移除（星星是帳號層級、跨所有練習賺取，不專屬 Word Game）。故不再需要在此頁選 star 定義。若之後要做全站 Leaderboard 頁，再於該頁決定 bestScore 加總 vs totalPoints。

Q7 已決定 是否支援「催未達標學生」？

要做。 作業展開的未達標名單可直接發提醒，比照 Dashboard 的「提醒未繳交」：沿用同一套通知管道與文案結構，不另做一套。原型尚未畫此按鈕

Q8 已決定 作業可否編輯 / 刪除 / 提早結束？

  • 編輯、刪除：可以，入口為 Manage 面板。
  • 提早結束：不做獨立行為 —— 用 Edit 把 End date 改到今天即可，不另立狀態欄位（也讓日曆占用邏輯自然一致）。
  • 刪除為軟刪：標記 deleted、畫面不顯示、日曆不占用，資料保留供回顧與誤刪查覆。
  • 改目標值：直接以新目標重算達標，Phase 1 不保留修改紀錄。

Q9 已決定 教師是否需要看單一學生的世界別細節？

不做。 要看個別學生走 Students 頁的「Word Game and Achievement」；Word Game 頁維持班級層級，避免兩頁功能重疊。

Q10 已決定 Play min/day 的結算定義

  • 逐週結算，週一為一週之始（Mon–Sun）：作業橫跨幾週，每一週都要達成所選天數。
  • 單日達成 = 當天累計滿 N 分鐘，可分次累加；不要求單次連續、不允許隔天補玩。
  • 一天的界線以班級所在時區的自然日為準。

資料來源仍待後端確認（見下方待確認 ①）。

Q11 已決定 Level 2–6 鎖住期間的行為

指派對話框的 Level 下拉一併鎖住，只能選 L0 / L1 —— 不允許指派到尚未開放的等級。右欄維持 🔒 Coming soon。內容備妥後逐級解鎖。原型的下拉目前仍列出 0–6

尚待確認（非設計決策）

  1. 每日遊玩時長的資料是否存在？ Play min/day 需要「每生每日 Word Game 遊玩分鐘數」。這是目前完全沒有的 telemetry，需後端評估新增成本 —— 這一項的答案決定 Phase 2 的時程。
  2. Level 2–6 的內容時程：由誰、依什麼條件判定「某一級內容齊備」？解鎖節奏與學生端是否必須一致？
  3. 提醒的通知管道：確認 Word Game 作業可直接掛在 Dashboard 現有的「提醒未繳交」通知機制上（管道、頻率限制、文案模板）。

原型待修正（依本次決策）

下列是 v7 / v8 原型與決策不一致之處，交接前要先改掉，否則工程師會照著錯的實作：
  1. Complete N stages 目前用跨世界累計前綴和（絕對值）算 To goal → 應改為相對 baseline。
  2. Assign 對話框的 Level 下拉仍可選 L2–L6 → 應只留 L0 / L1。
  3. 未達標名單沒有提醒按鈕 → 需補上（比照 Dashboard）。
  4. min/day 展開只呈現到期日那一週 → 應為逐週（Mon–Sun）結算。

8 Out of scope / 假設

  • 不含學生遊戲玩法、關卡設計、計分演算法的變更 —— 以現況 WG2 為準。
  • 不含內容編輯（教師只檢視關卡）。
  • 假設 world/stage/bestScore/placement 等資料可經 API（getWordGame2StageMap 等）取得；教師端 cohort 需能對一整班/多班批次查詢每生進度（API 能力待確認）。
