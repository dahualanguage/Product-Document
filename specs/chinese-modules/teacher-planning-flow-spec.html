Planning — 設計 flow

Planning 要在同一條對話裡容納八張卡、兩條路徑與各自的設定。這份文件把設計工作切成五步，備齊其中三步的素材，並用四個分頁記錄已完成的四張卡各自長成什麼樣、以及它們是從產品原本的哪幾步改過來的。

1 設計 flow 五步

#步驟狀態內容
1確定對話 完成 對話只問五件事：端點 → 從哪來 → 哪一個 → 課文對嗎 → 設定好了嗎。 分工是面板放東西本身，對話放決定。
2Todo list 未開始 一次勾選兩項以上的練習時，列出每一項還沒完成的設定。 它的內容就是 §2 步驟表的投影——一個練習未完成的事，就是它在步驟表上還沒走完的步驟。
3各練習的設定面板 4 / 5 Mirroring · Sentence Scramble · Vocabulary（Cards 與 Quiz 共用前兩步）已完成， 長成什麼樣寫在 §6。 剩下一張：Open-ended Questions 與 Sentence Response/Building—— 後兩張卡共用同一份設定，所以是一張不是兩張，理由見 §3。
4Assign 面板 未開始 目前仍是「班級 / 開始 / 到期 / 必修 / 學生」五則對話訊息， 也就是第 1 步在設定那段已經廢掉的形狀。不依賴任何一張練習面板，可以先做。
2026-09-03 修好的是接不接得到：原本 tail() 不管有沒有練習一律走 confirm， 從來沒接上這五則，doneBody() 寫好的「assigned to N in 班級」永遠是空的。 現在 confirm 兩種 run 都會經過，按鈕依 hasPractice() 顯示 Continue 或 Create。 五則訊息的形狀本身還是沒改。
5走過 20 種情境 部分 10 個端點 × 兩條路（既有 Project / 新建 Project）。 這是驗證不是設計，而且該拆成兩半：漏斗路徑機械式跑過，設定的部分每畫完一張面板就驗那幾格。
已經機械式跑過的（headless 驅動真實 DOM，不是讀程式碼）： Mirroring、Sentence Scramble、Vocabulary Cards、Vocabulary Quiz 的三條分支， 各自從端點一路走到 Assign 完成，含學生走查覆蓋層。 沒跑過的：新建 Project 那條路、QA、Comprehension Quiz。
Assign 是八張卡唯一都要走的一步。 §2 的步驟表裡，其他每一步都只屬於某幾張卡，只有 Assign Practice 八張都有—— 而它正是還沒設計的那一段。這是第 4 步值得插隊的理由。

① Comprehension Quiz 整欄是空的

它沒有任何設定。mc-step-two-section.js 是一份題目清單—— 型別與分類的 chip、逐題刪除、一顆 Edit in Question Bank。 它那一步在步驟表裡就叫 Edit & Preview，不叫 Settings，名字本來就講了。

所以設計 flow 第 3 步總共是五張面板，不是八張。 八張卡 → 六份設定（Response 與 Building 共用一份）→ 扣掉沒有設定的 Comprehension Quiz → 五張：Content Mirroring · Open-ended Questions · Vocabulary · Sentence Scramble · Sentence Response/Building。
Mirroring · Sentence Scramble · Vocabulary 已完成（§6）， 還剩一張：Open-ended Questions 與 Sentence Response/Building 共用的那一份。

② 「一張面板、列隨練習出現」有程式碼支撐

整張表是由三個共用元件撐起來的，產品自己就是這樣組的：

各自獨有的只有三個：Mirroring 的 English first、Vocabulary 的 Image、Open-ended Questions 的 Guide phrase language。

③ 三個不一致是產品自己的，不是設計的

  • Audio Mode：Mirroring 和 Open-ended Questions 用共用卡， Sentence Response/Building 自己畫了一份一樣的。
  • Auto pass 次數：同一個東西有三個名字—— Max attempts before auto pass（共用元件）、 Attempts per sentence（Scramble 自己畫）、 Attempts per question（Follow Pattern 自己畫）。
  • Practice name：六份裡四份有，Sentence Response/Building 和 Comprehension Quiz 沒有。
面板要不要統一這三個是設計決定，但要知道統一之後會跟現行畫面長得不一樣。

5 面板的共同規則

四張面板都畫完了（§6）。這一節留下的是四張都成立的規則—— 哪一張長什麼樣、為什麼，寫在各自的分頁裡。

5.1　分工：面板放東西本身，對話放決定

面板寬 480px，標題固定是 What students will do， 副標寫這是哪一個練習、用哪一份素材。

把設定搬進面板之後，對話從 17 則壓到 5 則： 端點 → 從哪來 → 哪一個 → 課文對嗎 → 設定好了嗎。 砍掉的是七題設定、句子那一步、學生預覽，以及「Need any changes → Yes 再進另一個畫面」那個轉場。 每一則被砍的理由都一樣：東西搬進面板之後，那則訊息只剩「你看到了嗎」的功能。

反過來也成立：是決定的就一定要回到對話問。 Vocabulary 的「要不要加字」、Scramble 的「要不要再生成句子」、Quiz 的「題數 / 怎麼出 / 必考哪幾種」， 面板上都有現成的空間可以直接擺，但它們是決定，所以都由對話問， 答了之後面板才長出對應的東西。

5.2　編輯與設定是兩步，不能合併

工程端對句子提出的要求：換順序 / 斷句 / 刪除必須是自己的一步， 不能跟設定合在同一個畫面。後來發現這條對每一種練習都成立—— 能改的那一步只有一個，之後一律唯讀。

練習能改的那一步之後（設定 / Review / 走查）
Content Mirroringmaterial 句子列同一份句子列，唯讀
Vocabulary Mirroringvoclist 字卡（挑圖 / 刪除）同一份字卡，唯讀
Vocabulary Quizvocqlist 題目（排序 / 刪除）同一份題目，唯讀
Sentence Scramblescrsent 句子同一份句子，唯讀

四張都用同一個 render 函式畫那份東西，只有「能改的那一步」傳 editable=true——兩邊因此不可能走樣。

5.3　兩條不能破壞的規則

  • 面板上的每一次修改仍然記一個復原點（mark(); keep();），所以 Back 退得回來； 但不再往對話寫 Q&A——對話已經不問設定了，寫進去只是雜訊。
    例外是純粹的顯示切換（例如把某個 Project 的課文字表折起來）：那不是編輯， 刻意不記復原點，Back 不該把「打開／收起」當成一步退回去。
  • 每一項設定有一顆 ?。點下去把「What is auto pass?」＋白話解釋寫進對話， 然後 tail() 把還沒答的那一題重貼到底部。對話的角色是解釋，不是逐題問。

5.4　面板什麼時候開

prevMode = 'auto' // 走到面板步驟自動開、離開自動關 // 老師一碰 pagebar 的 toggle 就釘住，直到下一個 plan PANEL_STEPS = 每一種練習自己的內容步驟與設定步驟 + 'confirm'

5.5　一張面板，列隨練習增減

  • 分組原則照搬：看得到的貼在學生畫面上、聽得到的收成一組、過關單獨一行。 哪幾列出現由 §3 的表決定。
  • 沒有 Audio Mode 的兩張（Vocabulary、Sentence Scramble）最上面那張卡不畫。
  • Comprehension Quiz 沒有面板（§3 ①）；Vocabulary Quiz 也沒有設定步驟。
  • Vocabulary 的 Image 那一列是特例——它目前對學生沒有作用（§8 已解決 ②）， 但它對老師有作用：挑不挑圖決定 Quiz 能不能出 Image 題（§6 · Vocabulary Quiz）。

6 四張卡的細節

四張已經畫完的卡，一張一個分頁。每一頁的第一件事都是 產品原本的步驟 → Planning 的步驟——Planning 不是把產品的步驟搬過來， 而是照「決定內容 → 檢查產出 → 設定 → Review」重切，所以哪一步被拆開、哪一步消失了， 是這四頁最該講清楚的事。

四張共用的東西不重抄： 面板的共同規則見 §5； Review 兩段預覽、進度條、mock 資料規則見本節最後的 6.5 四張共用。

Audio Mode 的連動——照真實產品

  • 打開會強制把拼音與翻譯寫成 STUDENT_CHOICE 並鎖住 （mirroring-step-two-section.js · handleAudioMode）。
  • 面板上要看得出被鎖住——變灰＋一句原因，而不是安靜地被改掉。
  • 學生畫面同時換成 Audio Mode 卡：耳機圖、Audio Mode is ON、 Please pay attention and repeat the sentences.， 底下一塊提示 Need help? Check the settings for text options. （assignments/content/index.js:488–546，見 §8 已解決 ①）。 拼音預設是關的，學生在練習當中自己叫回來——不是事先由老師決定。

設定的列

Audio Mode · Pinyin · Translation · English first · Speed · Voice · Auto pass（1–10，預設 3）。 值與共用元件見 §4。

產出與 Review

  • Review 顯示整篇句子列，唯讀，每句一顆播放鍵。
  • 走查的單位是句：Question N of 14。
  • 走查會套用設定：拼音關掉就只剩漢字、翻譯關掉就不顯示。（以前不會，是修過的。）

規則與邊界

  • 句子只能在 material 改；設定與 Review 都是同一份句子的唯讀版（§5.2）。
  • 斷句只在逗號處提供，選字介面 splitPicker 只活在 material。
  • 課文是 14 句（mock 資料，見 6.5）。

與真實產品的差異

  • 刻意不同 產品的 Settings & Preview 是一步，Planning 拆成兩步。
  • 簡化 產品的 Test 會把老師帶去真實學生頁；Planning 沒有後端，用兩段式預覽代替（6.5）。

面板：第一步——一個 Project 一塊

Project name ← 這一行本身就是這一塊的 select-all，右邊是 已選/總數 Teaching points ← 預設全勾，老師做的是減法 ── ADD WORDS ── ← 只有在對話答了 Yes 之後才出現 From Project ← 這個 Project 的整篇課文，可折疊 Custom word ← 打字

第一步，且已經回答「Yes, add words」——ADD WORDS 以下兩段才出現。原尺寸開啟 ↗

  • 兩條加字路都掛在某個 Project 底下，這是有語意的。 在「数字」那一塊打字加的 钱，就拿数字的 HSK 等級、去数字的課文找例句； 掛在家人那塊的 猫 就找家人的。全域一個輸入框做不到——它只能 fallback 到主 Project。
  • From Project 撈的是整篇課文，對應真實 add-vocab-dialog.js 的 splitArticleArray。已經在字集裡的字變灰但不消失， 照真實 dialog 的 Available / Already Added 兩態——藏起來的話，老師看不出這篇課文已經吃進去多少。
  • 同一個字出現在兩個 Project 的課文裡，兩塊都列，不去重： 區塊宣稱的是「這個 Project 的課文有什麼」，去重會讓那句話變成謊話。
  • 加進來的字回到自己 Project 的教學點旁邊，掛 Added 標籤（它不是教學點）。 取消勾選不會讓它消失——S.voc.added 與 S.voc.points 分開存。

Review 與 Preview as a student

真實產品沒有「Review」，它有的是 Test——直接把老師帶去學生實際做題的真實頁面 （/dashboard/assignments/content/?sk=…&type=…）。Planning 沒有後端開不了那個頁面， 做了一個對應的兩段式簡化版：

  • Stage 1（confirm 自動顯示）：面板換成這次 run 真的產出的全部內容，唯讀。 renderConfirmPreview() 判斷這個 run 有沒有 Vocabulary，沒有就退回句子列樣式， 兩邊共用一份邏輯。
  • Stage 2（點 Preview as a student）：蓋滿整個畫面的走查 （#spOverlay，不是 480px 面板），Prev / Next 換題，照真實學生介面畫， 但只是走查，不是真的能作答。
  • 按鈕在面板最上面，四張卡共用同一個 studentPreviewBtn()—— 放在內容後面的話，得先捲過 84 題才找得到入口。
  • 走查會套用老師剛設好的顯示設定（曾經不會，是修過的）。 學生視角共用一個 vocShow()；Mirroring 的走查同樣修過。 唯一不跟設定走的是 Review 的唯讀清單——那是老師檢查「我做出了什麼」的清單。

進度條

  • flowStepsFor(ep) 算出這個 run 會走的完整 step-kind 陣列， 邏輯刻意跟 tail() 的 dispatch 順序完全對應——這是唯一的正確性保證。 tail() 以後改動，這裡要跟著改。
  • 只在「從既有 Project 建立」時顯示；從零開始寫內容那條路沒碰。
  • Vocabulary Quiz 是第一個會分支的流程，總數隨答案長出來： Use all = 10 步、改題數 + Random = 11 步、改題數 + 必考 = 12 步。

Mock 資料的規則

誠實留白，絕不編造。查得到就用真的（真拼音、真翻譯、課文裡真的含這個字的句子）， 查不到就留白並說明，不拿第一句重複湊數、也不編一句出來。 這條規則同時管 vocEntryFor()、scrSentenceFor() 與 MC 題目生成。
  • 三個 Project 的課文都加長了（食物 6→14 句、家人 6→12、数字 6→12）， 因為 From Project 撈的是整篇課文——6 句的課文撈不出像樣的詞池。 連帶 Content Mirroring 也變成 14 句，這是同一篇課文，本來就該一致。
  • GLOSS 表補了課文裡有、但不在該主題 cards 的字（共 43 條）。 不然從課文加 我 進來會是空翻譯。
  • 圖片沒有真實資產，面板上一律是示意方框；但選圖的互動是真的， 因為它會決定 Quiz 能不能出 Image 題。

已解決 ③ — Open-ended Questions 的 guidePhraseLanguage 是什麼

它是學生在 QA 開始頁上會聽到的四句引導語，每一句有中文、英文和一個音檔 （content/qa/components/StartPracticeButton.js:12）：

请你跟我这样说 Please say it like this 请你这样说说看 Try saying it like this 请回答以下问题 Please answer the following question 说得很好！下一题 Well said! Next question

這份 checkout 裡它跟著 targetLanguage 走（zh-CN / zh-TW 兩套）， QA 的設定步驟（qa-step-two-section.js：Practice name / Audio Mode / Pinyin / Speed / Voice） 裡沒有這個下拉。所以要問工程的只剩「新版有沒有把它變成老師可選的」。

先去程式碼裡找，找不到再問。 原本掛在這裡的第 1 題是被程式碼回答掉的，不是被工程回答掉的—— 它掛了五天，而答案一直在 assignments/content/ 裡。 三題查完的結果都不一樣：一題拿到答案（純聽力），一題發現設定根本沒接上（Image）， 一題發現問題本身要改寫（引導語不是「是什麼」而是「有沒有變成設定」）—— 後者反而問出了更值得問的問題。程式碼答不了的只有「未來會怎樣」和「這是不是有意的」， 其餘先自己查。要問就六題一次問完，不要分散到各張面板。
