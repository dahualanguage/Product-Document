Submit & Redo Attempt Flow提交與重做流程

How a student practice becomes an attempt, how attempts are redone, and how a result gets submitted to the teacher.學生一次練習如何變成一次 attempt、如何重做（redo）、以及結果如何提交（submit）給老師。

1 Concepts概念

Attempt and submit are two different things:Attempt（練習一次）和 submit（提交）是兩件不同的事：

Term名詞Meaning意思
AttemptAttempt（一次練習）One run at a practice. Each run is stored with its own score, date and completion state. Practising again = a new attempt.對一份練習做一次。每一次都會存成獨立一筆，含自己的分數、日期與完成狀態。再練一次 = 新的一次 attempt。
Redo / new attemptRedo / 新的一次Starting a fresh attempt on the same assignment. Increases attemptCount.對同一份作業重新開始一次。attemptCount 會 +1。
SubmitSubmit（提交）A separate, deliberate action that sends the result to the teacher. Per-assignment, not per-attempt.另一個明確的動作：把結果送給老師。以「作業」為單位，不是每一次 attempt。
Best / LastBest = highest score across all attempts. Last = the most recent attempt's score.Best = 所有 attempt 中的最高分；Last = 最近一次的分數。
Key idea: you can practise (attempt) many times; submitting is the one moment you hand it to the teacher. After submitting, the assignment is marked SUBMITTED.核心概念：你可以練很多次（attempt）；submit 是唯一把它交給老師的那一刻。提交後，該作業標記為 SUBMITTED。
Student wording: "attempt" is a backend term; the student UI always shows "Try" (Try 1, Try 2…), never the word "attempt".學生端用字：「attempt」是後端術語；學生介面一律顯示「Try」（第 1 次、第 2 次…），不出現「attempt」這個字。

3 Submit flow提交流程

Submit sends the assignment's result to the teacher. Available on a record that has a completed attempt and is not yet submitted.提交會把該作業的結果送給老師。只有在記錄「已有完成的 attempt」且「尚未提交」時可用。

  1. In History, the student opens a record with a completed attempt (status Not submitted).在 History，學生打開一筆已有完成 attempt 的記錄（狀態 Not submitted）。
  2. Student taps Submit to teacher.學生按 Submit to teacher（提交給老師）。
  3. App calls upsertAssignmentHistory → marks isSubmitted = true and records submittedDate.App 呼叫 upsertAssignmentHistory → 把作業標記 isSubmitted = true 並記下 submittedDate。
  4. The latest completed attempt becomes the submission; status flips to SUBMITTED with the date shown.最近一次完成的 attempt 成為提交版本；狀態翻成 SUBMITTED 並顯示日期。
  5. The teacher can review — leaving a teacherComment; AI feedback (aiFeedbackForStudent) and rubric may also attach.老師即可審閱 — 留下 teacherComment；也可能附上 AI 回饋（aiFeedbackForStudent）與 rubric。
One submission per assignment. Submit is not per-attempt — it commits the assignment. In the prototype, submitting flips the row to Submitted and stamps the date (Today).一份作業只提交一次。Submit 不是針對單次 attempt，而是提交整份作業。原型裡按下 Submit 會把該列翻成 Submitted 並蓋上日期（Today）。

4 Redo — start a new attempt重做 — 開始新的一次

Redo lets the student practise the same assignment again to improve. Each redo is a new attempt; Best/Last recompute.重做讓學生對同一份作業再練一次以求進步。每次重做都是新的一次；Best/Last 會重算。

  1. In History, expand a record to reveal its attempts and the action row.在 History 展開一筆記錄，露出各次記錄與動作列。
  2. Student taps ↻ Redo (labelled "Start new attempt" in the live app).學生按 ↻ Redo（正式 App 裡稱「Start new attempt」）。
  3. App opens the practice fresh: /dashboard/assignments/content?sk=<id>&type=<type>.App 重新開啟練習：/dashboard/assignments/content?sk=<id>&type=<type>。
  4. On completion, attempt N+1 is stored; Best = max, Last = this attempt.完成後存成 第 N+1 次；Best = 最高分，Last = 這一次。
Availability: non-MC can be redone freely. MC is blocked once there is an attempt on the current version (see §5).可用性：非選擇題可自由重做。選擇題只要當前版本已有一次 attempt，就不能再重做（見 §5）。

5 MC vs non-MC選擇題 vs 非選擇題

Rule規則Q&A / Mirroring / VocabularyQ&A / 口說跟讀 / 詞彙Multiple Choice選擇題
Redo (new attempt)重做（新的一次）Unlimited無限One attempt per version每個練習版本一次
Condition條件Always (unless practice removed)一律可用（除非練習被刪）!submitted && !hasCurrentVersionAttempt
UI介面Shows ↻ Redo顯示 ↻ RedoHides Redo; shows Multiple Choice · one try隱藏 Redo；顯示 Multiple Choice · one try
SubmitSame for both — available while not yet submitted.兩者相同 — 尚未提交前都可提交。
Rationale: MC answers are fixed, so unlimited retries would let a student grind the exact answer. Open-ended types (speaking / writing) benefit from repeated practice.原因：選擇題答案固定，無限重做會讓學生刷出正確答案；開放式（口說 / 寫作）則需要反覆練習才有幫助。

6 States & fields狀態與欄位

Assignment statuses作業狀態

Status狀態Meaning意思
PRACTICEDHas at least one attempt, not submitted.至少練過一次、尚未提交。
SUBMITTEDHanded to the teacher; carries submittedDate.已交給老師；帶有 submittedDate。
REMOVEDPractice deleted by teacher; read-only history.老師刪了練習；歷史唯讀。

Per-attempt fields單次 attempt 的欄位

Field欄位Meaning意思
attemptAttempt number (1, 2, 3 …).第幾次（1、2、3…）。
date（createdAt）When the attempt was made.這次何時做的。
score（percentageScore）0–100. Drives Best / Last.0–100，決定 Best / Last。
isCompletedWhether finished (else resumable).這次是否完成（否則可續做）。
isSubmittedWhether this attempt is part of the submission.這次是否屬於提交版本。
teacherComment · aiFeedbackForStudent · rubricFeedback attached after review.審閱後附上的回饋。
practiceVersionWhich version of the practice this attempt belongs to.這次屬於哪個練習版本。

8 Feedback & Mail Box回饋與 Mail Box NEW

The items below extend today's product — discussed & built in the prototype, not yet in the app. Each carries a NEW tag.以下項目是對現有產品的延伸 — 已討論並在原型完成，尚未進正式 App。各項標上 NEW。

A · "Reviewed" stateA · 「Reviewed」狀態 NEW

History gains a third status: Not submitted → Waiting → Reviewed. Once the teacher reviews, the record becomes Reviewed and carries the feedback.History 新增第三種狀態：Not submitted → Waiting → Reviewed。老師審閱後，該筆變成 Reviewed 並帶著回饋。

B · Feedback is read in HistoryB · 回饋在 History 讀 NEW

The full teacher comment (+ AI Summary) is read inside the History record when expanded. Right after reading, ↻ Redo to improve is the natural next step — it turns feedback straight back into practice.完整老師評語（+ AI Summary）在展開 History 記錄時閱讀。讀完後，↻ Redo to improve 就是最自然的下一步 — 把回饋直接接回練習。

C · Mail Box — notification inboxC · Mail Box — 通知收件匣 NEW

A brand-new inbox (no equivalent in today's product). It notifies the student ("Teacher reviewed your X"); tapping the message deep-links into History and opens that record. Mail Box only notifies — the feedback content lives in History. Unread count shows on the sidebar badge.一個全新的收件匣（現有產品沒有）。它負責通知學生（「老師回饋了你的 X」）；點訊息會深連結跳進 History 並展開該筆。Mail Box 只通知 — 回饋內容住在 History。未讀數顯示在側欄徽章。
