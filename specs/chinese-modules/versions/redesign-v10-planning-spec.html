Teacher — Planning Mode

一串一問一答的對話，從老師說的那句話一步步推回我們現有的功能；建立之前先讓他看到學生會看到的東西。

Chinese Modules Role: CLASS_TEACHER Status: Draft v4 · 提案中 Scope: 教師端 Updated: Aug 14, 2026 Prototype: Redesign v10
用語：教材那個物件在產品裡叫 Project（側邊欄 Projects、projectConfig、New Project）—— 本文一律沿用，不另創「課文」這個說法。課文只用來指 Project 內部的那段文章內容。同理，練習型別一律用系統名稱（MIRRORING / VOCABULARY / SENTENCE_SCRAMBLE / QA / MULTIPLE_CHOICE），不另取代稱。

1 這是什麼

Planning mode 是 Practice 的新入口。它不先問「你要哪一種物件」，而是從老師講的話出發，一題一題把它推回系統做得到的事。

一串對話，不是一張表單

系統問一題、老師答一題，問與答都留在畫面上。答案改了，從它長出來的步驟就作廢重問。每一格右上角都能 Back，左側 History 隨時回頭看任何一條舊的計畫。

核心約束：先看見，再建立

AI 的產出不會直接寫進資料庫。課文、題目、學生會看到的畫面，都在建立之前先攤開讓老師看過。這一條沒有隨改版動搖，變的只是「看見」發生在哪裡。

一句話定義：Planning mode 把「建立練習」從先選型別 → 照固定步驟走完 stepper，改成說出目的 → 一題一題確認 → 看到學生會看到的 → 建立。
這個流程要解的，是「名詞對不上」。老師說的「造句」「聽寫」「會不會念」，沒有一個跟系統型別同名；有些他想要的我們根本做不到。一次性產出只能猜，猜錯整句重打。逐題推回去，才有地方把歧義問清楚、把做不到的直說。見 §6.4。

2 現況與問題

2.1 現在怎麼建立一個練習

以下取自 dahua-dash 現況程式碼，不是推測：

  1. Practice List 右上 New Practice → 開 AddNewPracticeDialog，標題「Choose Practice Type」，五張卡：Mirroring Practice / Vocabulary Practice / Sentence Scramble / Multiple Choice / QA Practice。註腳寫著「You can create one practice at a time.」
  2. 選定型別後導向 /dashboard/practice/create?type=X，進入該型別的 stepper（practice-unified-view.js）：
    型別步驟
    MIRRORINGContent → Settings & Preview → Assign Practice
    QAContent → Settings & Preview → Assign Practice
    VOCABULARYVocabulary → Practice Type → Settings → Assign Practice
    MULTIPLE_CHOICEQuestion Bank → Edit Questions → Preview → Assign Practice
    SENTENCE_SCRAMBLE待確認 —— 見 §9.2

2.2 問題

問題說明
入口要求老師先懂系統第一個決策是「四種練習型別選一個」。老師腦中想的是「我要教食物這課、要他們會唸」，不是「這屬於 MIRRORING」。型別是系統的分類，不是老師的語言。
一次只能做一個對話框明講 one practice at a time。但一堂課通常需要 2–4 個練習（生詞 + 跟讀 + 測驗），老師得把整段流程重複三遍，每遍都重選 Project、重設拼音、重指派班級。
看不到結果才決定要走到 stepper 第二、三步才知道系統會生出什麼；發現不對就得退回重來。
設定散在各處拼音、翻譯、語速、人聲、Auto Pass 全擠在 stepper 的一頁設定面板裡，一次要決定七件事；而且要改其中一件就得整頁重看。
注意：Planning mode 不取代 stepper。stepper 仍是精修與編輯的地方；Planning 只取代那張型別選擇對話框，並把「一次一個」放寬。詳見 Q7。

3 內容鏈：教學點、題庫與練習

Planning 要能提出一份好的提案，得先知道教材在系統裡是怎麼組起來的。

Project │ ├─ teachingPoints ──┬──▶ VOCABULARY 記住新詞 │ （這課要教什麼） ├──▶ VOCABULARY × MC 考單字 │ └──▶ SENTENCE_SCRAMBLE 練句型／語序 │ ├─ content（課文） ─────▶ MIRRORING 唸出來 │ └─ content ──▶ Question Bank ──┬──▶ MULTIPLE_CHOICE 考課文內容 題型 × 分類 × 題數 └──▶ QA 用它問答 （Content Base / Extension）
教學點是整個教材系統的脊椎，不是「欄位之一」。六個產出裡，三個直接吃 teachingPoints（Vocabulary、Vocabulary × MC、Sentence Scramble）。Mirroring 走課文句子；QA 與 Multiple Choice 都走題庫。課文反而比較像是承載教學點的容器。這件事決定了 Planning 的提案品質該用什麼衡量 —— 見 §8.2 與 Q8。

3.1 Teaching Points：幾乎所有練習的內容來源

不是講義上的一個區塊名稱而已，它有三重身分：

身分說明
projectConfig 的欄位teachingPoints 與 topic / wordLimit / contentType / levelType 並列在 getProjectConfigs 的查詢裡。
產生課文的輸入New Project 的 Generate Content 步驟是一個 tag 輸入框（Type a word and press Enter，以 ，、, 分隔）。老師先寫下要教的點，生成才跑 —— 課文是為了這些教學點而寫，不是先有課文再挑生詞。
建立流程的一個步驟New Project 共四步：Course Settings → Generate Content → Review & Edit → Teaching Points。最後一步就是確認教學點。

八種教學點型別

TEACHING_POINT_TYPE_OPTIONS，預設 WORD：

WORD 词汇 VERB 动词 NOUN 名词 ADJECTIVE 形容词 GRAMMAR 语法／句型 PHRASE 短语／成语 MEASURE_WORD 量词 OTHER 其他

這推翻了本文較早版本的一個假設。先前把一堂課的內容用「主題 + 練習型別」描述（「食物 + 跟讀」）。但系統裡「這堂課教什麼」的正規表達是 teaching points；主題只是課文的題目。GRAMMAR / PHRASE / MEASURE_WORD 這幾類根本不是生詞，用「12 個生詞」描述會直接漏掉句型與量詞的教學。
2026-08-11 決議：QA 的素材是 question bank，不是 teaching points。本文較早版本記載為 teaching points（口述），現依產品裁定更正 —— 與程式碼一致：qAndAQuestion 是 generateQuestions 的三種題型之一，分類 Content Base / Extension。連帶影響：勾 QA 就跟勾 Multiple Choice 一樣需要一個題庫（見 Q9），且 QA 不再計入教學點覆蓋（見 §8.2）。

3.3 Question Bank 是「題型 × 分類」的矩陣

題庫不是一疊 N 題，而是三種題型、各自帶分類（src/enum/questions-bank.js）：

題型分類適合檢查什麼
Multiple Choice
multiChoiceQuestion		 Comprehension Fill in blankusage Pinyin Meaning 讀懂了沒 / 會不會用 / 會不會唸 / 知不知道意思
True & False
trueAndFalseQuestion		 Comprehension Pinyin Meaning 同上，但沒有 Fill in blank
Q&A
qAndAQuestion		 Content BaseshortAnswer Extension (Beta) 就課文回答 / 延伸發揮
事實說明
從 project 生成generateQuestions(projectConfigSk, questionsBankSk, questionOptions)。題庫的題目掛在某個 project 底下。
一庫綁一個 Project建立時寫死 projectConfigSks: [selectedProjectSk]（Step 1 是單選）。資料結構雖是陣列、也有 useQuestionsBankProjects 能從題目反推出每個 project 各幾題，但只要題庫連到一個以上的 project，Step 2 會直接停用生成並顯示 “Linked to multiple projects — generation is disabled. Single-project only is supported for now.”（canGenerate = … && !hasMultipleProjects）。
結論：現況是 1 題庫 ↔ 1 Project。多 project 是要防守的遺留狀態，不是可用的能力。
每次生成的粒度一種題型 + 一個分類 + 題數 1–10（GENERATE_QUESTIONS_NUMBERS）。三種題型可用 bulkGenerateQuestions 一次送。
建立流程三步 wizard：Select Project → Generate Questions → View & Edit Questions，另可手動加題（每種題型各一張表單）。
題目的分組取用時是 grouped[題型][分類] = questions[]。

3.4 為什麼 Planning 非知道這些不可

老師講的話，落到系統裡就是教學點與題型 × 分類。少了這兩層，提案只能停在「10 題選擇題」這種說了等於沒說的程度：

老師說的要落到的設定
「檢查他們有沒有讀懂這篇」Multiple Choice × Comprehension
「練習用這幾個詞造句」Multiple Choice × Fill in blank
「考生詞的意思」Multiple Choice × Meaning
「看他們會不會唸」Multiple Choice / True & False × Pinyin
「讓他們自己講一段」Q&A × Extension
「這課要教『了』的用法」Teaching point，型別 GRAMMAR —— 不是生詞，Vocabulary 練習蓋不到
「順便帶到量词『碗』」Teaching point，型別 MEASURE_WORD
設計結論：Planning 每一步要讓老師看到真的內容，並在測驗類的項目上標明題型 × 分類 × 題數。詳見 §8 先看見，再建立 與 §9 資料與 API 對應。

4 設計理念

① 用老師的語言當入口

輸入框接受自然語言。型別由系統推斷，老師不需要先知道 MIRRORING 和 QA 的差別。推斷錯了，在產出預覽那一步一眼就看得出來。

② 一問一答

每一格只問一件事，也只有一個可以退回的點。不把三個決定塞進同一格 —— 那樣改一個就得整格重來。

③ 答案改了，衍生的就作廢

課文、題目、設定都是從上游答案長出來的。上游一改，它們必須消失而不是留在畫面上矛盾著。

④ 不發明新資料

產出一律是既有的練習型別，來源一律是既有的 Project（課文）或 Question Bank。Planning 不引入新的內容型別，做不到的就直說做不到。

5 對話模型

Planning 不是一張表單，也不是 wizard。它是一串接續的對話：系統問一題，老師答一題，問與答都留在畫面上，可以往上捲看完整過程。

5.1 一則訊息一個問題

這條規則是逼出來的。把「課文 + 教學點 + 設定」塞進同一格時，老師得先讀完整格才知道要回答什麼；而且一格裡有三個決定，改其中一個就得整格重來。拆成一問一答之後，每一格只有一個決定，也只有一個可以退回的點。

規則說明
一格一題每一則系統訊息只問一件事。設定類的（拼音、翻譯、語速…）也各自成格，不合併成設定面板。
只有最後一格是活的活的那格帶控制項（選項、輸入框、動作鍵）；往上的歷史訊息一律變成唯讀的內容，句子上的刪除鍵、教學點上的 ✕ 都會消失。
答案也是一則訊息老師的每一次選擇都以他自己的話回寫成一格（選 Xiaorou 就寫 Xiaorou，不是寫按鈕上的 Use this voice），讓整串讀起來像對話而不是操作紀錄。
打字與點選同一個入口底部永遠有輸入框。老師可以不理選項直接打字修正（「只要 QA」「改成十題」），系統重新解析後把衍生步驟作廢重問。

5.2 兩種 turn

種類內容誰產生
收斂題還沒填滿的必答格，選項是固定清單由目前狀態推出來（§6），不存進歷史；填滿了就自動消失
步驟課文、教學點、Mirroring 設定、題目、學生預覽、指派…答完收斂題後依路徑產生（§7），存進歷史
為什麼要分。收斂題是推導出來的，所以答案一改就會自動重問；步驟是已經發生的事，得明確作廢才會消失。混成一種，就會出現「改了練習型別，但上一個型別的課文還留在畫面上」這種矛盾狀態。

5.3 Back：改答案會作廢衍生的步驟

每一格右上角有一個 Back（唯一的例外是第一題和已完成的那格）。它不在回答列裡 —— 它是訊息上的控制項，不是一個選項。

語意說明
退回上一個「問題」不是退回上一次點擊。在句子那一步調了順序、刪了句子，這些不會各自變成一格歷史；等按下 They’re fine 進到下一題，Back 回來時句子仍是改過的樣子。
衍生的步驟一併作廢從「選 Project」退兩步回到「選練習型別」，已經產生的課文、教學點、題目全部消失 —— 它們是從那個答案長出來的，留著就是錯的。已經勾選的型別則保留。
可以連按一路退回第一題。退到底就沒有 Back 了。
待決：老師的手改要不要保住。目前作廢是整段丟掉 —— 老師若已經手動改過課文句子、加過教學點，退回上游再前進時那些編輯會不見。要不要保留（以及怎麼判斷「還適用」）見 Q13。

5.4 History 側邊欄

畫布左側常駐一欄對話列表，行為比照一般 AI 產品：頂端 New plan 隨時開新的，下方依時間分組列出過去的計畫，點一筆就切過去。可收合。

項目規格
標題由那條對話做了什麼推出來：練習型別 + Project（Mirroring Practice · 食物）。還沒選型別時是 New plan，選了就即時改掉。
副標已完成 → Created · assigned to 4A；進行中 → 已答幾題。
切換切走前先把當下這條存起來，切回來時連停在哪一題都一樣。已完成的對話沒有 Back。
Plan another完成畫面上的這顆等同 New plan —— 完成的那條留在清單裡，不是被清掉。
這一節有一個未決的後端問題：對話要不要存到伺服器。原型存在記憶體裡，重新整理就沒了。要跨裝置、跨登入回顧，就需要一張 planning session 表。見 Q12。

6 收斂：必答的幾題

老師的第一句話幾乎永遠不完整。「我要考 A 班學生會不會念食物」沒說：念單字還是句子、素材從哪來。在這些答案到齊之前，連要走哪幾步都還不知道，所以這幾題不能跳過。

6.1 問題順序

格子問法為什麼非問不可
modeWhat are we making today?決定是走教材線還是練習線 —— 兩條線之後的步驟完全不同。
afterAnd what do you want to do with it?只在選了 A Project 時出現。決定建完之後還要不要接練習或講義。
practicesWhich practices?可複選 —— 「建立 QA 跟 MIRRORING」是一次請求。系統可以先幫忙勾，但一定要老師按下確認。

6.2 什麼不問

准入條件只有一條：這個答案會不會改變接下來的流程形狀。

不問的原因
班級與排程不改變任何步驟。留到最後的指派（§7.6）。
題庫新舊推得出來。選了既有 Project 就查得到它有沒有題庫：沒有就只能新建，有就預設加進去。
幾題 / 幾句 / 哪些教學點屬於展開階段，全部可改，不必先問。

6.3 只問推不出來的

句子裡已經講清楚的就不問。對話長度因此由老師那句話決定，而不是固定流程：

老師說的句子已填還要問
食物那課出十題選擇題終點 = MULTIPLE_CHOICE、素材 = 食物0 題
我要考 A 班會不會念食物終點未定（型別歧義）、班級 = 4A2 題：念單字還是句子 → 食物從哪來
幫我弄一下明天的課幾乎沒有卡在第一格，從頭問起

6.4 名詞不同、以及做不到

老師說的「造句」「聽寫」「默寫」「朗讀」沒有一個跟系統型別同名。這是這個流程存在的理由之一 —— 要從老師的句子一步步推回我們現有的功能。

情境做法
型別有歧義「會不會念」在系統裡有兩個落點（VOCABULARY 念單字 / MIRRORING 念句子）—— 多問一句，選項就是那兩個。
名詞不同把老師的詞映到我們的能力上：「你說的『造句』是要他們把打亂的詞排成句子（SENTENCE_SCRAMBLE），還是自己說一句（QA）？」
做不到「我要他們寫作文」在終點清單裡沒有對應。直說沒有，並給最接近的替代，不硬塞一個相近的型別 —— 那是這種流程最糟的失敗方式。老師接受替代就接回同一串問題。
「做不到」清單與同義詞對照表誰維護，仍未定 —— 見 Q11。原型是前端寫死的兩條（作文、翻譯）與三組同義詞（念／造句／聽寫），只夠示意。

7.2 課文與教學點

項目規格

教學點至少一個Vocabulary、Sentence Scramble 都從它長出來，空的就無法繼續。

8 先看見，再建立

這是整個功能的核心約束，也是唯一沒有隨改版動搖的一條：AI 的產出不會在老師沒看到的情況下寫進資料庫。改變的只是「看見」發生在哪裡 —— 從一張提案表格，變成散在對話裡的幾格。

8.1 每一步要看到真東西

光描述不算看見。「12 個教學點 · 約 6 句」只是規格，老師沒看到那 6 句；「MC × Comprehension × 10」也一題都沒露。
哪一步看到什麼
課文會被寫出來的整篇句子，逐詞拼音 + 翻譯。真實 New Project 的第三步就叫 Review & Edit，這裡等於把那一步提前。
材料確認既有 Project 的整篇課文，以及會被用到的教學點與題庫名稱。
題目實際的題目與選項，正解標綠。
學生預覽學生視角的一則，設定已套用。
完成建立了幾項、各叫什麼、指派給誰幾人、到期時間、必修或選修。

8.2 教學點覆蓋率

一份計畫可能漏掉某些教學點 —— 尤其 GRAMMAR / MEASURE_WORD 這種不好處理的。覆蓋率怎麼算，有兩條規則：

規則理由
只算「練習」，不算教材Project 與題庫是素材，不是練習。把它們算進覆蓋，會讓「純建教材」看起來每個點都教到了，那是假的。
Multiple Choice 依分類計算同樣是 MC，Comprehension 考的是整篇讀懂沒，不針對任何單一教學點，覆蓋算 0；Fill in blank 練句型（GRAMMAR / PHRASE / MEASURE_WORD）；Meaning / Pinyin 練詞。QA 同理，兩個分類都算 0。用型別一概算成「全覆蓋」等於誇大。
這條規則是做原型時發現的。把 MC 當成全覆蓋時，關掉句子重組仍顯示「全部教到」—— 但語法點其實沒人練。改成依分類計算後，關掉句子重組會立刻標出「了、碗 沒有任何一項練到」，這才是這個指標存在的意義。
現況落差：規則還在算，但畫面上沒有地方顯示。覆蓋率原本掛在提案表格的最上方；表格隨改版拿掉之後，composeRows() 仍逐列算出 covers，卻沒有任何一格會把它畫出來（.covers 這組樣式已經是孤兒）。要放回哪一步尚未決定 —— 見 Q16。

8.3 建立之後

  • 完成那一格列出：建立幾項、各項名稱、指派給幾人 / 哪一班、到期時間、必修或選修。
  • 出口是三個連結：Open Practice List / Open Projects / Plan another。新建立的項目應帶 ?new={sk} 讓 Practice List 顯示 NEW 標記（已支援此參數）。
  • 完成的對話留在 History 裡，隨時可以回頭看整串問答。

11 待討論

Q1 AI 產出可以直接建立，還是一律要先進編輯器？

目前設計是可以直接建立 —— 對話走到底就寫進資料庫，另外提供 Open in editor 當備選。反面意見是：AI 寫的題目沒人看過就發給學生，風險高。

  • A. 維持現狀：可直接建立，Open in editor 為選項。
  • B. 一律先進編輯器，Planning 只負責「填好參數」。
  • C. 折衷：有 AI 生成內容的（QA 題目、MC 題目）強制進編輯器；只是重組既有素材的（跟讀取課文句、生詞取課文詞）可直接建立。

Q2 解析失敗或信心不足時怎麼辦？

老師可能打「幫我弄一下明天的課」這種資訊不足的句子，或打完全無關的內容。

  • A. 盡量猜，把推得出來的格子填好，剩下的照常往下問。
  • B. 完全不猜 —— 一個字都推不出來時就從第一題問起（原型現在的行為）。
  • C. 低信心時明講「我看不太懂這句」，再從第一題問起。

改成對話之後這題的風險比原先低很多 —— 猜錯不會浪費整段流程，下一題就會問出來，老師也隨時能 Back。牽涉 §9.2 的 confidence 欄位要不要做。

Q3 建立多個練習時中途失敗怎麼處理？

「整堂課」會連續建立 3–4 個。第 2 個失敗時：全部 rollback？保留成功的並標示哪個失敗？還是逐項顯示狀態讓老師重試單一項？

Q4 指派的範圍 —— 多班要不要做？

大半已決。對照真實指派表單後，Planning 現在問滿五題：班級、開始時間、到期時間、必修與否、逐生名單（§7.6）。原本的 A 案（單班、無截止日）已被推翻。

剩下的只有一項：班級仍是單選。assignPractice 的 classes 本來就是陣列。

  • A. 維持單班 —— 要指派兩班就跑兩次 Planning。
  • B. 班級改多選，學生名單依班分組。成本主要在最後一題：三個班就是三份名單要攤在同一格裡。

Q5 AI 生成的練習要不要留標記？

Question Bank 已經區分「AI generated / 手寫」。練習要不要也存一個來源標記（createdVia: PLANNING），供日後統計採用率與品質追蹤？

Q6 輸入語言支援到什麼程度？

老師可能用英文、繁中、簡中，或混用（「用食物課文做一個 mirroring」）。三種都要支援嗎？產出的練習名稱要跟隨輸入語言，還是固定格式（主題 + 動作）？

Q7 舊的型別選擇對話框留不留？

本案讓 New Practice 直接開 Planning。AddNewPracticeDialog 要：

  • A. 完全移除，只留 Planning。
  • B. 保留為 Planning 畫面上的一個次要入口（「我知道我要哪一種」）。
  • C. 兩者並存一段時間，用 feature flag 分流觀察採用率。

Q8 教學點沒被蓋到時，Planning 該做到什麼程度？

一份提案可能漏掉某些教學點 —— 尤其 GRAMMAR / MEASURE_WORD 這種現有練習型別不好處理的。

  • A. 只標示出來，讓老師自己決定要不要補。
  • B. 主動多提一項練習去蓋它（例如語法點 → MC × Fill in blank）。
  • C. 不處理 —— 教學點覆蓋率不是 Planning 的責任。

子問題已解：先前記為「語法點該用哪一種練習教？現有型別沒有一個是為句型設計的」—— Sentence Scramble 就是，素材直接取自 teaching points。本題只剩「漏掉時要不要主動補」這一層。

Q9 沒有合用的題庫時，Planning 可以現生嗎？

老師要「MC × Fill in blank × 10」但既有題庫只有 Comprehension 的題目。generateQuestions(projectConfigSk, questionsBankSk, questionOptions) 本來就能生，問題是 Planning 要不要自己觸發。

  • A. 可以：Planning 直接生進既有題庫，提案上標明「will generate 10 new questions」。
  • B. 不行：只能從既有題目挑，湊不出來就據實說明並少給一項。
  • C. 可以，但一律要老師先看過題目（接 Q1 的 C 案）。

若選 A 或 C，還要決定生進哪個題庫：既有的、還是新開一個。

Q10 1 題庫 ↔ 1 Project 的限制，Planning 要怎麼配合？

既然題庫綁死一個 Project（§3.2），一堂課要出測驗，就必須存在那個 Project 自己的題庫。這讓 Q9（沒有合用題庫時能不能現生）從選配變成必要 —— 老師新建一個 Project 後，若沒人替它建題庫，Planning 就永遠出不了測驗。

  • A. Planning 在需要時自動替該 Project 建題庫並生題（等於把 Q9 選 A）。
  • B. Planning 只提示「這個 Project 還沒有題庫」，附一個一鍵前往建立的連結。
  • C. 改成允許一庫多 Project —— 但那要先解掉 hasMultipleProjects 的停用邏輯，屬於題庫模組的變更，不在本案範圍。

另外：若題庫因遺留資料連到多個 project，Planning 應比照 App 一律不碰（不生成、不宣稱可用）。

Q11 「做不到」的清單誰維護？

漏斗第一題只認終點清單上的 8+1 個。老師打「我要他們寫作文」「聽寫」時，系統必須直說做不到並給最近的替代，不能硬塞一個相近的型別出來 —— 那正是一次性產出最糟的失敗方式。

  • A. 寫死在前端，跟終點清單一起維護。
  • B. 後台可編，方便隨功能上線調整。
  • C. 交給模型臨場判斷 —— 不建議，它會硬掰。

連帶要決定同義詞對照表（聽寫／默寫／造句／朗讀／背單字…）要做到多細，以及是不是同一份資料。

Q12 對話要不要存到後端？

History 側邊欄（§5.4）現在只存在瀏覽器記憶體，重新整理就全部不見。要做到「隨時回顧」這件事真的成立，需要一張 planning session 表。

  • A. 不存 —— History 只是本次工作階段的方便，重整就重來。成本最低，但「回顧」等於做半套。
  • B. 存 localStorage —— 同一台機器有效，跨裝置無效，不需要後端。
  • C. 存後端 —— 需要新資料表（老師、狀態快照、時間），並要決定保留多久、要不要能刪。

若選 C，還要決定存什麼：整份狀態快照（好回放，但綁死前端結構），還是只存問答紀錄（穩定，但重開時要重跑一次推導）。

Q13 Back 作廢衍生步驟時，老師的手改要不要保住？

目前是整段丟掉。老師若已經手動改過課文句子、加過教學點，退回上游再前進時那些編輯會不見（§5.3）。

  • A. 維持現狀：乾淨、可預測，但可能白做工。
  • B. 保住「動過的」內容，只重算沒動過的 —— 但要能判斷改過的東西在新答案下還適不適用（換了 Project，舊句子就完全不適用）。
  • C. 退回時先警告「這會丟掉你改過的 N 句」，讓老師自己決定。

Q14 Mirroring 的七題設定會不會太長？

拆成七格才能一題一題退回，但老師每次建 Mirroring 都要走七格；而且多數老師的設定每次都一樣。

  • A. 照問七題 —— 一致，但重複。
  • B. 記住上次的設定，開頭一格問「跟上次一樣嗎？」，要改才展開。
  • C. 只問「會影響學生體驗」的（拼音、翻譯、英文先播），其餘用預設，需要時到 stepper 改。

Q15 選了多種練習時，學生預覽要看幾張？

目前只展示第一種，其餘註明 follow the same settings（§7.5）。但「Mirroring + Multiple Choice」這種組合，只看 Mirroring 等於另一半沒看到。

  • A. 維持一張 —— 短，但不完整。
  • B. 每種練習各一張，同一格裡往下排。
  • C. 每種各一格，變成 N 個預覽步驟。

Q16 教學點覆蓋率要放在哪一步？

覆蓋率規則（§8.2）還在程式裡逐列算，但畫面上已經沒有地方顯示 —— 它原本掛在提案表格最上方，表格拿掉之後就沒了。

  • A. 放在教學點那一格 —— 但那時還不知道最後會建立什麼，算不準。
  • B. 獨立成一格，排在學生預覽之後、指派之前：「這份計畫教到什麼，哪些沒教到」。
  • C. 放進完成畫面 —— 事後才講，來不及補。
  • D. 不做了 —— 連同 Q8 一起收掉，把計算也移除。

選 D 的話要一併確認 Q8（漏掉教學點時要不要主動補）也不做，否則會留下一個沒人看的指標。

12 Out of scope / 假設

  • 不含對四種 practice type 本身的任何修改，也不含 stepper 的改版。
  • 不含新的內容型別。Planning 的產出一律落在既有的 practice + project + question bank 上。
  • 不含學生端任何變動。
  • 不含 Word Game 的指派 —— 那條線走 Word Game spec。
  • 已不再假設 Project 與題庫存在 —— 收斂那幾題就是為此而設（§6.1）：沒有 Project 就從課文開始建，沒有題庫就順便補。但 Planning 不重做 New Project 的四步流程，只在前面包一層收集意圖。
  • 不含樣本／範本清單。早先版本設計過一組樣本，已從產品移除 —— 對話本身就是入口，不需要預填的起點。
  • 假設模型可在數秒內回應；超過 15 秒需要有取消與重試。
