Teacher — Planning Mode

老師用一句話或點一個樣本來開啟作業，系統在建立之前先把會產生什麼逐項攤開讓老師確認。

Chinese Modules Role: CLASS_TEACHER Status: Draft v3 · 提案中 Scope: 教師端 Updated: Aug 10, 2026 Prototype: Redesign v9
用語：教材那個物件在產品裡叫 Project（側邊欄 Projects、projectConfig、New Project）—— 本文一律沿用，不另創「課文」這個說法。課文只用來指 Project 內部的那段文章內容。同理，練習型別一律用系統名稱（MIRRORING / VOCABULARY / SENTENCE_SCRAMBLE / QA / MULTIPLE_CHOICE），不另取代稱。

1 這是什麼

Planning mode 是 Practice 的起始畫面，概念參照 Figma / Miro 開新檔案時的那張畫布：不先問「你要哪一種物件」，而是先讓人說出目的或挑一個現成的起點。

兩條進入路徑

  • 自己打字 —— 用自然語言描述要的練習，例如「用食物課文做一個跟讀練習，六句，顯示拼音」。
  • 點樣本 —— 從樣本清單挑一個，等同於幫老師把那句話填好。

兩條路徑匯流到同一個結果畫面，不是兩套流程。

核心約束：先看見，再建立

AI 的產出不會直接寫進資料庫。系統先列出「會建立哪些練習、每個多大、從哪個 Project 或題庫來、指派給哪一班」，老師逐項確認（可逐項關掉），按下 Create & assign 才真的建立。

一句話定義：Planning mode 把「建立練習」從先選型別 → 照固定步驟走完 stepper，改成說出需求 → 看見會產出什麼 → 確認。

2 現況與問題

2.1 現在怎麼建立一個練習

以下取自 dahua-dash 現況程式碼，不是推測：

  1. Practice List 右上 New Practice → 開 AddNewPracticeDialog，標題「Choose Practice Type」，五張卡：Mirroring Practice / Vocabulary Practice / Sentence Scramble / Multiple Choice / QA Practice。註腳寫著「You can create one practice at a time.」
  2. 選定型別後導向 /dashboard/practice/create?type=X，進入該型別的 stepper（practice-unified-view.js）：
    型別步驟
    MIRRORINGContent → Settings & Preview → Assign Practice
    QAContent → Settings & Preview → Assign Practice
    VOCABULARYVocabulary → Practice Type → Settings → Assign Practice
    MULTIPLE_CHOICEQuestion Bank → Edit Questions → Preview → Assign Practice
    SENTENCE_SCRAMBLE待確認 —— 見 §9.2

2.2 問題

問題說明
入口要求老師先懂系統第一個決策是「四種練習型別選一個」。老師腦中想的是「我要教食物這課、要他們會唸」，不是「這屬於 MIRRORING」。型別是系統的分類，不是老師的語言。
一次只能做一個對話框明講 one practice at a time。但一堂課通常需要 2–4 個練習（生詞 + 跟讀 + 測驗），老師得把整段流程重複三遍，每遍都重選 Project、重設拼音、重指派班級。
看不到結果才決定要走到 stepper 第二、三步才知道系統會生出什麼；發現不對就得退回重來。
樣本無處可放現在沒有任何「常見做法」的入口。每個練習都從零開始配置。
注意：Planning mode 不取代 stepper。stepper 仍是精修與編輯的地方；Planning 只取代那張型別選擇對話框，並把「一次一個」放寬。詳見 Q7。

3 內容鏈：教學點、題庫與練習

Planning 要能提出一份好的提案，得先知道教材在系統裡是怎麼組起來的。

Project │ ├─ teachingPoints ──┬──▶ VOCABULARY 記住新詞 │ （這課要教什麼） ├──▶ VOCABULARY × MC 考單字 │ └──▶ SENTENCE_SCRAMBLE 練句型／語序 │ ├─ content（課文） ─────▶ MIRRORING 唸出來 │ └─ content ──▶ Question Bank ──┬──▶ MULTIPLE_CHOICE 考課文內容 題型 × 分類 × 題數 └──▶ QA 用它問答 （Content Base / Extension）
教學點是整個教材系統的脊椎，不是「欄位之一」。六個產出裡，三個直接吃 teachingPoints（Vocabulary、Vocabulary × MC、Sentence Scramble）。Mirroring 走課文句子；QA 與 Multiple Choice 都走題庫。課文反而比較像是承載教學點的容器。這件事決定了 Planning 的提案品質該用什麼衡量 —— 見 §6.2 與 Q8。

3.1 Teaching Points：幾乎所有練習的內容來源

不是講義上的一個區塊名稱而已，它有三重身分：

身分說明
projectConfig 的欄位teachingPoints 與 topic / wordLimit / contentType / levelType 並列在 getProjectConfigs 的查詢裡。
產生課文的輸入New Project 的 Generate Content 步驟是一個 tag 輸入框（Type a word and press Enter，以 ，、, 分隔）。老師先寫下要教的點，生成才跑 —— 課文是為了這些教學點而寫，不是先有課文再挑生詞。
建立流程的一個步驟New Project 共四步：Course Settings → Generate Content → Review & Edit → Teaching Points。最後一步就是確認教學點。

八種教學點型別

TEACHING_POINT_TYPE_OPTIONS，預設 WORD：

WORD 词汇 VERB 动词 NOUN 名词 ADJECTIVE 形容词 GRAMMAR 语法／句型 PHRASE 短语／成语 MEASURE_WORD 量词 OTHER 其他

這推翻了本文較早版本的一個假設。先前把一堂課的內容用「主題 + 練習型別」描述（「食物 + 跟讀」）。但系統裡「這堂課教什麼」的正規表達是 teaching points；主題只是課文的題目。GRAMMAR / PHRASE / MEASURE_WORD 這幾類根本不是生詞，用「12 個生詞」描述會直接漏掉句型與量詞的教學。
2026-08-11 決議：QA 的素材是 question bank，不是 teaching points。本文較早版本記載為 teaching points（口述），現依產品裁定更正 —— 與程式碼一致：qAndAQuestion 是 generateQuestions 的三種題型之一，分類 Content Base / Extension。連帶影響：勾 QA 就跟勾 Multiple Choice 一樣需要一個題庫（見 Q9），且 QA 不再計入教學點覆蓋（見 §6.2）。

哪一種在系統裡是什麼考什麼 · 素材

MULTIPLE_CHOICE		 頂層練習型別，Choose Practice Type 的一張卡 Project 的課文內容 · 取自 Question Bank（見 §3.3）

3.3 Question Bank 是「題型 × 分類」的矩陣

題庫不是一疊 N 題，而是三種題型、各自帶分類（src/enum/questions-bank.js）：

題型分類適合檢查什麼
Multiple Choice
multiChoiceQuestion		 Comprehension Fill in blankusage Pinyin Meaning 讀懂了沒 / 會不會用 / 會不會唸 / 知不知道意思
True & False
trueAndFalseQuestion		 Comprehension Pinyin Meaning 同上，但沒有 Fill in blank
Q&A
qAndAQuestion		 Content BaseshortAnswer Extension (Beta) 就課文回答 / 延伸發揮
事實說明
從 project 生成generateQuestions(projectConfigSk, questionsBankSk, questionOptions)。題庫的題目掛在某個 project 底下。
一庫綁一個 Project建立時寫死 projectConfigSks: [selectedProjectSk]（Step 1 是單選）。資料結構雖是陣列、也有 useQuestionsBankProjects 能從題目反推出每個 project 各幾題，但只要題庫連到一個以上的 project，Step 2 會直接停用生成並顯示 “Linked to multiple projects — generation is disabled. Single-project only is supported for now.”（canGenerate = … && !hasMultipleProjects）。
結論：現況是 1 題庫 ↔ 1 Project。多 project 是要防守的遺留狀態，不是可用的能力。
每次生成的粒度一種題型 + 一個分類 + 題數 1–10（GENERATE_QUESTIONS_NUMBERS）。三種題型可用 bulkGenerateQuestions 一次送。
建立流程三步 wizard：Select Project → Generate Questions → View & Edit Questions，另可手動加題（每種題型各一張表單）。
題目的分組取用時是 grouped[題型][分類] = questions[]。

3.4 為什麼 Planning 非知道這些不可

老師講的話，落到系統裡就是教學點與題型 × 分類。少了這兩層，提案只能停在「10 題選擇題」這種說了等於沒說的程度：

老師說的要落到的設定
「檢查他們有沒有讀懂這篇」Multiple Choice × Comprehension
「練習用這幾個詞造句」Multiple Choice × Fill in blank
「考生詞的意思」Multiple Choice × Meaning
「看他們會不會唸」Multiple Choice / True & False × Pinyin
「讓他們自己講一段」Q&A × Extension
「這課要教『了』的用法」Teaching point，型別 GRAMMAR —— 不是生詞，Vocabulary 練習蓋不到
「順便帶到量词『碗』」Teaching point，型別 MEASURE_WORD
設計結論：Planning 的產出預覽要以教學點為主軸交代「這堂課教到什麼」，並在測驗類的項目上標明題型 × 分類 × 題數。詳見 產出預覽 與 資料與 API 對應。

4 設計理念

① 用老師的語言當入口

輸入框接受自然語言。型別由系統推斷，老師不需要先知道 MIRRORING 和 QA 的差別。推斷錯了，在產出預覽那一步一眼就看得出來。

② 樣本的粒度由老師決定

有人要的是「一個跟讀練習」，有人要的是「一整堂課」。不替老師選，用一個 segmented control 明講兩種粒度，老師自己切。

③ AI 提案，老師拍板

AI 只負責「提出一份清單」。每一列都有開關，預設全開但可以逐項關掉。沒有任何東西是在老師沒看到的情況下被建立的。

④ 不發明新資料

產出一律是既有的四種 practice type，來源一律是既有的 Project（課文）或 Question Bank。Planning 不引入新的內容型別。

5 起始畫面規格

5.1 位置與入口

項目規格
側邊欄Practice 分組下的第一項，圖示 auto_awesome，排在 Practice List 之上。
其他入口① Practice List 的 New Practice　② Projects 卡片的 Make a practice / Slides / Handout　③ Question Banks 的 Make a quiz。從這些地方進來時，漏斗的格子已經被預填（見 §5.5）。
畫布淺點陣背景，內容置中，最大寬 720px；進入展開階段後放寬到 880px。
沒有班級選擇器八個終點裡有一半產出的是教材（Project / Handout / Slide），根本沒有指派這回事。班級只在有練習產出時、於最後一步出現。

5.2 漏斗：先收斂，再展開

老師的第一句話幾乎永遠是不完整的。「我要考 A 班學生會不會念食物」沒說：念單字還是句子、哪些食物、素材從哪來、幾題。一次性產出只能全部用猜的，猜錯老師得整句重打。

因此流程分成兩段：

收斂（必答，不能跳過） 展開（每一步可改、可回頭） ┌─────────────────────────┐ ┌──────────────────────────────────────┐ │ ① 要產出什麼（多選） │ ─▶ │ 課文 → 教學點 → 會建立什麼 → 建立 │ │ ② 素材從哪來 │ └──────────────────────────────────────┘ └─────────────────────────┘
漏斗在定位「起點 + 終點」 —— 也就是老師落在產出鏈的哪一段（§3）。收斂完成的那一刻，後面要走哪幾步才確定下來；在那之前，連進度條都沒有意義。

什麼該進漏斗

准入條件只有一條：這個答案會不會改變接下來的流程形狀。因此以下都不問——

不問的原因
班級不改變任何步驟，而且指派是最後一步。老師句子裡提了就記下，沒提就留到建立時再選。
題庫新舊推得出來。題庫綁死一個 Project（§3.3）—— 老師選了既有 Project，系統自己查得到它有沒有題庫：沒有就只能新建，有就預設加進去（可反悔）。
幾題 / 幾句 / 哪些教學點屬於展開階段，全部可改，不必先問。

5.3 第一題：要產出什麼（多選，必答）

終點就是產品現有的每一個功能，共 8 + 1 個。可以複選 —— 「建立 QA 跟 MIRRORING」是一次請求，不是兩次。系統可以先幫老師勾，但最後一定要老師確認。

終點需要什麼備註
MIRRORINGProject 的課文句子
VOCABULARYteaching points
VOCABULARY × MULTIPLE CHOICEteaching points不是獨立型別，是 Vocabulary 的模式
SENTENCE_SCRAMBLEteaching points
QAquestion bank分類 Content Base / Extension
MULTIPLE CHOICEquestion bank分類 Comprehension / Fill in blank / Pinyin / Meaning
HandoutProject ＋ 選配 question bankQuestions / Answer Key 兩個區塊來自題庫

八個終點全部需要 Project，其中兩個再多要一個題庫。所以第二題永遠要問，而題庫要不要建完全是推導出來的。這也是漏斗只需要兩題的原因。
Handout 與 Slide 進入清單，等於 Planning 的定位擴大了 —— 它從「建立練習的新入口」變成所有教材產出的共同入口。第一版是否一次做完，見 §12。

5.4 第二題：素材從哪來

選項接下來
既有 Project選一個。課文與教學點都是讀出來的，跳過 §5.8 的兩個必經步驟。
新建 · 上傳文章老師提供文章 → 萃取教學點 → 展開。
新建 · 我們幫你寫由主題生成課文 → 萃取教學點 → 展開。

5.5 已填的格子要一直看得見

漏斗的答案以可點掉的 chip 常駐在對話上方，不論是老師答的、系統從句子推的、還是從其他頁面帶進來的：

要產出 [ MULTIPLE CHOICE ✕ ] [ + ] 素材 [ 食物 — What we eat ✕ ] [ 開始 ]
為什麼說明
錯誤要能提早攔截老師一眼看得到系統理解成什麼。不然要走到最後一步才發現方向錯。
對話不能變成聊天紀錄chip 可以隨時點掉重答 —— 有 chip 才是結構化補完，沒有就是一段回不去的對話。
句子已經填滿時也要顯示老師打「食物那課出十題選擇題」時兩格都推得出來，此時不直接跳過，而是把填好的 chip 亮出來讓他確認或修改，再按開始。

5.6 對話規則

規則說明
先問終點，再問素材順序反過來會問到一半發現方向錯。終點決定了素材需不需要題庫。
只問推不出來的從句子推得到就不問。對話長度因此由老師那句話決定，而不是固定流程。
型別要釐清時多問一句「會不會念」在系統裡有兩個落點（VOCABULARY 念單字 / MIRRORING 念句子），這種要問。
名詞不同時先翻譯老師說的「造句」「聽寫」「默寫」「朗讀」沒有一個跟系統型別同名。問法是把他的詞映到我們的能力上：「你說的『造句』是要他們把打亂的詞排成句子（SENTENCE_SCRAMBLE），還是自己說一句（QA）？」
做不到的直說「我要他們寫作文」在終點清單裡沒有對應。不硬塞，直接說目前沒有寫作類練習並給最接近的替代。清單怎麼維護見 Q11。

對話長度的例子

老師說的句子已填還要問
幫我把食物這課從頭做完終點=多個練習、素材=新建0 題，確認 chip 後直接展開
食物那課出十題選擇題終點=MULTIPLE CHOICE、素材=食物0 題
我要考 A 班會不會念食物終點=練習（型別未定）、班級=4A2 題：念單字還是句子 → 食物從哪來
幫我弄一下明天的課幾乎沒有卡在第一格，直接問終點

5.7 預設組合（原本的三條路徑）

多選之後，「完整功課」不再是特殊路徑 —— 它就是一次勾好幾個終點。原先的三個起點降級為預設勾選組合，讓已經知道自己要什麼的老師跳過對話：

捷徑等同於
完整功課終點 = VOCABULARY + SENTENCE_SCRAMBLE + MULTIPLE CHOICE，素材 = 新建
建立考題終點 = MULTIPLE CHOICE
建立 Project終點 = 只要 Project，素材 = 新建

按鈕與打字是同一個模型的兩個入口，不是兩套流程。

5.8 建立 Project 的兩個必經步驟

凡是包含「Project」這一段的路徑，都必須走完這兩步。（完整功課、建立 Project、建立考題 · 沒有 Project）Project 已存在的兩條路徑兩步都跳過 —— 課文與教學點都是讀出來的。
起點 ──▶ ① 課文 ──▶ ② 教學點 ──▶ 會建立什麼 ──▶ 建立 讀 / 改 從課文萃取 必填，只出現一次

① 課文是第一步，不是最後一步

課文是整條鏈的根 —— 生詞卡、跟讀句、題目全都從它長出來。它必須先於自己的衍生物被看到與確認，不能跟它們並排在「會建立什麼」清單裡當五列之一；老師改一句課文，下面三列的內容就得跟著變。

這一步要有內容
整篇看得到逐詞拼音 + 翻譯，一句都不省。
可改逐句刪除；Edit 切換成一行一句的純文字編輯。改過的句子標示「拼音會在存檔時重新產生」。
可重寫Write another 重新生成整篇。
與真實產品同序。New Project 的第三步就是 Review & Edit（讀課文），第四步才是 Teaching Points。

② 教學點必填，且只出現一次

真實 New Project 裡教學點出現兩次：Generate Content 當種子輸入、Teaching Points 確認萃取結果。Planning 只保留後者 —— 兩次對老師是重複勞動，而壓縮流程本來就是這個功能存在的理由。

規則說明
必填一個都不留時繼續鍵停用，並明說沒有教學點就什麼都建不出來 —— Vocabulary / Sentence Scramble / QA 三種練習的素材全部來自這裡（§3）。
與課文對照不在課文裡的教學點要標出來（老師刪了句子，或手動加了一個課文沒提到的詞）。這個檢查只有在課文先於教學點時才做得到。
可編輯逐個刪、打字新增並選型別、整組重新萃取。

少了這兩步，老師等於沒看過就接受一整個單元的內容。這也是 Q1（能不能直接建立）在完整功課上最尖銳的地方：單一練習做錯了重做就好，完整功課做錯是整課重來。

6.1 流程

6.2 提案要交代的事

整份提案的最上方：這堂課教到什麼

一條 Teaching points covered 的橫列，每個教學點一個 chip，並帶出它的型別 —— 語法與量詞要看得出來不是生詞（見 §3.1）：

米饭 词 面条 词 好吃 形 了 语法 碗 量词

沒被任何一項練習蓋到的教學點要標出來。老師才看得見「這課要教『了』，但這份提案沒有任何一項練到它」。

覆蓋率怎麼算 —— 兩條規則

規則理由
只算「練習」，不算教材Project 與題庫是素材，不是練習。把它們算進覆蓋，會讓「純建教材」的提案看起來每個點都教到了，那是假的。
Multiple Choice 依分類計算同樣是 MC，Comprehension 考的是整篇讀懂沒，不會特別練到任何單一教學點，覆蓋算 0；Fill in blank 練的是句型（GRAMMAR / PHRASE / MEASURE_WORD）；Meaning / Pinyin 練的是詞。QA 同理 —— Content Base 是就課文回答、Extension 是延伸發揮，兩者都不針對單一教學點，覆蓋同樣算 0。用型別一概算成「全覆蓋」等於誇大。
這條規則是做原型時發現的。把 MC 當成全覆蓋時，關掉句子重組仍顯示「全部教到」—— 但語法點其實沒人練。改成依分類計算後，關掉句子重組會立刻標出「了、碗 沒有任何一項練到」，這才是這個指標存在的意義。

每一列都要能展開看到真正的內容

光描述不算「先看見再建立」。「12 個教學點 · 約 6 句」只是規格，老師沒看到那 6 句；「MC × Comprehension × 10」也一題都沒露。Project 尤其不能省 —— 它是整條鏈的根，練習與題目都從它長出來。

7.1 One practice —— 六個，一個目的對一個型別

樣本的軸線是「你想讓學生做到什麼」，不是「產出哪一種物件」。五種練習型別加上 Vocabulary 的考單字模式，剛好各出現一次、不重不漏：

唸出來MIRRORINGProject 的課文句子
記住新詞VOCABULARY（Mirroring / Mixed 模式）teaching points 的詞類

用它問答QAQuestion Bank（Content Base / Extension）
考單字VOCABULARY × MC 模式teaching points
考課文MULTIPLE_CHOICEQuestion Bank（題型 × 分類為樣本內參數）

這份清單解掉的三個問題

先前的毛病怎麼解掉的
命名軸線混亂先前混用動作（Read a passage aloud）與目的（Check they understood）兩種命名混用。現在一律採系統的型別名稱。
選擇題佔掉三格先前把題庫的 Comprehension / Fill in blank / Meaning 拆成三個樣本，長得一模一樣。真正該分的是考單字 vs 考課文 —— 而系統本來就用兩種 MC 分開了，這也正是老師腦中的分法。四個分類降級為「考課文」裡的參數。
語法點沒有入口GRAMMAR / PHRASE / MEASURE_WORD 型別的教學點，Vocabulary 蓋不到。Sentence Scramble 就是為這件事存在的（素材直接來自 teaching points）。

Sentence Scramble 的細節尚未確認：吃哪些型別的教學點（全部，或只有 GRAMMAR / PHRASE / MEASURE_WORD）、一次幾句、「Listen」是否每句都有 TTS。只影響描述文字，不影響清單結構。

10 待討論

Q1 AI 產出可以直接建立，還是一律要先進編輯器？

目前設計是可以直接建立（Create & assign），另外提供 Open in editor 當備選。反面意見是：AI 寫的題目沒人看過就發給學生，風險高。

  • A. 維持現狀：可直接建立，Open in editor 為選項。
  • B. 一律先進編輯器，Planning 只負責「填好參數」。
  • C. 折衷：有 AI 生成內容的（QA 題目、MC 題目）強制進編輯器；只是重組既有素材的（跟讀取課文句、生詞取課文詞）可直接建立。

Q2 解析失敗或信心不足時怎麼辦？

老師可能打「幫我弄一下明天的課」這種資訊不足的句子，或打完全無關的內容。

  • A. 照樣給一份最可能的提案，讓老師自己改。
  • B. 回一個追問（「要哪一課？哪一班？」），像對話一樣多問一輪。
  • C. 低信心時不出提案，改成「你是不是想要這幾個？」列出最接近的樣本。

牽涉 §8.2 的 confidence 欄位要不要做。

Q3 建立多個練習時中途失敗怎麼處理？

「整堂課」會連續建立 3–4 個。第 2 個失敗時：全部 rollback？保留成功的並標示哪個失敗？還是逐項顯示狀態讓老師重試單一項？

Q4 指派的範圍與截止日要不要放進 Planning？

目前 Planning 只能選一個班、不設截止日。但既有的 assignPractice 支援多班，Practice List 也大量以截止日組織資訊（無截止日／7 天內／逾期）。

  • A. 維持最簡：單班、無截止日，之後補。
  • B. 加上截止日一個欄位（多班仍不做）。
  • C. 班級改多選 + 截止日，Planning 直接把指派做完。

Q5 AI 生成的練習要不要留標記？

Question Bank 已經區分「AI generated / 手寫」。練習要不要也存一個來源標記（createdVia: PLANNING），供日後統計採用率與品質追蹤？

Q6 輸入語言支援到什麼程度？

老師可能用英文、繁中、簡中，或混用（「用食物課文做一個 mirroring」）。三種都要支援嗎？產出的練習名稱要跟隨輸入語言，還是固定格式（主題 + 動作）？

Q7 舊的型別選擇對話框留不留？

本案讓 New Practice 直接開 Planning。AddNewPracticeDialog 要：

  • A. 完全移除，只留 Planning。
  • B. 保留為 Planning 畫面上的一個次要入口（「我知道我要哪一種」）。
  • C. 兩者並存一段時間，用 feature flag 分流觀察採用率。

Q8 教學點沒被蓋到時，Planning 該做到什麼程度？

一份提案可能漏掉某些教學點 —— 尤其 GRAMMAR / MEASURE_WORD 這種現有練習型別不好處理的。

  • A. 只標示出來，讓老師自己決定要不要補。
  • B. 主動多提一項練習去蓋它（例如語法點 → MC × Fill in blank）。
  • C. 不處理 —— 教學點覆蓋率不是 Planning 的責任。

子問題已解：先前記為「語法點該用哪一種練習教？現有型別沒有一個是為句型設計的」—— Sentence Scramble 就是，素材直接取自 teaching points。本題只剩「漏掉時要不要主動補」這一層。

Q9 沒有合用的題庫時，Planning 可以現生嗎？

老師要「MC × Fill in blank × 10」但既有題庫只有 Comprehension 的題目。generateQuestions(projectConfigSk, questionsBankSk, questionOptions) 本來就能生，問題是 Planning 要不要自己觸發。

  • A. 可以：Planning 直接生進既有題庫，提案上標明「will generate 10 new questions」。
  • B. 不行：只能從既有題目挑，湊不出來就據實說明並少給一項。
  • C. 可以，但一律要老師先看過題目（接 Q1 的 C 案）。

若選 A 或 C，還要決定生進哪個題庫：既有的、還是新開一個。

Q10 1 題庫 ↔ 1 Project 的限制，Planning 要怎麼配合？

既然題庫綁死一個 Project（§3.2），一堂課要出測驗，就必須存在那個 Project 自己的題庫。這讓 Q9（沒有合用題庫時能不能現生）從選配變成必要 —— 老師新建一個 Project 後，若沒人替它建題庫，Planning 就永遠出不了測驗。

  • A. Planning 在需要時自動替該 Project 建題庫並生題（等於把 Q9 選 A）。
  • B. Planning 只提示「這個 Project 還沒有題庫」，附一個一鍵前往建立的連結。
  • C. 改成允許一庫多 Project —— 但那要先解掉 hasMultipleProjects 的停用邏輯，屬於題庫模組的變更，不在本案範圍。

另外：若題庫因遺留資料連到多個 project，Planning 應比照 App 一律不碰（不生成、不宣稱可用）。

Q11 「做不到」的清單誰維護？

漏斗第一題只認終點清單上的 8+1 個。老師打「我要他們寫作文」「聽寫」時，系統必須直說做不到並給最近的替代，不能硬塞一個相近的型別出來 —— 那正是一次性產出最糟的失敗方式。

  • A. 寫死在前端，跟終點清單一起維護。
  • B. 後台可編，方便隨功能上線調整。
  • C. 交給模型臨場判斷 —— 不建議，它會硬掰。

連帶要決定同義詞對照表（聽寫／默寫／造句／朗讀／背單字…）要做到多細，以及是不是同一份資料。

11 Out of scope / 假設

  • 不含對四種 practice type 本身的任何修改，也不含 stepper 的改版。
  • 不含新的內容型別。Planning 的產出一律落在既有的 practice + project + question bank 上。
  • 不含學生端任何變動。
  • 不含 Word Game 的指派 —— 那條線走 Word Game spec。
  • 已不再假設 Project 與題庫存在 —— 「建立 Project」與「建立考題 · 沒有 Project」兩條路徑就是為此而設（§5.4）。但 Planning 不重做 New Project 的四步流程，只在前面包一層收集意圖。
  • 假設模型可在數秒內回應；超過 15 秒需要有取消與重試。
