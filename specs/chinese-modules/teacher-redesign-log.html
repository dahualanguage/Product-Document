Teacher Redesign — Log

Design decisions & change history for the Chinese-module teacher dashboard mockup.

Chinese Modules Role: CLASS_TEACHER Mockup: teacher-redesign.html Spec: teacher.html Updated: Jul 22, 2026
What this is. A high-fidelity, professional dashboard mockup for the Chinese-module teacher — the visual/interactive companion to the Teacher — Content Creation spec. This log records why it looks the way it does and what changed.

1 Overview

The teacher dashboard answers one question first: "what needs my attention now?" Teachers are tool users who open the console many times a day, so the design is task-first and deliberately professional — not the playful game aesthetic of the student side.

  • Scope of v1: the Dashboard (home) screen only.
  • Primary job: reviewing student submissions (the daily, high-volume work).
  • Style: emerald #059669 + slate neutrals, Plus Jakarta Sans; matches the existing spec docs.
  • Cross-product consistency: practice-type colours reuse the student redesign — Q&A Mirroring Vocabulary Multiple Choice.

2 Design principles

  • Task-first, not feature-first. The home surfaces pending work (review queue, active assignments), not a menu of tools.
  • Review is the centrepiece. Content creation / assigning happens occasionally; reviewing recorded answers is daily and repetitive, so it gets the most space.
  • System scores, teacher confirms. The system auto-grades; the teacher reviews, comments, and approves — they do not re-score.
  • Strip to essentials. No vanity metrics; removed anything the teacher doesn't act on.
  • Sidebar mirrors the real app. Nav items match the actual CLASS_TEACHER menu (Content / Practice / Overview), plus an added Dashboard entry.

3 Key decisions

DecisionRationale
Review queue = main panelHighest-frequency daily task; kept front and centre (moved to a right-column action panel).
AI pre-scores; no teacher sliderTeacher "只會照系統評分" — confirms the system grade rather than re-scoring. The editable score control was removed.
Per-question reviewA practice can have several questions; each is shown as a collapsible item so the teacher can inspect the actual answer.
1–5 per question (speaking)Each spoken answer carries its own 1–5 score badge; MC uses ✓/✗ (correct/incorrect) per question.
MC auto-graded, no recordingMC is click-based; the drawer shows options (chosen vs correct) instead of an audio player.
Quick review fills the notePreset comments drop into the note box (toggle) so the teacher can combine/edit; approval stays a deliberate action.
Approve & Next advancesBatch workflow — approving loads the next student without closing the drawer.
Removed stat cards & page headerReduced noise; the greeting and vanity counters didn't help the teacher decide the next action.

4 Locked features

Finalized Jul 21, 2026 — do not change without an explicit request.

Search Locked

Global keyword search in the top bar. A green Search button sits outside the input. Typing a keyword matches each item's name + keyword tags and surfaces related Project / Question Bank / Practice (plus Student / Class) in a grouped dropdown; Enter opens the first result. Works in English and Chinese (e.g. food / 食物, tones / 声调, harry / 哈利波特).

Quick Create Locked

Four icon buttons — Project · Question Bank · Practice · Assignment. No subtitles.

To Review Locked

Right-column action panel. Filter tabs All / Q&A / Mirroring / Vocabulary / Multiple Choice; active tab is green. Each row shows name + class + type + practice · date-time — no avatar, unread dot, attempt count, or AI score. The whole row is clickable (faint chevron, no per-row button).

Review drawer: per-question collapsible answers — speaking shows prompt (zh / pinyin / en) + recording with its own 1–5 score; MC shows options with chosen-vs-correct and ✓/✗. A read-only Score (no explanation). Quick-review chips fill the note box; Approve & Next approves and advances to the next student in the filtered list.

5 Change log

Sep 23, 2026 — Word Game v10: stage browser de-duplicated, demo scope made explicit
  • Stage header no longer repeats itself. HSK 1–6 stage titles in the curriculum are just 詞彙 · 第N關 / 測驗 · 第N關 / 大魔王 · 第N關, which restated the stage number and the type pill. Those are dropped; the header reads Stage 5 · Quiz · 基礎零件·量詞·先修詞. Level 0 titles (a, a / i, 1+1) carry real information and stay. The Assign dialog's stage picker follows the same rule.
  • Level 0 stage rows show their title in the unit sidebar (finals and tone combos), so a quiz like ai / ao can be found without opening it.
  • Search says what it covers. Only the embedded demo units are searchable; the empty state now reads “Search covers the stages embedded in this demo — Unit 1 and Unit 22 of this level” instead of a bare “No matching stages”.
  • Unit names in the “not embedded” note are links that jump to the first embedded stage of that unit (also clears an active search or filter). Same links in the search empty state.

The seven level rows are all open (Level 0 Pinyin & Tones, Levels 1–6 HSK vocabulary) with the real stage and unit counts (60 / 155 / 395 / 509 / 536 / 496 / 514 stages) and the unit themes from dahualanguage/HSK-vocab-game-assets. The Vocabulary / Sentence Building / … placeholder labels and the “Coming soon” locks are gone.

Aug 12, 2026 — Redesign v9 frozen · Planning becomes a funnel
  • Planning rebuilt as a funnel. Converge on two mandatory answers — what do you want to make (multi-select across all 8+1 outputs, including Handout and Slides) and where does the material come from — then expand into passage → teaching points → what will be created. The old three routes became preset combinations; a preset just fills the funnel in one click.
  • The conversation only asks what it cannot infer. A complete sentence fills both slots and asks nothing; an ambiguous verb gets one question (“念” → words or sentences); a teacher’s own wording gets translated onto system types (“造句” → Sentence Scramble or QA); something unsupported is said plainly with the nearest alternative offered, and no endpoint is silently invented.
  • Filled answers stay visible as removable chips, and the funnel never skips its own confirmation — even when the sentence answered everything. Once complete the heading flips to Ready to go, the stage strip appears (the moment the run’s shape is actually known), and a one-line summary states the Project, the outputs, whether a question bank gets written, and which screen comes next.
  • Passage first, teaching points once. Any run that creates a Project reads the passage first — editable, deletable, rewritable — then confirms the teaching points pulled out of it. Mandatory, and a point that no longer appears in the passage is flagged.
  • Terminology corrected twice. Samples now carry the system’s own names (MIRRORING / VOCABULARY / VOCABULARY × MC / SENTENCE_SCRAMBLE / QA / MULTIPLE CHOICE) rather than invented ones, and the object is called Project everywhere — “課文” now only means the passage inside it. QA’s material is the question bank, not the teaching points.
  • v9 frozen as 13 self-contained snapshots. Because this version introduced shared assets/teacher-nav.js and assets/teacher-shell.css, the freeze also copies those into versions/assets-v9/ and rewrites every link inside the snapshots — so a frozen page navigates to its frozen siblings and cannot be changed by later edits. Earlier snapshots had no such protection. The version viewer now renders a pages[] list instead of the three fixed fields.
Aug 10, 2026 — Redesign v9: Planning mode & the rest of the sidebar
  • Every sidebar entry now has a page. Six items were dead links (data-nav with no href): Projects, Question Banks, Practice List, Program, Classes, Leaderboard. All six exist now, in the same design system as the v8 dashboard, and built from what the dahua-dash code actually does — card/table toggle and standard + level filters on Projects; level and AI-vs-handwritten filters plus the generate dialog on Question Banks; the four practice types, the assignment-status strip (no due date / due within 7 days / overdue) and the Test + Result buttons on Practice List; create, edit, delete, manage students and invite codes on Classes; members, roles, invitations and removal on Program; class switcher, podium, ranked list, manual point adjustment and CSV download on Leaderboard.
  • Planning mode (new). A start screen under Practice, in the spirit of a Figma / Miro opening canvas. The teacher either types what they want in plain language, or clicks a sample. Samples come at two grains and the teacher chooses between them with a segmented control: One practice (mirroring, vocabulary, Q&A, quiz, tone drill, revise-last-week) or A whole lesson (new topic pack, review pack, end-of-unit check, speaking-only).
  • Planning shows its work before it commits. Whatever the teacher typed or clicked resolves to a list of exactly what will be created — each row naming the practice, its size, the text or question bank it draws from, and the class it goes to. Every row has a switch, so anything unwanted is turned off before “Create & assign”. A whole-lesson sample produces three or four rows; a single-practice sample produces one.
  • New Practice now leads to Planning. The Practice List button and the “Make a practice” action on a project both open the planning canvas instead of a type-picker dialog.
  • One sidebar, one definition. The nav was duplicated in every page; it now comes from assets/teacher-nav.js, and the shared chrome from assets/teacher-shell.css. Adding a destination is a one-line change. Dashboard, Students and Word Game keep their own drawer scripts via data-drawer="self".
  • Slides and Handout now exist as pages. Both were live routes in the app (/dashboard/projects/slide, /dashboard/projects/handout) that the mockups had never covered. Slides builds the same five-type deck the app builds — cover / content / full text / translation / vocabulary — with per-word pinyin above the characters, a thumbnail rail, arrow-key navigation, fullscreen (F), the Pinyin / Vocab Pinyin / Translation settings, and a working segment editor that splits and merges content slides. Handout is an A4 sheet with the app's six toggleable sections (Reading with Pinyin / Full Reading / Translation / Teaching Points / Questions / Answer Key), the Pinyin / Translation / School Logo switches, ruled lines for open questions, and real print styles. Reachable from the Projects card buttons and its row menu, and cross-linked to each other.
  • Word Game draft renamed to teacher-wordgame-v9.html; v8 is frozen at versions/redesign-v8-{dashboard,students,wordgame}.html.

Assignment rules (reference)

From the Teacher spec §4, and decided here:

  • Created inline as the final step (Step 3) of practice authoring — no standalone Assignments page.
  • Assign to individual classes or all classes.
  • Type: Mandatory (hard due date) or Optional (expiry date, bonus).
  • Dates: due/expiry per class or global; optional start date controls availability.
  • Decided: the dashboard\'s Active Assignments tracks Mandatory only — Optional is not tracked.

Areas still open for iteration: Active Assignments (sort / per-class dates), Classes, and the sidebar.
