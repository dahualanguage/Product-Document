ESL Teacher

Student profile management, AI-powered learning insights, and targeted assignment creation for ESL program teachers.

ESL Module 3.3 Status: Planning Target: TBD Last updated: February 2026

1 Feature Goal

How does an ESL teacher know which students need help, with what vocabulary, and in which subject area — across multiple content classes?
ESL teachers support students across several content-area classes (science, math, social studies). Without a unified view of each student's language profile and real-time class behavior, identifying gaps and creating targeted support is time-consuming and reactive.
Goal: Give ESL teachers a unified workspace to view each student's language profile, review AI-analyzed class content and student behavior data, and create targeted vocabulary and comprehension assignments — all driven by what students actually struggled with.

The ESL Teacher interface combines three capabilities:

  1. Student Info — Per-student language profile including grade, native language, English level, ESL group, and practice progress
  2. Student Learning Insights — AI-organized content from live sessions cross-referenced with each student's word-tap behavior and word bank
  3. Assignments — Targeted exercises created from insight data: vocabulary mirroring, multiple choice, and subject-content QA

3.2 ESL Group

ESL Group is the ESL teacher's primary organizational tool. Each student is assigned to one ESL group, which determines which teacher monitors them and which assignments they receive.

Group Assignment

  • ESL teacher manually assigns students to groups (e.g. Group A, Group B, or by proficiency tier)
  • A student belongs to exactly one ESL group at a time
  • Groups can be renamed and restructured by the ESL teacher

Group Use Cases

  • Assign the same vocabulary exercise to all students in a group
  • Filter Learning Insights by group
  • Compare progress across groups in the teacher dashboard
Open question: Is ESL Group assigned by the ESL teacher or auto-suggested by the system based on English Level? See Section 7.

3.3 Grade Book & Progress

4 Student Learning Insights

Data source: All insights are derived from Live Classroom sessions (Flow 6). Data is produced after each session ends or after students confirm saves in the Class End Summary.

4.2 Category B — Student Behavior

Generated from active student interaction during class
Save mechanism: When a student taps a word during class, it is immediately auto-saved to a temporary session list visible in the sidebar. At class end, a Class Complete modal displays all tapped words — students can uncheck words they don't want to keep. If the student closes the browser without reviewing the modal, all tapped words are saved automatically. The final Word Bank entry = tapped words minus any manually unchecked.

5 Assignments

The ESL teacher creates assignments directly from the insights data. The flow is: select material (high-priority words or content topics from Section 4) → choose assignment type → assign to a student or ESL group.

Design principle: Assignments should require minimal manual input from the teacher. The system pre-populates word lists and content from insights; the teacher's job is to review, adjust, and publish.
100%

  


  
  
5.1 Vocabs / Phrase


  
Vocabulary assignments are built from words in the student's word bank or from the session's high-save-rate keyword list.


  

    

      
Vocabs Mirroring MVP

      
Students see a word and must reproduce it — either by typing, selecting the correct spelling, or matching it to its translation.

      
    
        
  • Targets word recognition and recall
    • 
        
  • Works well for early-stage vocabulary acquisition
    • 
        
  • Teacher selects the word list from insight data
    • 
      

    

    

      
Vocabs Multiple Choice MVP

      
Students choose the correct definition, translation, or usage of a word from multiple options.

      
    
        
  • Targets vocabulary comprehension and meaning discrimination
    • 
        
  • Distractors can be auto-generated from similar words in the student's word bank
    • 
        
  • Supports both word-level and phrase-level questions
    • 
      

    

  


  
  
5.2 Subject Content


  
Subject Content assignments are built from the AI-organized class content summary. They test whether students understood the concepts taught in the content class — not just the vocabulary in isolation.


  

    
QA (Question & Answer) MVP

    
The teacher (or AI) generates comprehension questions based on the class content summary. Students answer in short form.

    
    
      
  • AI can draft questions from the session transcript; teacher reviews and edits before publishing
    • 
      
  • Questions are tied to specific content areas (e.g. “Science — Cell Structure”)
    • 
      
  • Helps the ESL teacher assess whether the student grasped subject concepts, not just vocabulary
    • 
      
  • Teacher can review student responses and add feedback
    •

6 Data & Schema


  
6.1 Student Profile


  
ESLStudentProfile {
  studentId: String
  name: String
  nativeLanguage: String          // e.g. "Mandarin", "Spanish"
  gradeLevel: String              // e.g. "Grade 5"
  englishLevel: Enum              // BEGINNER | INTERMEDIATE | ADVANCED
  studySubjects: [String]         // e.g. ["Science", "Math"]
  eslGroupId: String              // FK → ESLGroup
}


  
6.2 ESL Group


  
ESLGroup {
  groupId: String
  name: String                    // Teacher-defined label (e.g. "Group A")
  teacherId: String               // ESL Teacher who owns this group
  studentIds: [String]            // Members
}


  
6.3 Word Bank Entry


  
WordBankEntry {
  entryId: String
  studentId: String
  word: String
  savedAt: ISO8601
  sourceSessionId: String         // Which live session the word came from
  contentArea: String             // Subject context (e.g. "Science")
  tapCount: Number                // How many times student tapped this word across sessions
}


  
6.4 Assignment


  
Assignment {
  assignmentId: String
  teacherId: String               // ESL Teacher who created it
  assignedTo: { type: "STUDENT" | "GROUP", id: String }
  type: Enum                      // VOCAB_MIRRORING | VOCAB_MCQ | SUBJECT_QA
  contentArea: String
  sourceSessionId: String         // Session insights this was derived from
  wordList: [String]              // For vocab assignments
  questions: [{ q: String, answer: String }]  // For QA assignments
  createdAt: ISO8601
  dueAt: ISO8601
  status: Enum                    // DRAFT | PUBLISHED | CLOSED
}


  
  
7 Open Questions


  

    
Is ESL Group assigned manually by the teacher, or does the system auto-suggest groupings based on English Level and behavior data?

    
Auto-grouping could save setup time, but teachers may want full control over group composition. A hybrid approach (AI suggests, teacher confirms) may be best.

  


  

    
How does the teacher know which students attended a specific live session?

    
The Learning Insights view needs to filter by session attendance. If a student wasn't in a session, their insights for that session should be clearly marked as absent/no data rather than empty.

  


  

    
Can the ESL teacher join a live session to observe — and should they see a different view than students?

    
The current Live Classroom spec gives ESL Teachers "view only" transcript access. But should they also see real-time student difficulty events during the class (not just after)? This would require a real-time monitoring panel.

  


  

    
What is the assignment review flow — does the teacher see student responses inline, or in a separate grading view?

    
For QA assignments especially, the teacher needs a way to review and comment on student responses. This could be a simple list view or a more complex grading tool.

  


  
  
8 Implementation Notes


  

    
A. AI Content Analysis Pipeline

    
After a live session ends, the system triggers an async AI job:

    
    
      
  1. Pull session transcript from LiveSession.transcript
    2. 
      
  2. Send to AI (OpenAI / similar) with subject context for structured summarization
    3. 
      
  3. Extract keyword list with frequency counts and sentence context
    4. 
      
  4. Cross-reference keywords with student DifficultyEvent records from the same session
    5. 
      
  5. Store output as SessionInsight record, linked to sessionId
    6. 
    

  


  

    
B. Save Rate Calculation

    
Save Rate (word, session) =
  (students who saved word) / (students who tapped word) × 100%

    
Computed per session at session-end. Recomputed when late saves arrive (up to 24h post-session).

  


  

    
C. Assignment Generation

    
    
      
  • Vocab assignments: Teacher selects words from insight panel → system generates exercise scaffold → teacher previews and publishes
    • 
      
  • QA assignments: AI drafts 3–5 questions from session content summary → teacher edits and publishes
    • 
      
  • All assignments are linked to the source session for traceability
    •

Closed assignments Dimmed to 60% opacity. Closed = past due date or manually closed by teacher. Students can no longer submit. Scores are final.
