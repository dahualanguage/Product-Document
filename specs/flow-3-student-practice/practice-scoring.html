1 計分架構(後端 vs 前端)

分數本體由後端(Azure 發音 AI)算好回傳,前端只負責四捨五入、平均,以及把分數換算成星等顯示。

學生完成練習後,答案(錄音 / 對話)送到後端,由發音評分服務算出分數並存進 assignment history。前端拿到時分數已經算好,前端做的事比較像「把成績單翻譯成星星與百分比」,不會重新評分。

◆ 後端 — 改考卷的老師

算出原始分數

Azure 發音評分回傳 percentageScore、averageScore、completenessScore、每句 overall / fluency / accuracy(0–5 分)。

◆ 前端 — 謄成績單

換算與顯示

四捨五入、取平均、把分數換成 0–5 星等。所有計算數學集中在 src/utils/assignment.js。

2 各練習類型的計分規則

整份作業的星等由哪個後端欄位決定,以及後端沒給分數時前端的後備算法:

練習類型 整份作業星等(主) 後備算法(後端無分數時) rubric 細項算法
QA對話問答 直接用後端 completenessScore(已是 0–5 星) 每句 practitioner 對話的 overall 取平均 fluency / pronunciation / tone / overall 各自平均;accuracy =(pronunciation + tone)/ 2,再 /5×100
MIRRORING跟讀 completed 且 averageScore > 0 → 直接用 averageScore 每句 overall 取平均,四捨五入到小數 1 位 每句 fluency / accuracy / overall 平均後 /5×100;vocabulary 固定 0
VOCABULARY單字 同 MIRRORING 同 MIRRORING 同 MIRRORING(vocabulary 亦為 0)
關鍵:QA 用 completenessScore,Mirroring / Vocabulary 用 averageScore —— 兩者都是後端算好的 0–5 分。前端只在後端沒給時才自己平均每句 overall。

每次 attempt 顯示的分數,則是直接四捨五入後端的 percentageScore:

6 rubric 細項計算

rubric 面板顯示的 fluency / accuracy / pronunciation / vocabulary 四項百分比,由 calculateRubric() 從每句分數平均後 /5×100 得出。

MIRRORING / VOCABULARY

fluency = round( 平均(每句 fluency) / 5 × 100 ) accuracy = round( 平均(每句 accuracy) / 5 × 100 ) pronunciation= round( 平均(每句 overall) / 5 × 100 ) vocabulary = 0 // 固定

QA

// 先平均每段對話的 pronunciationScores accuracy =(平均 pronunciation + 平均 tone)/ 2 fluency = round( 平均 fluency / 5 × 100 ) accuracy = round( accuracy / 5 × 100 ) vocabulary = round( 平均 overall / 5 × 100 ) pronunciation= round( 平均 pronunciation/ 5 × 100 )
QA 的 vocabulary 取自對話的 overall,而 Mirroring / Vocabulary 的 vocabulary 固定為 0 —— 這是兩者 rubric 的主要差異。
